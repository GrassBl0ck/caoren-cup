# 多地图方案：一张地图 = 一个世界容器

> 2026-10-27 00:00—00:20 实施并实测通过。
> 目的：坐垫战争从小游戏合集里搬出来，成为独立地图；以后新增"以地图为基础"的小游戏，只要新建一个世界容器，切换即用。

## 1. 为什么这么做

原来的做法是**同一个世界内按坐标/维度分区**：坐垫战争挤在主世界 `x=20000 z=20000` 的高空，和小游戏的 lobby、battle box、woolwars 共用一个存档、一套 20 个数据包。

这有三个问题：

| 问题 | 后果 |
|---|---|
| 数据包全局加载 | 坐垫战争的 260 个函数和 20 个别的包挤在一起，任何一边改动都可能互相干扰 |
| 方块与实体共用存档 | 棋盘残留、坐垫实体、掉落物混在别人的世界里，出问题难定位 |
| 没有"地图"这个概念 | 换玩法只能靠 `/function` 切维度，玩家入口混乱 |

改成**一个地图 = 一个独立的 Minecraft 世界容器**后，每张地图有自己的存档和自己的数据包，物理隔离。

## 2. 关键机制（已实测）

原版/Paper 支持两组启动参数：

```
--universe <目录>   世界容器目录（默认 "."）
--world <名字>      加载哪个世界（默认取 server.properties 的 level-name）
```

数据包的加载路径是 `<universe>/<world>/datapacks`。也就是说：**换一个 world，就换了一套数据包，天然的按地图隔离**，不需要任何插件去 enable/disable。

所以启动命令变成：

```
mapctl start
  → java -jar purpur.jar --nogui --universe maps/cushion-wars --world world
```

## 3. 现在的目录结构

```
/opt/caoren-mc-26.3/
├── mapctl                      地图切换工具（同时是 systemd 的 ExecStart）
├── mcctl                       RCON 客户端（本机调试用）
├── purpur-26.3-2651.jar        共享服务端
├── plugins/                    共享插件（CushionWarsProbe 等）
├── server.properties           共享配置（端口、白名单、max-players…）
├── whitelist.json / ops.json   共享玩家名单
├── logs/                       共享日志（切图时自动归档历史日志）
├── .rcon-password              本次新开，权限 600
└── maps/
    ├── active                  当前启用的地图 id（纯文本）
    ├── minigames/
    │   ├── map.conf
    │   └── world/              ← 原来的 world 整目录迁移而来，559 MB，20 个数据包
    └── cushion-wars/
        ├── map.conf
        └── world/              ← 新建，11 MB
            └── datapacks/
                ├── cushionwars-a-datapack-0.1.0-static.zip
                └── cw-entry/   ← 地图自举包（见 §6）
```

**世界目录名统一叫 `world`**，这样插件、配置里写的 `world` 不用改，也不会有"世界名随地图变"的麻烦。

## 4. 日常用法

```bash
cd /opt/caoren-mc-26.3

./mapctl list                 # 列出所有地图，* 为当前启用
./mapctl status               # 当前地图、服务状态、世界大小、端口、内存
sudo ./mapctl use minigames   # 切到小游戏合集并重启（自动归档上一份日志）
sudo ./mapctl use cushion-wars
./mapctl log 80               # 看服务日志
```

切换过程约 **25—35 秒**（停服 + 启动 + 世界加载）。这期间玩家会断线，属于预期行为。

## 5. 新增一张地图（你后面那个新小游戏照这个做）

```bash
# 1. 建目录与元数据（不会立刻切换）
sudo /opt/caoren-mc-26.3/mapctl create my-game "我的新小游戏"

# 2. 把该地图专属的数据包放进去
cp my-datapack.zip /opt/caoren-mc-26.3/maps/my-game/world/datapacks/

# 3. 切换（首次启动时服务端会自动生成这个世界）
sudo /opt/caoren-mc-26.3/mapctl use my-game
```

三件事要注意：

1. **插件要用自己的地图判断**。`mapctl start` 会把 `-Dcw.map=<地图id>` 传给 JVM，插件用 `System.getProperty("cw.map")` 读。坐垫战争插件的写法可以照抄：
   ```java
   String activeMap = System.getProperty("cw.map", "cushion-wars");
   if (!"cushion-wars".equals(activeMap)) {
       // 不注册任何监听器，只在 /cw 上回一句"当前地图不是坐垫战争"
       return;
   }
   ```
   这样切到别的地图时，坐垫战争插件完全待命，不会碰其它小游戏的伤害/下座/放置规则。

2. **地形默认是普通世界**。`server.properties` 的 `level-type=minecraft:normal`（本次生成完坐垫战争世界后已恢复）。想要超平坦就临时改成 `minecraft:flat`，生成一次后改回来——`level-type` 只在**新世界第一次生成**时生效。

3. **世界级设置写在数据包里**，别写进 server.properties。参考 `cw-entry`：出生点、gamerule 都在该地图自己的 `datapacks/*/function` 里，跟着地图走。

## 6. 坐垫战争的地图自举包（cw-entry）

`maps/cushion-wars/world/datapacks/cw-entry/`，只有 3 个文件，做四件事，全部幂等：

| 做的事 | 说明 |
|---|---|
| 建图 | 中心格不是地面方块时才调 `cushionwars_a:arena/init`（4v4）。**已建好就绝不动**，避免毁掉进行中的比赛 |
| 出生点 | `setworldspawn 20000 200 19986`，玩家进服直接落在棋盘旁，不用 `/tp` |
| 世界规则 | 见 §7 的 gamerule 改名表 |
| 强制加载 | 先 `forceload` 施工区，否则远景未加载会让 `block` 判定误判成"非空气"（这个坑之前踩过） |

## 7. 26.3 的 gamerule 全部改名了（实测表）

**这是本次发现的第二个硬坑。** 旧的驼峰名（`doDaylightCycle`、`keepInventory`…）在 26.3 上**全部不再解析**，写进数据包会让整个函数加载失败。以下名字都在 `purpur-26.3-2651` 上用 `/gamerule` 逐条实测通过：

| 旧名 | 26.3 实际名 |
|---|---|
| `doDaylightCycle` | `advance_time` |
| `doWeatherCycle` | `advance_weather` |
| `doMobSpawning` | `spawn_monsters` + `spawn_mobs`（拆成两条） |
| `keepInventory` | `keep_inventory` |
| `naturalRegeneration` | `natural_health_regeneration`（不是 `natural_regeneration`） |
| `doImmediateRespawn` | `immediate_respawn` |
| `showDeathMessages` | `show_death_messages` |
| `fallDamage` | `fall_damage` |

坐垫战争地图当前生效的设置：固定白昼、固定晴天、不刷生物、死亡不掉落、无自然回血、保留摔落伤害。

## 8. 这次改了服务器上的什么

| 位置 | 改动 |
|---|---|
| `/etc/systemd/system/caoren-mc.service` | `ExecStart` 从直接 `java -jar` 改为 `/opt/caoren-mc-26.3/mapctl start`。备份在 `/var/backups/caoren-mc.service.bak-*` |
| `server.properties` | 新增 `enable-rcon=true`、`rcon.port=25575`、`rcon.password=<随机>`、`broadcast-rcon-to-ops=false`。备份在 `/var/backups/server.properties.bak-*` |
| `server.properties` | `level-type` 临时改 flat 生成新世界，**已改回 `minecraft:normal`** |
| `world` → `maps/minigames/world` | 整目录迁移，内容一字未改 |
| `world/datapacks/cushionwars-a-…zip` | 移到 `maps/cushion-wars/world/datapacks/` |
| 主世界 `x=20000` 的旧棋盘 | **已清理**：`fill` 清空 1065 个方块、杀死 8 个坐垫实体、取消 16 个区块的强制加载 |
| `/opt/caoren-mc-26.3/mapctl` | 新增（root 755） |
| `/opt/caoren-mc-26.3/mcctl` | 新增（root 755），RCON 调试客户端 |

RCON 只监听 `*:25575`，但因为云安全组未放行 25575，**外网连不上**，只有服务器本机（和通过 SSH 登录的人）能用。密码在 `/opt/caoren-mc-26.3/.rcon-password`（600，属主 caoren-mc）。

## 11. 回滚

```bash
# 回到旧的单世界模式（不推荐，但可逆）
sudo systemctl stop caoren-mc
cd /opt/caoren-mc-26.3
# 恢复 unit 与配置
sudo cp /var/backups/caoren-mc.service.bak-* /etc/systemd/system/caoren-mc.service
sudo cp /var/backups/server.properties.bak-* server.properties
# 世界搬回原处
mv maps/minigames/world ./world
mv maps/cushion-wars/world/datapacks/cushionwars-a-*.zip world/datapacks/
sudo systemctl daemon-reload
sudo systemctl start caoren-mc
```

完整备份（含配置、unit、20 个数据包）：`/var/backups/caoren-mc-premultimap-20261027-0003.tar.gz`。
迁移前的世界全量备份：`/var/backups/caoren-mc-cushionwars-20261026.tar.gz`。
