# [草人杯] 阶段04结果记录模板（空白）

这是模板，不是测试结果。复制到获准的私有 `runtime/cross-era-stage04/<runId>/` 后填写；真实UUID、玩家数据、视频、日志和生产配置不入Git。用例定义见[验收清单](ACCEPTANCE.md)。

机器核对入口现已提供：[离线工具说明](../../combat/tools/README.md)及[空白JSON清单](../../combat/tools/manifest.example.json)。人工表与JSON清单使用同一runId/caseId和原始证据引用；工具不解析此Markdown、不自动修改本表状态，也不能替代人工核对输入真实性或用户验收。

## 日志完整性与归因

| 检查 | 结果与证据 |
|---|---|
| startup、shutdown、进程正常停止及最终收尾记录 | NOT_RUN |
| 开始/结束accepted、rejected、errors、queued、writtenToBuffer、workerAlive | NOT_RUN；区分关闭前快照与最终排空 |
| 输入次数、实际事件次数、health_followup与会话关联 | NOT_RUN；无事件不自动表示无输入 |
| JSONL是否完整可解析、是否截断/丢记录/错误/超时 | NOT_RUN |
| velocity_event是否能可靠解释来源 | NOT_RUN；其本身没有单击因果ID，不强行绑定 |
| 攻击冷却/暴击是条件观察还是原生判定证据 | NOT_RUN；当前日志只有观察条件 |
| 生命净变化是否混入连续攻击、回血、死亡复活 | NOT_RUN；不能把净值强行分摊成逐击伤害 |

有丢记录、错误、未知来源或观测污染时，判“证据不完整/INCONCLUSIVE”并保留原因；不能因此自动证明玩法PASS，也不能把测量失效冒作确定的战斗FAIL。
