# [草人杯] 灵空战锋首版运行与统一试玩

本说明提供安装、玩家操作和验收步骤。实际部署状态、当前产物与服务器核验以最新部署报告为准。

## 使用哪个文件

- 普通构建生成 `plugin/build/<构建时间>/CaorenSpiritSky.jar`；最新构建目录写在 `plugin/build/latest.txt`。
- **不要把 `--runtime-probe` 生成的测试插件用于试玩或正式服务。** 它只用于无人值守临时副本，会自动创建模拟玩家与测试对局。普通构建不包含 `RuntimeBoot`。
- 从同一版本 Release 下载 `CaorenSpiritSky-MapTemplate-v0.1.zip`，核对随包地图清单中的 SHA-256，保留原 ZIP，仅在副本上游玩。
- Paper 26.3 build 223，Java 25；不依赖其他玩法插件或资源包。

## 安装与配置

1. 在独立测试服务端中解压地图副本，设置 `server.properties` 的 `level-name` 指向实际世界目录。不要覆盖既有玩家世界。
2. 放入普通 `CaorenSpiritSky.jar`，准备 `plugins/CaorenSpiritSky/config.yml`：

   ```yaml
   world: 实际已经载入的世界名
   map-points: map-points.json
   ```

   使用现有 `mapctl` 时，地图 ID 必须为 `spirit-sky`；插件检查启动参数 `cw.map`，切到其他地图时不接管世界或恢复本地图快照。独立服务端不传此参数时按显式世界配置运行。

   点位文件首次启用时从 JAR 内的已验证地图配置复制；不能把另一张世界仅改同名就认为兼容。默认世界留空，避免误接管已有世界。
3. `server.properties` 设置 `pause-when-empty-seconds=0`，保证全员离线后仍继续对局；保持正版验证 `online-mode=true`。这份说明不授权修改或启动生产服务。
4. 启动后检查日志出现“灵空战锋已就绪”，执行 `/sss admin validate`。若地图、点位或无玩家暂停设置有问题，插件保持未开放状态；不要忽略错误强行开局。

首版默认数值全部采用已确认规则。首次启动自动生成 `rules.yml`，支持主要生命、伤害、射程、资源上限/再生、部署/波次/阶段/复活计时和飞行倍率；时间键以 `-ticks` 结尾，20 tick = 1 游戏秒。未知键、非数字、越界或非整数计时会阻止启用。`config.yml` 的 `messages` 可调整开局、平局、胜利、取消和帮助文字（胜利消息的 `{team}` 会替换为队伍）。所有配置只在重启时读取，不能局中重载。

数值调整仍需按项目流程先确认；配置边界只是防止输错，不代表任意数值已验证平衡。箭衰减分段、成长曲线、原版武器/药水细节等结构规则在源码中。地图模式和全局难度由地图保留；插件自己的小兵与固定伤害已兼容当前和平难度粗模，不改其他世界难度。

## 玩家操作

| 操作 | 入口 |
|---|---|
| 加入、分队、选职业、准备 | `/sss` 菜单 |
| 自由观战 | `/sss spectate` |
| 离开并恢复加入前物品与位置 | `/sss leave`；局中参赛者仍按掉线规则记等待时间 |
| 驾驶恶魂 | 己方右键登乘，只有 Director 控制；WASD 与视角移动、空格上升、潜行下乘 |
| 召回、取消、载具重生点 | Director 的己方指南针或 `/sss`；死亡等待期间使用命令打开 |
| 自愿接任离线 Director | 局中 `/sss` 菜单；原 Director 回来后按落地脱战/恶魂死亡条件交回 |
| 部署哨站 | Defender 持部署道具，在槽位中心三维 6 格内使用 |
| 攻击建筑 | 对准原地图核心标记上方新增的红/蓝玻璃核心；多个核心共用一份建筑生命 |
| 管理状态、取消 | `/sss admin status`、`/sss admin cancel` |

每队 4 人、1 名 Director、最多 2 名 Defender，全员准备后倒计时 10 秒。其他职业可重复。结束后回准备区，手动准备下一局。

职业资源在固定背包槽位自动恢复，不可丢弃、移入容器或交换。基地补给在脱战 7 秒后停留 3 秒回满生命与消耗品。武器、护甲按原版使用方式操作。

## 单人和双人测试

先安装本轮更新后的普通试玩插件。管理员（OP 或持有 `caoren.spiritsky.admin`）在准备区执行：

```text
/sss admin test on
```

然后所有测试者使用 `/sss` 加入、选队、选职业并点击准备，照常倒计时开局：

- **1 人**：选任意一队和职业；另一队可为空，双方基地、兵线、恶魂仍生成。想驾驶就选 Director，测试其他职业时恶魂无人驾驶会悬停。
- **2 人对抗**：各选一队；不要求任何一队有 Director。
- **2 人合作**：选同一队；可以一人选 Director 驾驶，另一人当乘客测试配合。

少人数模式至少需要 1 名参赛者，所有已加入的参赛者都要选队、选职并准备；只有观察者不能开局。每队最多 4 人、最多 1 名 Director、最多 2 名 Defender 的上限仍保留。不会添加机器人补位，也不开放比赛中换职或新参赛者补入。

测试模式会在菜单和基地血条标记。结束后保留当前模式，重启默认恢复正式模式。准备区执行以下命令可手动恢复：

```text
/sss admin test off
```

模式切换会清除原准备状态，需要重新准备。倒计时期间先取消准备；比赛中先执行 `/sss admin cancel` 并等待回到准备区，再切模式。不能在比赛中途改变人数规则。`/sss admin status` 可查看当前模式。

少人数测试用于功能检查；完整职业平衡和比赛时长仍需八人试玩。

## 完整首版统一试玩清单

这一轮建议安排 8 名玩家，至少连续两局，轮换五个职业；无需先拆成单独的地图试玩。

1. 检查分队/职业限制、取消准备、正常 10 秒开局，首次兵线在 30 秒出现。
2. 双方恶魂四人搭乘、只有 Director 能驾驶；低/中/高空速度、受伤减速、治疗和速度药水、最高 30 格与边界阻挡。
3. 召回时 Director 边走边换位置；取消、登船结束、死亡或掉线取消；抵达后不反复绕路。观察转弯、掩体和乘客视角。
4. 近战、钻石矛、不同蓄力弓箭、飞行衰减；队友攻击不扣血或击退。Witch 药水也可能帮助敌人。
5. 无兵、有兵和最后一名支援小兵死亡时拆基地/哨站；每座建筑独立判断。核对反击优先级、掩体遮挡、基地龙息追踪和哨站火球躲避。
6. 两名 Defender 分别部署，尝试远处/高空/敌占槽位；第三座替换最早一座，死亡不刷新 20 秒个人部署冷却。
7. 小兵沿道路推进、索敌和回路；观察 3/6/9/12 分钟成长、近战清兵耗时和后期压力。
8. 玩家死亡自由观战、正常复活和保护提前结束；掉线重连、Director 自愿交接、库存恢复不额外补满。
9. 恶魂死亡后乘客自然坠落；选择基地/哨站复活，目标哨站被毁或进入战斗时回退基地；场地堵塞后重试。
10. 基地和哨站回血条件、基地档位停点、玩家每 8 秒缓慢回复与补给中断。
11. 正常胜负、管理员取消、连续下一局；最后逐人离开，确认物品、模式、位置和状态恢复。

重点记录：无法操作/卡住的位置、实际对局时长、职业使用率、基地/哨站火力是否过强、核心是否容易瞄准、UI 是否遮挡。客户端画面、真实网络延迟和 4v4 平衡仍需这轮试玩判断；模拟玩家验证不能替代这些体验结论。

## 停用与异常恢复

先取消对局，让玩家 `/sss leave`；正常停服时插件也会恢复在线玩家，离线玩家保留恢复记录到下次上线。

`plugins/CaorenSpiritSky/player-snapshots/` 中的 UUID 文件是未完成恢复记录；`restored/` 保存已成功恢复的归档。不要在有未恢复玩家时删除插件、原世界或快照目录。快照损坏或恢复失败会保留记录并拒绝玩家继续游戏，管理员核对日志和备份后处理，不能用删除记录绕过。

若崩溃，重启后取消旧对局，玩家上线恢复场外状态；不恢复半场战斗。不要将测试副本中的模拟玩家数据带到正式服务。
