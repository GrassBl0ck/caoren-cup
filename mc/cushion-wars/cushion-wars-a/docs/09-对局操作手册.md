# 坐垫战争 · 对局操作手册（1v1—8v8）

> 本文记录 2026-10-26 线上原型行为。2026-10-31 本地修复版的命令、规则和未验证项见 [试玩修复与本地验收](13-试玩修复与本地验收.md)，尚未部署。

状态：**最小可玩流程已实现并已部署，等真人试玩**。命令入口 `/cw`。
本文只描述当前代码真实具备的行为；未实现的部分在 §5 逐条列清，不当作已有功能。

---

## 1. 开一局的四步

以下命令中 `N` = 每队人数（1—8）。

```
1. 组织者设人数      /cw size N
2. 组织者建棋盘      /cw build N          （等价于数据包 /function cushionwars_a:arena/prepare {team:N}）
3. 玩家自己入队      /cw join red   /   /cw join blue
4. 组织者开局        /cw start
```

`/cw status` 随时查看阶段、回合、剩余秒数、双方存活数与名单。中止用 `/cw stop`。

第 2 步与第 3 步的顺序可以互换，但**建图会清空并重建 47×47 范围**，开赛前必须完成。
`/cw build` 是管理员命令（OP），`join` 不需要权限。

## 2. 一局的时间线

| 阶段 | 时长 | 玩家能做什么 |
|---|---|---|
| 准备 | 5 秒 | 被传送到出生坐垫并入座，能看到先手方；此时放置与射箭都被拦 |
| 行动（先手） | 最长 30 秒 | 只有先手方存活玩家能放置、射箭、换座 |
| 结算 | 最多 10 秒 | 不能做 AP 操作，已发出的箭继续结算 |
| 行动（后手） | 最长 30 秒 | 轮到后手方 |
| 结算 | 最多 10 秒 | 结算完进入下一回合 |
| …循环 | | 第 7 回合起每回合缩一圈；第 12 回合起每回合最大生命 −4、当前 −2 |

- 屏幕下方行动栏实时显示：回合、当前行动方、剩余秒数、`AP 个人+共享`、自己的血量。
- 手持**时钟**右键 = 结束行动；全队确认后本阶段立刻进入结算（再按一次取消确认）。
- 后手方每人多发 1 个坐垫（4 个，先手 3 个），这是确认稿里的补偿规则。

## 3. 资源与判定

| 项目 | 当前实现 |
|---|---|
| 个人 AP | 每阶段开始重置为 2 |
| 共享 AP | 每阶段开始重置为 N（4v4 是 4） |
| 放置坐垫 | 扣 1 AP，不足则不放置、不消耗物品 |
| 射箭 | 扣 1 AP，不足则本次射击无效、箭不消耗 |
| 换座 | 扣 1 AP（已在 SeatListener 里实现） |
| 药水 | 不扣 AP（原版机制） |
| 主动下座 | 被拦截，留在原坐垫 |
| 敌方 / 已占坐垫 | 拒绝乘坐 |
| 己方箭命中队友或自己 | 不造成伤害 |
| 死亡 / 断线 | 淘汰，转旁观，不能复活 |
| 胜利 | 一方全灭；或中央 3×3 被同一方坐垫占满 9 格并在该回合结束后仍保持 |

初始装备（按确认稿 §4.3 的快捷栏）：弓（无限、不损耗）、本队坐垫、治疗 I、喷溅治疗 II、伤害之箭 ×2、时钟、副手普通箭 ×1。最大生命 40。

## 4. 试玩前必须知道的四件事

1. **只对入队玩家生效**。没 `/cw join` 的玩家，插件完全不干预（这是为保护同服 battle box、woolwars 等小游戏）。
2. **棋盘在 y≈199 的高空**，掉下去会摔死并判定淘汰。这是当前设计代价，不是 bug。
3. **`max-players` 还是 10**，8v8 需要 16 人，需要先改这个键（未改，等你确认）。
4. **白名单只有 5 个号**，8v8 要 16 人先加白名单。

## 6. 已知缺陷（会在试玩中看到）

1. **中央胜利判定偏宽松**：只要回合结束那一刻是 9/9 就判胜，没有严格记录“开始时的 9/9 + 撑过整个敌方阶段”。
2. **淘汰玩家的物品**保留在身上（转为旁观），不会自动清理。
3. **阶段计时用服务器 tick**，服务器卡顿时现实时间会变长（与确认稿 §4.4 一致）。
4. **共享 AP 被一人吃干**是允许的（确认稿 §5.1.6），测试时容易被误认为 bug。
5. **缩圈靠控制台执行数据包函数**，若缩圈时正好有人站在被清除的格子上，只会掉下去摔死，而不是按“缩圈直接淘汰”判定。

## 7. 建议的试玩顺序

1. **1v1**（边长 19）：两个人最快的验证，先确认阶段切换、AP、上下座、射箭扣 AP 都正常。
2. **2v2**（23）：验证队友不受伤、共享 AP 被队友消耗、全队确认提前结算。
3. **4v4**（31）：确认稿的基准尺寸，128 格距离下的弓箭手感与缩圈节奏。
4. **8v8**（47）：确认 24 AP 是否让中央争夺过快、掩体是否过空。

每局结束后看 `plugins/CushionWarsProbe/probe-*.log`（JSONL），里面按事件记录了 `game-start`、`phase-action`、`gate-deny`、`shoot-deny`、`arrow-damage`、`eliminated`、`game-end`。
