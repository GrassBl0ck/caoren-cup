# 26.3 语法与标识待验证清单

本轮为纯静态交付，**没有** 26.3 客户端或服务端，因此下面每一条都只是“按现有证据推断的最可能写法”，不是已核实事实。核实方法统一为：用 26.3 官方 `server.jar` 加载本包，读取控制台报错；或用解包后的 `data/minecraft/` 原生数据包、`version.json`、注册表导出对照。

## 1. 数据包元信息

| 项 | 本包写法 | 依据 | 若不成立的影响 |
|---|---|---|---|
| `pack_format` | `121` | 版本元数据记录数据包版本 `121.0` | 整包无法加载 |
| `supported_formats` | `{"min_inclusive":121,"max_inclusive":121}` | 1.20.2 起支持的字段，26.x 是否仍接受未核实 | 报“未知字段”或拒绝加载 |
| 目录单复数 | `data/<ns>/function/`、`tags/function/` | 1.21 起目录单数化 | 所有函数找不到 |

## 2. 实体与标识

| 项 | 本包写法 | 风险 |
|---|---|---|
| 坐垫实体 ID | `minecraft:cushion` | 由 `net.minecraft.world.entity.decoration.Cushion` 类名推断，注册名可能不同（如 `minecraft:seat`）。仅影响 `place_spawn_cushions`、`selfcheck` 与缩圈清理 |
| 坐垫 NBT | `{TileX,TileY,TileZ,Tags}` | `BlockAttachedEntity` 的挂接坐标键名未核实；缺省会挂到最近的方块上 |
| 坐垫染色 | 未使用 `Color` | 队伍归属改用 `Tags` 标签而不是颜色，避免依赖未核实的字段 |
| 箭/掉落物/喷溅药水 ID | `minecraft:arrow` / `minecraft:item` / `minecraft:splash_potion` | 喷溅药水实体 ID 在部分版本为 `minecraft:potion`，需核实 |

## 3. 命令语法

| 命令 | 本包写法 | 备注 |
|---|---|---|
| `fill` | `fill <x1> <y1> <z1> <x2> <y2> <z2> <block>` | 无 `replace` 参数时默认覆盖；体积最大 32768，本包单条最大 961×3 |
| `setblock` | `setblock <x> <y> <z> <block> replace` | 稳定语法 |
| `execute` | `execute unless block <pos> air run ...`、`execute anchored eyes positioned ^ ^ ^3 if entity ...` | `anchored` 与相对坐标前进的组合需核实 |
| `scoreboard` | `operation`、`remove`、`matches ..0`、`matches 1..` | 稳定语法 |
| `data` | `data get entity @s Pos[0]`、`execute store result storage <target> <path> double 1 run ...` | 存储路径的类型必须与 `double/float/byte` 一致 |
| `data modify` | `data modify storage cw_p0:log snapshots append from storage cw_p0:new entry` | 列表追加语法稳定 |
| `particle` | `particle minecraft:flame <x> <y> <z> 0 0 0 0 1 normal` | 参数顺序为 `pos delta speed count mode`，需核实 |
| `schedule` | `schedule function cw_p0:g08/timer_tick 1t` | 重复调用会叠加多个计时器，测试前先 `schedule clear` |
| `summon` | `summon minecraft:cushion <x> <y> <z> {…}` | NBT 键大小写敏感 |
| `tellraw` | `{"score":{"name":"#round","objective":"cw_a_match"}}` | 分数组件结构需核实 |
| `title actionbar` | `title @a[tag=p0_subject] actionbar {…}` | 目标选择器带标签在 `title` 中是否可用，需核实 |
| 谓词 | `{"condition":"minecraft:entity_properties","entity":"this","predicate":{"vehicle":{}}}` | `vehicle` 字段在 26.x 谓词结构中的位置未核实 |

## 4. 选择器边界语义

`@e[...,x=..,y=..,z=..,dx=..,dy=..,dz=..]` 中 `dx/dy/dz` 是**体积范围**而不是终点坐标，边界是否含端点在版本间有过调整。本包缩圈清理使用 `dx=30`（覆盖 −15..15）、`dz=0`（单层），若端点语义改变，可能多清或少清一格。核实方法：在测试世界放 3 个标记盔甲架于 x=−15、15、16，执行一次清理，检查哪个被清除。

## 5. 世界与坐标

- 维度取 `minecraft:overworld`，施工框 Y 63..65。超平坦或空世界默认地形远低于此高度，一般无冲突；若专用世界地形出现在该高度，`arena/init` 会因预检失败而拒绝，属预期行为。
- 地图要求固定白昼、晴天、关闭自然生物生成。本包**没有**写入 `gamerule` / `time` / `weather`，因为这类改动会影响整个世界而不是专用区域，需要用户确认后再决定由数据包还是由开服参数负责。见 `docs/05-已知限制与阻塞.md` 第 3 条。

## 6. 核实顺序建议

1. 只放探针包（`cushionwars-a-p0-probes`）→ 看 `pack.mcmeta` 与 `probe/load` 是否报错。
2. 执行 `cw_p0:probe/help` → 验证 `tellraw` 中文与分数组件。
3. 执行 `cw_p0:g08/timer_start` → 验证 `schedule` 与 `title actionbar`。
4. 再放正式包，执行 `arena/init` → 验证 `fill`/`setblock`/`summon`。
5. 执行 `arena/selfcheck` → 这一步同时验证坐垫实体 ID 与 NBT 是否正确。
6. 全部报错清零后，才谈 P0 的行为验证。
