# 回合制 A：技术设计与实现约束

日期：2026-10-25。性质：依据已确认玩法编制的开发设计；内部方案待 P0 验证，不是运行通过的声明。与确认稿有冲突时停止，不能用本文件覆盖玩法。

## 1. 总体结构

只构建一个回合制包。建议命名空间为 cushionwars_a，内部目标、标签、实体和存储使用项目独有标识，避免全局名称冲突。不创建 CS2 插件，也不引入服务端插件或客户端模组。

| 模块 | 责任 | 不应承担 |
|---|---|---|
| bootstrap | 格式/版本检查、首次注册、重复加载兼容 | /reload 时无提示清场或重新开局 |
| arena | M1 源数据、明确包围盒、初始化、重置、预警、收缩 | 修改任意坐标内容或清理全世界实体 |
| lobby | 空背包、选队、选位、剩余点随机补齐 | 正式对局换队、补位 |
| lifecycle | 名单锁定、准备、阶段切换、中止、结果锁定 | 具体伤害和门坐垫规则 |
| actions | 真实输入路由、合法性验证、AP/库存事务 | 不经门禁直接操作地形或资源 |
| seats_doors | 坐垫/门的占格、归属、占用、放置/拆除/切换 | 用坐垫联网要求新增玩法限制 |
| combat | 蓄力、发射、弹药、投射物、敌箭伤害、治疗 | 全局改写无关玩家伤害 |
| elimination | 淘汰、断线、重连、比赛资源收尾、观战 | 销毁死者已部署门与坐垫 |
| round_rules | AP 重置、确认、中央资格、缩圈、衰减、补给 | 使用 B 的恢复时钟或 90 秒截止 |
| presentation | 公共战况、己方全部字段、准星敌人血量、选位按钮 | 向敌方泄露个人资源 |
| evidence_build | 可复现测试、产物清单、校验、打包 | 把测试后门带入正式包 |

目录结构可在任务范围内调整，但职责和入口应清晰；记录真实文件映射，避免把所有逻辑塞进一个 tick 函数。

## 2. 规则与事件的权威来源

1. 用户最新明确选择和回合制 A 确认稿决定玩法。
2. 服务器确认的真实输入和原版事件决定哪些操作实际发生。
3. 项目的比赛状态决定阶段、存活、AP、库存、格子归属和胜利。
4. 展示层只读取状态，不能成为另外一套比赛状态。

不能依赖客户端自报 AP、队伍、命中、格子或资源。聊天按钮、控制道具、管理入口和实际物件交互都必须经过同一套服务器校验。

原版已有交互可能先于数据包运行。P0 必须核实真正的触发时机、可阻止范围与可能副作用，不能把“下一 tick 检测到变化”当成“已经拦截”。

## 3. 生命周期与阶段

建议显式状态：

~~~text
WAITING
  -> PREPARING (100 tick)
  -> ACTION_FIRST (最多 600 tick)
  -> SETTLING_FIRST (最多 200 tick，可提前结束)
  -> ACTION_SECOND (最多 600 tick)
  -> SETTLING_SECOND (最多 200 tick，可提前结束)
  -> 无人获胜：完整回合结束、进入下一回合
  -> ACTION_FIRST ...

任意有效比赛阶段：
  -> 结果锁定 -> 停止比赛效果、清除剩余投射物 -> WAITING，保留结果显示
  -> 组织者中止 -> 停止效果、清除投射物 -> WAITING，无获胜方
PREPARING 人数不足：
  -> 取消准备 -> WAITING，保留仍在场者的选位
~~~

### 3.1 候场和准备

- 正式开始必须红蓝各 4 人；不能只检查总人数为 8。
- 入局前保护个人原有物品，空背包检查失败直接拒绝，不执行清空背包补救。
- 对本队固定 1—4 号点先合法成功先占位；每人最多一个，不能顶替。
- 开始准备前允许取消/改选空位，换队/离场释放原位。
- 组织者启动时保留手选点，为未选队员随机补齐本队剩余空位。
- 完成分配即锁名单、阵营和位置，准备 100 tick；随机确定整局先后手，后手背包多 1 垫。
- 初次入座面向中央，之后可转视角；正式开赛不再次重置朝向。
- 准备中不能用道具、蓄弓或执行 AP 行为；不发回合补给。
- 准备取消仅收回本局已发的比赛物资，不误清原有物品；保留仍在线者点位，离线者释放。

### 3.2 行动和结算

- 两队轮流；同队所有存活者同时行动。
- 每次己方阶段开始，存活者个人 AP 设为 2，该队共享 AP 设为 4，结束确认清空。
- 个人优先，共享补足；队友死亡不减少共享 AP。
- 30 秒到或全部存活者确认结束才结束阶段；AP 用完不自动结束。
- 确认者锁定本人 AP 行为，但仍可免费治疗；须主动取消确认才能再进行 AP 行为或新蓄弓。
- 阶段截止禁止新 AP 行为，取消未发出的蓄弓；已合法发出的投射物继续。
- 结算截止固定为该阶段结束后 200 tick，不能被新投药延后。
- 本阶段所有相关投射物处理完可提前切换；未完成饮用不算投射物，不因此延后阶段。
- 截止清除剩余比赛投射物，已合法消耗的 AP/物资不退。
- 饮用可跨行动、结算和完整回合，结果锁定后未完成饮用不再生效。

## 4. 最小数据模型

以下是需要表达的数据，不强制具体命令写法。实际实现须列出每个字段的存储位置、读写入口与清理时机。

| 层级 | 必须表达的字段 |
|---|---|
| 比赛 | 比赛 ID、有效状态、回合、固定先后手、当前行动队、统一 tick、阶段起止点、结算截止、结果及锁定标记 |
| 队伍 | 队伍 ID、成员、存活数、共享 AP、中央格数、中央胜利候选及对应反制阶段 |
| 玩家 | 稳定身份、本局成员/阵营、在线与存活、出生预约、当前坐垫、个人 AP、结束确认、当前/最大生命、比赛物资、蓄力/饮用状态、观战对象 |
| 格子 | 棋盘相对坐标、当前有效、固定掩体、坐垫或门占格、归属、乘坐者/对象 ID |
| 投射物 | 唯一身份、比赛 ID、发射者及阵营、箭种/药水种、蓄力 tick、出生 tick、最长存活、是否已结算 |
| 地图 | 维度、原点、地面 Y、施工包围盒、固定掩体、出生点、初始化标识和版本 |
| 测试 | 用例 ID、真实环境、输入证据、前后状态、结果、失败分类、日志路径 |

- 名称可变的玩家不能仅以显示名关联资源和观战状态。
- 掉线再上线仍是同一本局身份，不能因为实体重建恢复参赛资格。
- 每件比赛物品、实体和投射物须能与本项目/本局关联，方便精确清理。
- 唯一 ID 去重不能被误做成额外统一操作冷却；A 没有 B 的 1 秒切垫间隔。
- 至少支持 0.1 HP 精度，因为 3 tick 合法普通箭为 0.9 HP。
- 若采用整数十分之一 HP，必须同时验证原版生命、显示、治疗、死亡和上限的一致性。它是候选内部表示，不自动授权替换原版药水或改变玩家体验。

## 5. 一次操作的事务边界

每个入口按同一规则处理：

1. 确认事件属于本局真实、尚未处理的输入，保留服务器合法成功的先后顺序。
2. 校验本局资格、存活、阶段和本人确认状态。
3. 以真实坐姿视点、目标形状、手持物和原版交互条件校验距离与遮挡。
4. 校验棋盘有效范围、地面层、占格、对象归属、乘坐者和对象状态。
5. 校验库存与个人/共享 AP；免费治疗不走 AP 扣减，但仍校验数量和存活状态。
6. 合法操作的有效结果与 AP/物资扣减作为一次事务提交。
7. 更新占用和战况；失败保留原位置、对象、库存与 AP，返回合适提示。

共享最后 1 AP、同一空坐垫和同一出生点的竞争只允许一个成功。不能先让多个原版行为生效，再根据 tick 末的遍历顺序决定“谁算成功”；若这种做法已产生有效漏洞，P0 不通过。

界面隐藏、移走物品或冒险模式都不是完整门禁的证明。要检查主手、副手、切槽、交换副手、按住操作、重复输入和阶段边界的实际路径。

## 6. 输入路由

按确认稿保持主手用途优先：

| 主手 | 右键行为 |
|---|---|
| 弓 | 仅尝试蓄弓，不同时开门/换座 |
| 饮用或喷溅药水 | 仅尝试对应治疗使用 |
| 坐垫、门 | 仅尝试相应放置 |
| 本模式时钟控制物 | 仅结束行动/取消确认 |
| 空 | 合法己方空座换座，或门开关；副手仍可持箭 |

不合法目标不能转而触发另一种 AP 行为。不得因默认控制物难用而新增聊天命令、菜单或其他快捷道具替代已定操作。

确认稿未为每个拆除动作逐一写出手势和原版耗时。如果实施方案需要改变原版操作方式、变为专用拆除工具或瞬时拆门，应先指出实际差异并让用户决定，不能默认为已经批准。

弓仅在己方行动阶段、本人未确认结束时可新蓄力。允许当时无 AP 先蓄；释放才验证 AP 和弹药。蓄力不预占共享 AP。未成功发射，不扣射击 AP 或永久消耗箭。

## 7. 坐垫与门

- 地面格是唯一合法占格层；掩体顶、门上和悬空不合法。
- 坐垫与门一格互斥，开门也不释放格子；固定掩体占地不能放置。
- 原生坐垫须一人一座，存活者只能乘己方；不要求坐垫网络连接出生区。
- 主动下座无效，留原位，不扣 AP、不淘汰；要报告客户端与服务器是否存在可利用的瞬时状态。
- 占用座不能主动拆；无人己方/敌座均可拆，1 AP，无返还/掉落。
- 换座成功 1 AP；多人争同一空座仅一个成功，其他留原位。
- 门为橡木门；双方都能开、关、拆，每次成功 1 AP；拆除无返还/掉落。
- 门方向、上下半块、开关、铰链和跨格形状应按原版处理，并验证不越过占格/地面规则。
- 已部署门与坐垫不随所有者死亡消失；缩圈可强制清除有人坐垫。
- 箭穿坐垫本体，不破坏坐垫；乘坐者仍可正常中敌箭。

不能用装饰实体完全替换原生坐垫、用固定距离射线替换原版合法条件，或改变输入来规避难点。辅助实体若影响选择、箭路、眼高或动作，也须按 P0 验证；改变规则须先问用户。

## 8. 装备、弹药与生命

初始布局按确认稿第 4.3 节逐格给出：

- 1 弓；2 己方坐垫；3 门位（初始 0）；4 治疗 I；5 喷溅治疗 II；6 伤害箭 2；7 空；8 时钟；9 空。
- 唯一普通箭 1 在副手，确保默认普通射击。选第 6 格、交换副手、回到弓可以选择伤害箭。
- 弓有无限且不损耐久；药箭有限。不能凭空补回用完的药箭/药水或复制普通箭。
- 最大/当前生命均 40 HP。非敌箭正常战斗伤害禁用，无击退、不下座、饥饿满、自然回血关闭。
- 所有比赛物资禁止主动丢弃/转交；检查真实丢弃、容器、死亡与退出路径，保护入局前原有物品。

箭伤公式：普通箭为 6 × min(蓄力 tick,20)/20 HP；合法最短 3 tick；伤害箭在普通箭对应值上固定再加 6 HP。

不得按弹速直接代替线性蓄力比例；原版弹速曲线不同。随机暴击、原版药箭附加效果、飞行时间和原版受伤无敌时间均不得使最终结算偏离已定伤害。

每支箭一次有效命中独立结算，命中去重；基础与额外伤害合并为一次命中。友方含本人穿箭，不能只关闭友伤而仍挡箭或吞箭。

箭命中地形即清除，不能拾取。箭和喷溅药水发射后最长 200 tick，阶段结算截止可能使其更早清除。允许飞越失效空中区后重入，不人为增加初始 31×31 或棋盘下方的清理边界。

## 9. 治疗与同批处理

饮用治疗 I 为 4 HP、耗时 32 tick；喷溅治疗 II 完整强度 8 HP，保留原版碰撞箱距离强度与衰减，敌人也可能受益。不能简化为玩家脚部距离或固定全员 8 HP。

治疗免费且有限，不复活、不超过当前上限。只清理本局饮用产生的空瓶。

建议分清“收到输入”“已合法成功”“伤害/死亡”“治疗”“胜负锁定”，实际顺序必须满足：

1. 到期/恢复/补给先于同刻新操作；A 的 AP 只在该队阶段开始重置。
2. 在阶段/完整回合边界，先完成旧阶段合法事件、伤亡及中央胜负检查。
3. 本批箭伤先判死，再治疗仍存活者。不能治疗后才判断本应已死的玩家。
4. 没有旧阶段胜负时，才进入新回合缩圈、衰减；缩圈和衰减先于相应同刻治疗和新操作。
5. 先判双方全灭、再单方全灭、最后中央胜利；结果锁定后清除剩余投射物，不等待死者未命中箭。

不能把“同批”宽泛解释为任意延迟收集时间。P0 要记录事件触发顺序、服务器 tick 与接入位置，验证不会因命令排序或 tick 扫描漏掉本已发生的命中/死亡。

## 10. 中央反制窗口

需要记录候选队、资格是否连续有效、敌方完整行动阶段及其结算是否完成。

- 己方坐垫覆盖中央 9/9 即建立候选，不要求玩家坐在上面；门不计格。
- 等敌方获得一次完整行动阶段及对应投射物结算，不能立即获胜。
- 期间被破坏则取消该次资格，不能只在最后重新数到 9 就认定连续保持。
- 窗口最后一批先判伤亡与歼灭。候选队最后一人死，即使仍 9/9 也不能抢先判中央胜。
- 候选队未被歼灭、资格未取消且窗口结束仍 9/9，才判中央获胜。
- 本次窗口检查结束且无人获胜，才进入下一回合缩圈、衰减、补给。

须覆盖先手建立候选和后手建立候选两种情形，不能把“下一回合开始”硬写为统一获胜点。

## 11. 回合边界、收缩与衰减

设新回合为 r。可用下列公式校验确认稿表格，但仍以原表为准：

- 棋盘半径 R = max(2, 15 - max(0, r - 6))。
- 边长 = 2R + 1。
- 最大生命 M = max(2, 40 - 4 × max(0, r - 11)) HP。

第 7 回合首次缩圈；第 19 回合到 5×5，此后不再缩。第 6 回合首次预警下一失效圈；到最小时停止新增危险圈。预警区消失前仍可合法操作。

新回合收缩时按此前已完成的坐垫位置判定：仍在失效圈者直接淘汰，无视 HP；当刻的新换座不能抢救。清除失效区域的地面、坐垫、门、掩体相应部分及比赛掉落物，不返资源。

第 12 回合起最大生命每回合降 4，当前生命每回合降 2。对存活者：

- 当前 H >= 2 时，衰减值不低于 2；H < 2 时不得回升到 2。
- 最后当前生命还须不超过新最大值。
- 例：40/40 -> 36/36；20/40 -> 18/36；1/40 -> 1/36。
- r >= 21 最大值为 2，不因继续回合产生负上限、回血或额外致死。

无人获胜并进入下一回合时，先缩圈及其死亡，再按生命衰减规则处理；只给仍存活者每人补 1 垫、1 门。首次进入第 2 回合补给，第 1 回合不额外补。

先手初始背包 3 垫、后手 4 垫，出生座额外预置；坐垫库存上限 6、门上限 2。库存满或背包装不下时本次补给跳过，不累计、不掉落。

## 12. M1 地图

必须从坐标源数据生成，而不是分别手写多个不一致版本。

- 相对 X/Z 为 -15..15；中央 -1..1；最终 -2..2。
- 地面为完整黑白混凝土，固定掩体为两层完整石砖，每格高 2。
- 红出生 (-6,-13)、(-2,-13)、(2,-13)、(6,-13)。
- 蓝出生 (6,13)、(2,13)、(-2,13)、(-6,13)，编号按此对应。
- 出生前掩体：Z=-11、11；X=-7..-5、-3..-1、1..3、5..7，共 24 格。
- 中场短墙：Z=-7、7；X=-7..-5、5..7，共 12 格。
- 两翼短墙：X=-10、10；Z=-3..-1、1..3，共 12 格。
- 角柱：(±2,±2)，共 4 格。

共 52 占地、104 方块；初始非掩体格 909，最终 5×5 非掩体格 21。中央 9 格留空，最终四角柱保留。地图露天，不能加会挡高抛的顶棚、侧墙或装饰。

地图清单须记录实际维度、绝对原点、地面 Y、完整施工/清理包围盒。坐标高度等纯施工选择要明确记录；如果选择影响原版交互或新增玩法条件，先取得用户决定。

初始化只在用户明确选择的专用空世界或获准空区域执行。先检查范围内原内容，再施工；不能借“专用世界”省略保护。重置必须与清单一致，只清本项目地形和有本项目/本局身份的对象。不能使用未限定范围的 fill、kill、clear。

## 13. 信息与观战

| 接收者 | 可以看到 | 不能泄露 |
|---|---|---|
| 所有人 | 双方存活数、中央格数、回合/阶段时钟、预警、最终结果 | 敌方个人资源 |
| 本队成员 | 各队员当前/最大血量、个人 AP、比赛背包物资、共享 AP、结束确认 | 对方上述个人字段 |
| 正在瞄准敌人的玩家 | 仅无遮挡目标的当前/最大血量 | 移开准星或遮挡后保留血量、全局敌方血量表 |
| 已淘汰者 | 仅跟随本队存活队友；允许原版自然展示的己方信息 | 自由飞行侦察、切到敌方、复活或重返操作 |

具体呈现可使用原版 UI 能力组合，但不能因单条显示放不下而精简已定字段。若实现只能分时显示、增加切页操作或改变信息获得方式，应先说明影响；不要默认为原稿已批准这种取舍。

检查所有侧栏、队伍侧栏、头顶名牌、列表、bossbar、actionbar、聊天、实体文本和观战菜单。只隐藏一个面板不足以证明没有泄露。

## 14. 断线、结果、中止和新局

- 正式断线立即淘汰；重连只观战，不因新实体、重新领取物品或重入队伍复活。
- 准备断线导致不足 8 人时回等待，保留仍在场者预约。
- 淘汰清除个人比赛 AP/物资，无掉落；门/坐垫保留。
- 不能自行新增 AFK 淘汰或托管。
- 结果锁定后停止全部比赛效果，禁止新治疗、AP 行为和迟到投射物命中。
- 中止无获胜方，回等待。下一局由组织者手动开始，重新选队/选位，不继承预约。
- /reload、重进世界、服务端重启等没有明确产品语义的中途恢复行为，如会影响比赛，需要报告并请用户决定；不自行决定“自动续赛/自动判负/抹掉结果”。

## 15. 验证与交付关联

开发者在报告中填写“模块 -> 真实文件 -> 真实入口 -> 用例 ID -> 证据路径”。P0、正式实现、加载成功、八人实测和用户验收分别报告，不混用状态。

正式 ZIP 不含测试作弊入口、账户/凭据、服务器程序、运行日志、备份或无关个人存档数据。若公开测试辅助命令确有需要，应先说明权限与隔离，不默认打入玩家包。

技术设计以可验证结果为目标，不要求特定复杂框架。能用清晰的少量函数实现时不引入大型依赖；任何必要的重大技术变更都回到用户决定。
