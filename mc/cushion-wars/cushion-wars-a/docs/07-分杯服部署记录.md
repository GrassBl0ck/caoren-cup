## 4. 部署过程中修正的两个真实问题

### 4.1 出生坐垫 NBT 字段过期（已修）

第一次建图出现 8 条 `Block-attached entity at invalid position: null`。
从服务端类文件 `net/minecraft/world/entity/decoration/BlockAttachedEntity.class` 里确认：**26.3 用 `block_pos` 整数数组记录挂接方块**，`TileX/TileY/TileZ` 已不适用。
已改为 `block_pos:[I;x,y,z]` 并加 `color:"red|blue"`，重建后 8 个坐垫全部正常，插件计数 8/8。

### 4.2 远景平台预检失败（已修）

第二次建图时地面 0/961、掩体 0/104，但无任何命令报错：`arena/init` 执行了预检就拒绝。
根因：**数据包 `#minecraft:load` 阶段远景区块未加载**，`execute unless block` 对未加载区块判定为非空气，预检计数被抬高。
修法：`arena/init` 开头先 `forceload add`（施工区 19985..20015）再预检。重建后预检 0，建图成功。
`forceload` 生成的坐标有界，已加静态校验（`verify_pack.py` 的“forceload 均带四个显式坐标”）。

### 10.2 服务器上怎么按人数建图

```
/function cushionwars_a:arena/prepare {team:N}
```

N = 1—8。流程：强制加载 47×47 → 清空最大施工区（含残留坐垫/掉落物/箭）→ 地面 → 掩体 → 出生坐垫 → 逐格自检，

- 插件侧 `/cwprobe n <N>` 同步共享 AP 与越界判定；插件启动时也会**从世界实测**棋盘半宽自动对齐。
