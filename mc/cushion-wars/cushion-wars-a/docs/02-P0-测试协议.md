# P0 能力验证协议（G01—G08）

本文件是**待执行**的测试协议。截至 2026-10-25，八个关卡的状态全部是 `NOT_RUN`：本机没有 Minecraft 26.3 客户端与服务端，用户明确选择纯静态交付，不调用外部程序。任何一项都不得被写成通过。

## 0. 环境与记录规范

### 0.1 最低环境

| 项目 | 要求 |
|---|---|
| 客户端 | Minecraft Java 26.3，原版，无模组、无强制资源包 |
| 服务端 | 26.3 官方服务端（或等价的 26.3 专用服务端），仅本机/局域网 |
| 人数 | G01—G05、G07 至少 2 人；G06 至少 3 人；八人场景单列 P05 |
| 数据包 | `cushionwars-a-p0-probes`（探针）与 `cushionwars-a-datapack`（地图层）分别安装 |

### 0.2 每条记录必须包含

```
case_id, required_level, actual_level, status, environment, actual_action_or_command,
expected, actual, evidence_path, issue_id
```

`status` 只能填 `PASS` / `FAIL` / `NOT_RUN` / `BLOCKED`。需要 `C`（真实客户端）的用例，只有 `S`/`F` 证据时不得填 `PASS`。

### 0.3 证据保存

- 视频：`runtime/evidence/<case_id>.mp4`
- 原始日志：`runtime/evidence/<case_id>.log`（服务端日志整段另存 `runtime/logs/server-<时间>.log`）
- 数据快照：`/data get storage cw_p0:log snapshots` 的原样输出，贴入上表 `actual`

### 0.4 探针命令

| 命令 | 用途 |
|---|---|
| `/tag <玩家> add p0_subject` | 标记采样对象 |
| `/function cw_p0:probe/snapshot` | 采样生命、坐标、是否乘坐 |
| `/function cw_p0:probe/dump` | 输出采样摘要 |
| `/function cw_p0:probe/reset` | 清空采样记录 |
| `/function cw_p0:g07/raycast` | 粗粒度准星射线检查 |
| `/function cw_p0:g08/timer_start` | 600 tick 计时器 |

## G01 输入与 AP 门禁

**要回答的问题**：能否在真实输入路径上，让“失败的操作”不产生任何有效结果，也不扣 AP 或物资？

**已知风险（静态证据，非实测）**：数据包函数只在 tick 边界运行；原版交互（`CushionItem.useOn`、门方块 `use`、`BowItem.use/releaseUsing`）在玩家输入当刻即已完成并返回结果。数据包只能“看到结果再回滚”。

**步骤**

1. 玩家不持有任何坐垫，试着用原版方式在脚下放置坐垫（探针包不改变物品），记录是否出现任何坐垫实体。
2. 给玩家 1 个坐垫但把 AP 设为 0，重复放置，记录坐垫实体数量变化、掉落物、背包变化。
3. 玩家 AP 为 1、共享 AP 为 0，队友个人 AP 为 2，尝试连续两次放置。
4. 同一 tick 由两名玩家争抢最后 1 点共享 AP 的一次操作，各重复 10 次。
5. 玩家按住右键持续放置 5 秒，记录实际成功次数与 AP 消耗是否一一对应。

**必须记录**：每次尝试前后的坐垫实体数（`/execute if entity @e[type=minecraft:cushion]`）、背包数量、AP 分数、服务端 tick 顺序。

**判定**：只有在“失败即无任何有效结果（含 1 tick 的瞬时结果）”时才算 PASS。若必须靠下一 tick 回滚才能恢复，按 G01 的定义为 FAIL。

**关联**：A01—A07、S02、D02。

**当前状态**：`NOT_RUN`

## G02 乘坐、占座与主动下座

**要回答的问题**：能否限制敌座/有人座，并让“主动下座”不构成合法地面移动？

**已知风险**：`Player.wantsToStopRiding` 返回潜行状态，`rideTick` 内含 `stopRiding` 路径；数据包无法覆写方法，只能每 tick `ride ... mount` 重挂，存在 1 tick 空档。

**步骤**

1. 玩家坐己方坐垫，按住潜行 3 秒，逐 tick 采样 `Pos` 与 `seated`（`probe/snapshot` 每 tick 人工触发或用 `g08/timer` 同步），记录是否出现下座帧、是否有水平位移。
2. 同上，但在潜行同时按住方向键与跳跃。
3. 空手右击敌方坐垫、队友已占用坐垫、己方空坐垫，各 5 次，记录是否发生换座、AP 变化。
4. 两人同 tick 争抢同一空坐垫，重复 10 次，记录是否两次都成功。
5. 从坐垫状态测量眼高、可达方块面：对正前方/斜前方/上下方逐格测试可放置距离，记录实际可放置的最远格数（不要套用 4.5/3.0 属性值）。
6. 拆有人坐垫（本人/队友/敌人），记录是否被拒绝。

**判定**：下座若存在任何“已生效”的地面位移或可操作帧 → FAIL。若采用每 tick 重挂且可证明无有效位移，需在报告中附逐 tick 采样；仅凭肉眼“看起来没动”不构成证据。

**关联**：S01、S03—S06、S08、S09。

**当前状态**：`NOT_RUN`

## G03 门与放置互斥

**要回答的问题**：门与坐垫的占格互斥、支撑条件、主手用途优先能否严格成立？

**步骤**

1. 主手弓、药水、坐垫、门、控制物分别对同一扇门右键，记录门状态是否变化、是否重复扣 AP。
2. 空手（副手持箭）右击门与己方空坐垫，记录路由是否正确，失败时是否转做另一种 AP 行为。
3. 门与坐垫尝试同格；先开门再在同一格放坐垫。
4. 在掩体顶、门顶、悬空处尝试放门/放垫。
5. 双方开关与拆除对方门，记录 AP 变化、是否掉落。
6. 连续部署 3 扇门（超出背包上限 2）：记录是被库存限制还是被场地限制。

**判定**：任一次“失败操作”产生了有效门状态变化或 AP 扣除 → FAIL。

**关联**：D01—D08、S02。

**当前状态**：`NOT_RUN`

## G04 箭矢与逐箭独立伤害

**要回答的问题**：能否做到逐箭独立结算、不受受伤无敌吞伤、己方含本人穿箭、坐垫穿箭、线性伤害 0.9/3/6 与 +6？

**已知风险**：箭命中走 `AbstractArrow.onHitEntity → LivingEntity.hurt`，`invulnerableTime` 在首次命中后置位，同 tick 后续命中被吞；数据包无法取消 `hurt`，也没有可写的“箭伤=0”字段证据。

**步骤**

1. 满蓄力普通箭单发命中，记录 `Health` 变化（应 6，即 3 颗心）。
2. 4 支满蓄力普通箭在 1 tick 内命中同一目标（4 名射手同时松弦，或用命令生成 4 支同 tick 到达的箭），记录总伤害（期望 24）与每次命中的独立日志。
3. 同上改用伤害之箭（期望 48，可淘汰 40 HP 玩家）。
4. 3 tick 与 10 tick 蓄力各测一次，记录实际伤害（期望 0.9 / 3，允许记录原版取整行为）。
5. 己方两人与射手共线，射手射击其后的敌人，记录箭是否被挡、是否造成友伤。
6. 射击坐在坐垫上的敌人，记录坐垫是否被破坏、乘客是否中箭。
7. 箭命中地形后尝试拾取。

**判定**：第 2、3 条是关键。若同 tick 多箭只结算一次且数据包无法补偿到“每箭独立”，G04 判 FAIL 并阻塞战斗层。

**关联**：B01—B16。

**当前状态**：`NOT_RUN`

## G05 治疗与同批顺序

**要回答的问题**：能否保留原版治疗，同时保证“本批伤害先判死、再治疗存活者”和跨阶段饮用？

**步骤**

1. 饮用治疗 I，记录从开始到完成的 tick 数与 `Health` 变化（期望 32 tick、+4 HP）。
2. 喷溅治疗 II 直接命中、4 格边缘、上方投掷，分别记录恢复量与敌人受益情况。
3. 在敌方行动阶段治疗，记录是否被允许。
4. 致死箭伤与完成饮用同 tick 发生，记录是否出现“治疗后未死”。
5. 结果锁定（模拟）后再完成饮用，记录是否仍然回血。
6. 空瓶是否只清理本局产生的。

**判定**：第 4 条若无法证明“先死后治疗”，G05 FAIL。

**关联**：H01—H10、A20。

**当前状态**：`NOT_RUN`

## G06 观战、断线与重连

**要回答的问题**：死亡后能否只跟随己方存活队友，不获得自由侦察？

**已知风险**：spectator 自带自由飞行与穿墙；数据包只能每 tick 传送或用其它模式限制，无法从根上禁止。

**步骤**

1. 玩家死亡后进入观战，尝试自由飞行、穿墙、切换到敌方视角，逐项记录是否成功。
2. 同上但每 tick 被传送回队友处（需先实现该机制），记录视角抖动与是否仍可侦察。
3. 比赛中主动断线后重连，记录是否复活、是否能重新领取资源。
4. 被跟随的队友死亡/断线后，记录是否出现临时自由视角。

**判定**：只要存在任何可用的自由侦察路径（哪怕短暂），G06 判 FAIL 或 PARTIAL，并在报告中列出具体路径。

**关联**：E01—E10、I03。

**当前状态**：`NOT_RUN`

## G07 信息隔离与准星血量

**要回答的问题**：己方全字段可见、敌方只在准星指向且无遮挡时显示血量，能否做到且不漏信息？

**已知风险**：没有原生的“准星目标”选择器；只能用射线近似，遮挡与实体包络难以严格一致。探针里的 `g07/raycast` 只是 5 段粗粒度示意，不能作为正式方案。

**步骤**

1. 检查侧栏、玩家列表、头顶名牌、聊天、动作栏、bossbar、文本实体，逐一记录是否泄露敌方 AP/物资/血量。
2. 敌人可见但不瞄准 → 不应显示血量。
3. 瞄准且无遮挡 → 应显示该敌人当前/最大血量。
4. 移开准星 / 敌人被掩体遮挡 / 敌人躲在门后 → 应隐藏。
5. 同一 tick 两名敌人在准星方向前后重叠，记录显示哪一个、是否有误判。

**判定**：任何全局敌方血量名单或敌方 AP/物资泄露 → FAIL。准星近似若存在“明显误判”（例如瞄准 A 显示 B），按 PARTIAL 记录并说明误差范围。

**关联**：I01—I04。

**当前状态**：`NOT_RUN`

## G08 计时、去重与定向清理

**要回答的问题**：统一 tick 截止、清理范围是否严格可控？

**步骤**

1. `/function cw_p0:g08/timer_start`，用秒表核对 600 tick 的实际耗时，记录 TPS。
2. 在施工框外放置一个带标记的普通方块与一个掉落物，执行 `arena/reset`，确认框外内容不变。
3. 在框内放置非本项目方块，执行 `arena/init`，确认被拒绝并报出数量。
4. 执行 `arena/shrink`，确认只清当圈、圈内不受影响。
5. 比赛中执行 `/reload`，记录地图与状态是否被无提示重建（这是 E10 的中途恢复语义问题，需用户决定）。

**判定**：清理越界或状态被静默重建 → FAIL。

**关联**：M08—M10、E10、P02。

**当前状态**：`NOT_RUN`（地图层的静态产物一致性已由 `tools/verify_map.py` 覆盖 29 项，但那不是运行证据）
