# 安装与验证（地图层）

本文对应 `dist/cushionwars-a-datapack-0.1.0-static.zip`。该包当前**只含地图层与状态推导层**，不含玩法层（见 `src/round-a/README.md`）。

## 1. 前置条件

| 项目 | 要求 | 本机实际 |
|---|---|---|
| Minecraft Java | 26.3（数据包版本 121） | **未安装**（`.minecraft/versions` 只有 26.1.2 等，无 26.3） |
| Java 运行时 | 主版本 25 | 已安装 25.0.3（Microsoft OpenJDK） |
| 世界 | 专用小游戏世界，施工框内为空 | 未创建 |

没有 26.3 客户端时，下面的步骤只能作为流程说明，**不能产生任何实际验证结果**。

## 2. 安装

1. 新建一个专用世界（建议超平坦或空世界），不要使用已有存档。
2. 在该世界目录下建立 `datapacks/`，把 ZIP 直接放入（26.x 支持直接读取 ZIP，不必解压）。
3. 进入世界后执行 `/reload`，或重新进入世界。
4. 控制台应出现：`[cushionwars_a] 已载入：地图层与状态层。玩法层等待 P0 结论，未启用。`
5. 若出现命名空间或 pack_format 报错，先看 `docs/03-26.3语法待验证清单.md`——本包的语法字段全部未经 26.3 实际加载核实。

## 3. 初始化地图

坐标与结构全部来自 `maps/m1/board.json`，由生成器写入函数，不需要手工摆方块。

1. 把组织者移动到施工区附近（命令不受距离限制，但便于观察）。
2. `/function cushionwars_a:arena/init`
   - 先对施工框 X −15..15、Y 63..65、Z −15..15 逐格预检共 2883 个位置。
   - 若有任何非空气方块，直接拒绝，并报出冲突数量，**不会覆盖**。
3. 成功后执行 `/function cushionwars_a:arena/selfcheck`，应输出“地图自检通过”。
4. `/function cushionwars_a:arena/reset` 可清空施工框并重建（新一局前使用）。

## 4. 缩圈与预警

1. `/scoreboard players set #in_round cw_a_match 12` 再 `/function cushionwars_a:admin/set_round`
   —— 设定回合，并推导棋盘边长与最大生命，会输出“棋盘 19x19，最大生命 36”。
2. `/function cushionwars_a:arena/shrink` —— 按该回合清除当圈（地面、掩体、坐垫、门、投射物）。
3. `/function cushionwars_a:arena/warn` —— 用火焰粒子显示下一失效圈（不改方块、不改碰撞）。

## 5. 组织者命令一览

| 命令 | 作用 |
|---|---|
| `/function cushionwars_a:admin/help` | 列出全部可用命令 |
| `/function cushionwars_a:arena/init` | 预检后初始化 M1 |
| `/function cushionwars_a:arena/reset` | 清空施工框并重建 |
| `/function cushionwars_a:arena/selfcheck` | 逐格比对地图与源数据 |
| `/function cushionwars_a:arena/shrink` | 按 `#round` 执行缩圈 |
| `/function cushionwars_a:arena/warn` | 按 `#round` 显示预警粒子 |
| `/scoreboard players set #in_round cw_a_match <n>` + `/function cushionwars_a:admin/set_round` | 设置回合 |

## 6. 与源数据的一致性

- 修改地图只能改 `maps/m1/board.json`，然后依次执行：
  ```
  python tools/gen_map.py
  python tools/verify_map.py
  python tools/verify_pack.py
  python tools/build_pack.py
  ```
- `arena/gen/` 下的文件是生成物，不要手改；`verify_map.py` 会解析生成物并与源数据比对，手改会被判 FAIL。
