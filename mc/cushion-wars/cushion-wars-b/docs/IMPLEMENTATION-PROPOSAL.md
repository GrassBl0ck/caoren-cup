## 3. 人数、棋盘与时间安排

每队 N=1—8，默认 4。边长 S=4N+15，半径 H=2N+7；每次缩圈四边各退一格，总边长减 2，最终边长 5。出生点、默认两层掩体使用 A 已有的按人数几何规则，N=4 对应 M1。

所有人数均采用：

- 准备 5 秒，不计入比赛钟；比赛 90 秒硬截止。
- 首次缩圈第 20 秒，最后一次第 86 秒；最终 5×5 保留到第 90 秒。
- 每次缩圈提前 3 秒预警，首次第 17 秒；最后一次缩圈后无新预警。
- 普通 AP 初始/上限 3，每人从离开满值起每 1.5 秒恢复一点；未满时继续消耗不重置计时。
- 每人整局三次临时 AP 激活，每点独立有效 3 秒；先扣最早到期的临时 AP。
- 两次成功换座至少相隔 1 秒。
- 第 5—85 秒每 5 秒给存活者补给一次，总计 17 波；第 90 秒不补。
- 第 45 秒首次生命衰减，此后每秒一次，数值及最低生命规则沿用 B-V1.0。

| 人数 | 初始棋盘 | 缩圈次数 | 相邻缩圈间隔（tick 对齐后的实际值） |
|---|---|---|---|
| 1v1 | 19×19 | 7 | 11 秒 |
| 2v2 | 23×23 | 9 | 8.25 秒 |
| 3v3 | 27×27 | 11 | 6.6 秒 |
| 4v4 | 31×31 | 13 | 5.5 秒 |
| 5v5 | 35×35 | 15 | 4.7 / 4.75 秒 |
| 6v6 | 39×39 | 17 | 4.1 / 4.15 秒 |
| 7v7 | 43×43 | 19 | 3.65 / 3.7 秒 |
| 8v8 | 47×47 | 21 | 3.3 秒 |

选择理由：让不同人数都有相同的开场展开时间、后半程生命压力与最终决胜窗口，较大的地图用更多次收缩完成压缩；保留 4v4 既定节奏。最短间隔 3.3 秒仍大于 3 秒预警，不会出现两次危险圈预警重叠。这是首轮试玩方案，不代表推进距离、AP 或射击平衡已经实测。

### 精确 tick 规则

使用整数 tick 作为唯一时钟：20 tick = 1 游戏秒；卡顿时现实耗时可能增长。

令缩圈次数 K=(S-5)/2=2N+5，D=K-1=2N+4，第 i 次缩圈的下标 i 从 0 到 K-1：

```text
shrinkTick(i) = 400 + floor((1320*i + D/2) / D)
warnTick(i)   = shrinkTick(i) - 60
newSide(i)   = S - 2*(i+1)
deadlineTick = 1800
```

D 为偶数，计算全部使用整数；等价于将等距目标四舍五入到最近 tick，半 tick 向上。不要逐次累加四舍五入后的间隔，以免最后一次偏离 86 秒。

### 同批顺序与硬截止

按 B-V1.0，达到第 1800 tick 时先锁定截止，不接受此刻新命中、操作、治疗、AP 恢复或补给；清除未命中投射物，按截止前已确认状态比较中央格数、存活人数，相同则平局。

有效比赛期间同批依次保证：到期缩圈/生命衰减 → 箭伤及死亡 → 存活者治疗；AP 到期/恢复与补给先于新操作；所有合法操作与伤亡完成后统一判断双方全灭、单方全灭、中央占满。不能在一次放垫事件回调内提前锁中央胜利而漏掉同批致死箭。实现需要把原版回调纳入统一、有可测试边界的结算流程，不能简单复制 A 的即时广播和结果判断。

## 4. 命令、权限与配置

下列为本轮接入方案，全部命令按当前地图守卫检查，所有参数支持前缀 Tab 补全且按权限过滤。

| 命令 | 用途 / 权限 |
|---|---|
| /cwb help、status | 帮助及公共战况，不泄露敌方个人资源 |
| /cwb join red\|blue、leave | 加入/离开队伍；cushionwarsb.play，默认 true |
| /cwb spawn <1-N>、spawn clear | 选择/取消己方出生点，另提供聊天可点击按钮 |
| /cwb start、stop | 管理员开局/中止；cushionwarsb.admin，默认 OP |
| /cwb size <1-8> | 候场时设置人数并恢复对应模板，成功后持久化，无需追加 build |
| /cwb build [1-8] | 恢复已保存模板；没有模板才采用默认布局，不代表恢复出厂 |
| /cwb edit begin <1-8>、edit save、edit exit | 管理员创造编辑、保存和退出；exit 恢复已保存棋盘 |
| /cwb config show | 查看当前/下一局设置与缩圈时间；不新增未批准的自由改时功能 |

size、build、edit begin 在比赛或其他编辑任务进行时拒绝；配置和人数只在安全候场状态修改。换人数时释放不再适用的出生点预约，重新选择，不在进行中改变地图或阵容。

插件数据归属 plugins/CushionWarsRealtime/：

- config.yml：board.world、board.center-x、board.center-z、board.ground-y；rules.team-size 默认 4、范围 1—8。原点必须显式配置，不从 A 的运行配置推断或复制。
- arenas/n1.yml 至 n8.yml：各人数独立模板，保存地面和上方两层、校验中央金块/出生空间/实心支撑；不保存比赛实体或容器。
- recovery/：按 UUID 保存恢复记录，运行数据不进 Git。
- 缩圈公式和其他规则版本固定为本文首版，通过整数 tick 算出；设置展示包含当前人数对应时间表。
- 兼容环境、默认值、修改时机、备份与恢复写入 B 的 README；配置非法拒绝启用，不静默回退其他世界。

游戏内编辑与 A 相同：保存成功后 exit 才离开编辑；未保存棋盘编辑不持久化，场外景观由世界存档保存且 exit 不撤销。默认模板中央 3×3 使用金块标识。背景建筑在最大 47×47 施工范围之外；不增加屋顶或棋盘下托底层。测试使用隔离地图，实际高原背景复用/复制随部署另行处理，不自动复制现服存档。

## 6. 生命周期与异常处理方案

- 等待 → 5 秒准备 → 同时行动 → 结果锁定 → 清理 → 等待。每队须满 N 人；保留合法选位，未选者随机填本队余位；准备开始锁名单、位置和阵营。
- 准备中缺人取消，释放离场者点位，保留仍在场者预约；重新开始仍由管理员触发。
- 断线/死亡本局淘汰，重连只观战；只能跟随己方存活者，不开放自由侦察。队伍全灭按原稿结束。
- 正常胜利与90秒截止都先锁结果，再清投射物和比赛资源；保留赛果，下一局重新选队选位。
- 管理员 stop、正常停服和切图视为中止，不判任何队胜；通知并收尾，切图仍会全员断开。B 不新增自动战绩或奖励。
- 重复 start/stop 拒绝或幂等；旧任务携带局次标识，下一局不能接收上局命中、治疗或补给。
- 崩溃后不恢复半局、不自动判胜负，按可靠快照恢复玩家并回等待；离线玩家保留待恢复记录直到重连。
- 配置、世界、模板、恢复记录损坏或恢复传送失败：记录可定位错误并保留原文件/快照；阻止涉及玩家入局或整局开始，不伪造空快照清背包。
- 世界与实体操作只在服务端主线程；文件保存不每 tick 执行，写入采用校验后的临时文件与替换。每局只有一套时间推进器，不为每个 AP 开独立周期线程。
- 性能目标按最多 16 名参赛者及 47×47 棋盘核验；不承诺 Folia、多实例或无限观战人数，不加入未经验证的每 tick 全世界扫描。
