## 3. 消息发送规则

| 场景 | 收件人及颜色 | 必须包含或保留的内容 |
| --- | --- | --- |
| 管理员修改其他玩家、队伍或全服规则成功 | 全服，红色 [草人杯] | 目标、实际变更、立即/下回合等真实生效时机；不写操作者 |
| 上述管理设置关闭、清除、恢复默认 | 与启用、修改相同的公示原则 | 哪些设置被清除、恢复到何值，不能只有开启时公告 |
| 个人设置、帮助、查询、用法、权限拒绝、执行前失败 | 本人，绿色 [草人杯] | 清楚说明结果或可行的下一步；不公开私密内容 |
| 己方通知或明确指定的小组通知 | 对应队伍或小组，黄色 [草人杯] | 保留原有接收限制；不是遍历发给多人就都用绿色 |
| 投票全服结果等全员共同通知 | 全服，红色 [草人杯] | 公共结果；不能通过逐人私聊接口导致全员消息变成绿色 |
| 异能职业分配、更改、清除 | 全服，红色 [草人杯] | 目标玩家显示名、职业中文显示名、清除状态、生效时机；不写操作者 |
| 验证码、账号信息、卧底身份、秘密任务等 | 保持原有私密范围 | 单人私密回复绿色；指定小组共同通知黄色；不得向无关玩家披露 |
| 服务器控制台回复 | 控制台保留文字 [草人杯] | 不依赖游戏颜色码，不能用 [CaorenCup] 等替代规定文字前缀 |

公示示例（不写操作者）：

- [草人杯] CT 队头部缩放已设为 2 倍，立即生效。
- [草人杯] 所有玩家的循环体型缩放已停止，已恢复原体型。
- [草人杯] 玩家小明的异能职业已改为医师，下一回合生效。

实现时沿用现有命令权限、目标解析、数值与玩法规则；本任务只改变消息行为。正文可保留有助理解的强调色，但 [草人杯] 前缀按可见范围着色且每条只出现一次。

公示不得添加“管理员某某”“网页某账号”“由某人操作”等操作者信息。此要求针对管理公示，不要求删除既有内部审计日志，也不删除正常玩家聊天的发送者署名。

## 4. 发送时机、去重与隐私

- 以实际执行结果决定消息，不能先公告成功再尝试修改。下回合才生效必须说清楚，不能显示为已经即时生效。
- 部分成功应准确说明已改变的部分与未成功的范围；详细错误只给执行者或现有内部日志，不把失败伪装成完整成功。
- 同一次批量修改发送一次清晰摘要，避免为每个目标重复刷全服消息；操作者也能看到公共结果时，不重复发送相同成功回执。
- FV 的每帧循环、HD 自动战绩缩放、HUD 刷新、正常重生后的状态重施，不为每个数值或每帧广播。公告针对管理配置变更或值得告知的故障状态转换。
- 轮询、重试和同一状态的重复回调不能持续刷相同公告。必要提示不应因粗暴全局限流被误吞。
- 菜单、聊天命令、网页桥接、服务器控制台等现有入口应遵守同一结果规则；不能通过更换入口绕开公示或产生双份公告。
- /notice 当前按网页名单筛选收件人。本次保留其现有选择逻辑，明确显示“本场网页名单”等实际范围，避免把它写成服务器全体；不得擅自把 all 扩大为所有在线玩家。若需要改变实际收件人，单独提出并等待用户决定。
- 观察者队聊转发仍只发原有观察者，按指定小组使用黄色前缀并保留原聊天署名；不扩大发送到敌队，也不改变已有旁观规则。
- 个人设定与玩法管理的边界如存在实际歧义，列出具体命令询问用户，不自行把私密设定改为公告或把应公示的修改归为个人设置。
