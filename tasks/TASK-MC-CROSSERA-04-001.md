### 命令、权限和配置（用户已批准）

- `/cecombat profile <在线玩家> <old|modern>`：将其当前世界的规则设为旧版或现代；用可信在线 Player/UUID 定位，昵称只用于查找和显示。
- `/cecombat status [在线玩家]`：查看生效规则、后端、版本与诊断状态；所有管理动作校验 `cross-era.combat.admin`，默认仅 OP。
- 使用 OCM **命名 modeset** 作为当前后端的实际规则来源；旧/现代两套预设名称由本插件配置映射。按照公开 API 的正常语义，选择按 UUID 和世界保存，重连后保留；不再另存一份可能不一致的玩家规则表。
- 现代预设应维持本任务范围内的现代原生行为，新玩家采用现代预设；不能直接把上游默认 `new` 预设当作已经符合原版。
- 本插件 `config.yml` 管理实验启用开关、允许世界、后端与两套 modeset 名称；示例默认不接管任何世界。明确字段类型、默认值、校验和生效时机；非法配置或缺依赖时拒绝启用本插件，不替服务器改装依赖或停服。
- OCM 示例配置只放新工程 `examples/`，经最小模块审计后提供；不覆盖生产配置。需要重启生效的配置应明确说明，不实现动态重载入口。
- 命令反馈统一使用本插件内一个消息工具，添加 `[草人杯]` 和仅执行者可见的绿色；控制台保留文字前缀。暂不创建全 MC 公共基础插件，也不改造现有消息模块。

## 已确认的规则与本轮范围

1. 旧战斗基准为 **1.8.9**，现代目标为 **26.3**；实际客户端版本与规则身份分开。本轮只承诺现代客户端，不实现旧客户端接入。
2. 攻击规则跟随攻击者，防御规则跟随受击者。不能因为某一方为旧版就把整次交互全部按旧版处理。
3. 无法归属来源的环境伤害跟随受伤玩家；消耗品跟随使用者。这些原则保留，本轮不扩展实现完整环境和消耗品。
4. 最小范围：无附魔钻石剑的普通攻击、攻击冷却、暴击；无护甲和完整无附魔钻石护甲；基础击退和受伤无敌；规则切换与战斗日志。
5. 原版机制保持原意，平衡以后通过装备、资源、地图和目标处理，不在本轮新增平衡系数。
6. 本轮不实现游戏队伍、人数门槛、胜负、奖励、背包发放、传送、复活流程、网站绑定或正式地图；不设计多房间、代理、转服、常驻副服及其预留接口。
7. 正式接入继续沿用既有 Esc 切图。玩法插件与 OCM 的加载隔离留在正式接入任务，不能把本轮独立测试工程称为已经完成隔离。
