## 2. 技术基线(来自 hud-click-probe 验证,不重新论证)

- 路线:CS2 实验性实体 `custom_hud_layout` + CSSharp v1.0.374 CustomHudLayout API,现有技术栈原生成立,不引入 SwiftlyS2。
- 三层架构:引擎层(Valve)→ 插件层(C#/CSSharp)→ 资源层(Panorama XML/CSS,需 resourcecompiler 编译为 `_c` 文件后打 VPK)。
- 能力边界:**仅 Panel / Label / Image / Button 四种控件,无客户端 JS,交互只有按钮点击回传**。菜单只能是分页+按钮形态,没有输入框。

- 验证后两端测试残留已清理干净;正式开发从 hud-click-probe 移植代码,不直接复用部署。

## 4. 阶段 1 详细规划:管理员快捷面板

### 4.1 目标

把主持比赛最常用的操作按钮化,减少记命令、敲命令的负担。不追求覆盖全部命令——复杂参数仍走聊天命令,菜单负责高频、低复杂度操作。

### 4.2 打开与关闭

- 管理员在聊天输入 `/menu`(命令名实施时可再定)打开;权限校验沿用插件现有管理员判定体系(实施前核对 `CaorenCupPlugin.cs` 与各 Feature 的现有写法,不新造权限机制)。
- 打开时开启输入捕获,面板出现关闭按钮,点击后释放捕获并收面板(与 probe 的 `probe_close` 行为一致)。

### 4.3 页面结构(分页+按钮)

```
主菜单页
├─ 模块总控:各娱乐模块的 T / CT / 全体 / 关闭 快捷切换
├─ 参数调整:倍率/时间类的常用档位(见 4.4)
├─ 预设与流程:预设应用(PresetFeature)、重置、保存、状态
├─ 广播与音效:玩法说明广播、全服音效、规则显示
└─ 关闭
```

具体进第一版的功能清单在实施前**从实际代码盘点后由用户确认**。注意:`docs/caoren-game-commands.csv` 已过时(其中 OMAFeature.cs 实际不存在),盘点以 `game-plugin/Features/` 现有代码为准。

### 4.4 参数输入的设计约束(核心难点)

HUD 菜单没有输入框,现有命令大多是 `<t/ct/all/0> <数值>` 两段参数。第一版按四类处理:

1. **开关类**(如二段跳、ESP):目标选择按钮组(T/CT/全/关)直接完成。
2. **档位类**(如经济倍率、伤害倍率):每个功能预设 3~5 个常用档位按钮,档位数值实施时定。
3. **步进类**:当前值显示在 Label 上,提供 +/- 按钮循环调节,适合范围明确的值(如 FOV 30–150)。
4. **复杂参数**(多参数组合、自由数值):菜单不承载,在面板上显示命令模板引导管理员回聊天输入。

### 4.5 技术整合方式

- 并入 `game-plugin/`(娱乐插件本体),新增目录如 `Features/InGameMenu/`。理由:管理员面板直接调用现有 Feature 的公开方法与状态,避免跨插件通信;独立插件反而要复制一层接口。
- 菜单做成**通用可扩展框架**,不是一次性面板:菜单服务统一管理"页面注册、权限过滤、分页、回调分发",后续阶段 2/3 的玩家功能与投票复用同一框架,只是入口权限和页面不同。
- 资源文件(XML/CSS)模板化:布局结构固定,按钮文字与当前值全部走 `SetDialogVariableString` 动态填充,改功能不需要改 XML。
- 构建链路照搬 probe README 第三节:本机 CS2 resourcecompiler 编译 → VPKEdit 打包 → 服务器 `plugins/` 放 DLL、`overrides/` 放 VPK 并在 gameinfo.gi 挂载(管理员手动方案的部署形态,README 第四节)。
- 目标框架 net10.0(CSSHarp 374 起强制);升级 CSSharp 版本时复查 Linux execstack 问题(README 第六节第 3 条)。

### 4.6 实施顺序建议

1. 功能盘点:从 `game-plugin/Features/` 现有代码整理"可按钮化"清单与当前值查询方式,交用户确认第一版范围。
2. 菜单框架:页面/按钮模型、权限过滤、分页、回调分发(纯 C#,可先单元测试)。
3. 资源层:在 probe 基础上做正式的菜单 XML/CSS 模板并打通本地编译打包。
4. 集成:接入 game-plugin,管理员面板各页面接线。
5. 本地/测试服验证:渲染、点击、权限(非管理员不可见/不可用)、与现有功能回归。
6. 管理员端手动分发装机(少量管理员)。

## 5. 风险与已知坑(继承自 probe README 第六节)

1. `custom_hud_layout` 是 Valve 实验特性,CS2 大版本更新可能变动,需关注更新日志。
2. 面板类型只有四种、无事件脚本,所有交互必须收敛为"按钮点击"。
3. 客户端 `gameinfo.gi` 会被 Steam/CS2 进程锁定,管理员手动装机要在 Steam 完全退出后进行(写入装机说明)。
4. 菜单打开时输入捕获会占用鼠标(准星消失),必须保证任何路径都能关闭菜单释放输入,避免玩家"卡在菜单里"。
5. 并入 game-plugin 后的回归:菜单仅新增监听与实体操作,不改动现有 Feature 逻辑;仍需跑现有测试确认零影响。
