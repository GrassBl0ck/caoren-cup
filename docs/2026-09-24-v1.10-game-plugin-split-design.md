## 目录和加载约束

`plugins/CaorenCup/` 是不含 DLL 的分类目录。每个实际插件放在与其 DLL 同名的目录里。CounterStrikeSharp 1.0.374 会递归寻找 `目录名/目录名.dll`，找到后不继续扫描其子目录。因此单插件目录下不再嵌套其他运行插件。将来部署时如服务器的 `plugins/CaorenCup/CaorenCup.dll` 仍存在，扫描会在该层停止，全部子插件都不会自动发现；必须先只读核对服务器实况，备份旧 DLL 与配置，再单独取得覆盖/移除许可。

## 接口、配置和行为

1. 先做最小的真实插件加载与 Capability 通信验证。Core 提供版本化共享契约；消费者只依赖契约，不直接引用 Core 的插件实现。调用前检查服务是否可用，并处理 Core 热重载与加载顺序。共享接口只暴露拆分所需能力，避免把整个旧插件对象传出去。
2. 保留旧 `CaorenCup.json` 作为兼容输入和 `module-configs/*.json` 的现有覆盖顺序；现有数据和 `presets.grass.json` 不得因目录变化丢失。配置新位置与迁移须先以本地夹具验证，再用于生产。无配置文件时仍采用原默认值。
3. 保留现有命令名、别名、权限判断、玩家与控制台差别和聊天入口。特别检查 Alias 重载旧配置路径、SimpleHp 的 .hp、Preset 的预设文件与命令分级、InGameMenu 调用其他插件命令。
4. `reset_plu` 仍重置托管 CVar、关闭原本会关闭的功能、关闭 HpCap 并保存；SkillPoints 和 RadarColor 保留当前例外。RUSH 的当前 SetEnabled 是空操作。独立插件必须显式参与统一重置；卸载插件不能代替原重置语义。
5. 草人杯独立模式入口先执行上述统一重置，再执行 MatchZy 相关指令，最后执行草人杯自定义设置。Competitive 的管理员入口为 `/competitive`：`css_reset_plu` → `css_exitprac` → `exec grass/default`。RUSH 保持 `css_rush`、`css_sleep`、`rush_001` 和换图后重新应用官方 `gamemode_rush.cfg` 的行为。直接使用 MatchZy `/prac` 是用户确认的例外，不执行草人杯重置；Wingman 暂缓。
