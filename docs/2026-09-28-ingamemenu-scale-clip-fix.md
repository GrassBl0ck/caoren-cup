# 数值控件截断与菜单点击音量

## 当前证据

用户实测：右侧 +5 仍截断；菜单点击声 0% 关闭，其他非零值听感相同。前次修改没有通过这两项验收。

本地原生 SettingsBackground 使用 946px 宽和左右各 64px padding，而内部业务面板使用 100% 宽；这是此次裁剪排查中确认存在的混合布局，但尚未经过实机证明为唯一根因。

服务器只读查询 `UIPanorama.submenu_select`：事件自身 volume=0.3、pitch=1.2，触发 `inventory_inspect_close` 和 `submenu_leveloptions_slidein` 两个子事件，主素材为 `sounds/ui/panorama/submenu_select_01.vsnd`。原 `EmitSound` 非零参数对该事件没有达到用户期待的缩放效果；不得把 0% 能静音当作完整的比例音量验证。

用户确认改用同一个游戏自带主点击素材，优先保证按百分比缩放，接受较简单的听感。

## 修改

- 内容容器明确覆盖原生 padding 为 0，宽 946，顶部原 32+42 的距离合并为 margin-top 74。
- 五个数值槽位分别位于 x=0、62、124、226、288；四个按钮各宽 56，当前值宽 96，+5 右端 344，外层宽 360，留 16px 余量。所有位置相对自己的无流布局面板。
- 菜单点击改用 `playvol` 播放已确认存在于游戏 VPK 的主素材 `.vsnd_c`，基础增益 0.3，再乘个人比例。请求比例分别为 1%→0.003、25%→0.075、50%→0.15、100%→0.3；0% 仍不发送。
- 不改变游戏全局音量；原游戏素材直接引用，不导出再改写或放入自有包。
- 用户已确认当前 `start 12` 试听音听感合适；此结果保留，但不自动推广为全部素材的正式默认值。

## 验证

67 项相关测试通过，包括四个非零点击音量请求的比例。PlaySound 开启探针的 Release 构建通过，0 警告、0 错误；13 个资源编译和 VPK 校验通过。

这些结果证明本地请求、构建和资源准备，不证明客户端已按比例播放，也不证明裁剪已消失。修改前备份及实际差异保存于本轮工作树。

经用户确认，PlaySound 和两端 VPK 已备份更新，服务器正常重启，19 个插件加载成功，目标文件哈希核对通过。菜单 DLL、个人数据和原音频清单保留，本机 VPK 与服务器一致，gameinfo 未改变。用户本机已安装，可直接重开 CS2。匹配玩家包为 `release-build/ingamemenu-audio/scale-clip-20260928/tester-kit-scale-clip-deployed-20260928.zip`。
