## 二、如何测试当前菜单

本机客户端资源已更新；服务器插件和资源已按下文校验结果更新。

1. 启动 CS2，连接测试服务器。
2. root 管理员在聊天输入 `/crcmenu_admin`，进入“指令帮助”。
3. 检查字母顺序、分页、长参数说明、返回上一级及退出。
4. 输入 `/crcmenu` 查看普通玩家菜单；管理员也允许进入。
5. 在“个人设置”把透明度改成 0%、50%、100%，确认文字未跟着变透明、其他玩家的界面不受影响。
6. 关闭菜单、重新打开、重连后检查个人设置是否保留。
7. “悬浮查看背景示例”按钮上移入鼠标，检查预设图片是否显示；退出按钮检查文字提示是否被边缘裁掉。
8. 至少两个不同 SteamID 验证：普通玩家不能打开管理员菜单；root 管理员不能作为普通投票者投票。
9. 管理员发起投票：普通玩家分别设置音量 0% 和 100%，比较提示音；按钮点击音暂不随此音量变化。
10. 从玩家菜单进入投票页，点击“返回”应回玩家菜单；直接 `/crcvote` 打开的投票页返回游戏。

普通玩家没有安装 VPK 时仍可使用聊天投票 `/crcvote A`，但无法保证菜单显示。**本次没有实现自动下载/Workshop/MultiAddonManager 分发。**

## 三、规则变化及菜单分工

- 按你的新要求废弃“透明度仅供开发测试”，正式构建包含个人设置。
- 两个菜单共同提供个人设置，视为你本次明确提出的共同入口。数据只有一份，按操作者 SteamID 保存。
- 玩家菜单只介绍普通玩家能操作的内容。管理员控制 `/eco`、`/sp` 的功能，与玩家竞猜/购买的参数说明分别编写。
- 公共查询和公共返回/退出帮助放在玩家菜单，避免两套帮助重复介绍同一操作。管理员可通过 `/crcmenu` 查看这些内容。
- 管理员菜单继续检查 `@css/root`：打开和点击均校验。指令帮助为只读，不会执行展示出来的命令。
- 搜索按已确认决定取消；没有实现模糊搜索或“停输 0.5 秒刷新”。
- 返回/退出仍使用按钮及 `css_crcmenu_back`、`css_crcmenu_exit`；没有自动绑定 Esc。

指令帮助是随 DLL 内嵌的静态目录。新增命令、插件改参数或 Alias 配置改变后，需要更新目录；没有伪装成运行时自动枚举完整参数文档。

## 四、卧底指认逻辑

参考的原实现：

- `web-command-center/src/socket-handlers.ts` 的 `ACCUSE` 处理。
- `web-command-center/public/js/lobby-app.js` 的己方/敌方候选及进度墙。

本次移植：

- 要求对应比赛会话、卧底已启用、处于赛后指认阶段。
- 排除 Admin/Spectator、自选和队伍缺失；己方只能选同队，敌方只能选另一队。
- 己方和敌方各一个锁定提交，提交后不能改；重复提交不会覆盖。
- 在线合资格玩家都交齐两份选择后输出完成状态。
- 全员进度仅包含姓名和是否提交，不公开别人选择的目标。
- 候选按 8 人分页，数据视图提供自己的锁定选择。
- 支持恢复网页服务端已经验证的选择，供刷新/重连时保持锁定。
- 留下 `IAccusationTransport`：加载经过鉴权的操作者网页 ID 和会话状态、提交目标网页 ID。

没有新增评分规则，没有改网页的真实比赛状态、身份绑定和结算，也没有把 SteamID 或 T/CT 自行等同于网页 playerId/rosterTeam。

### 接完整链条前需要你决定/确认

1. **身份绑定和服务端通信**：菜单如何取到可信的 SteamID → 网页玩家 ID 映射；使用现有桥接扩展还是独立服务端接口。这涉及长期边界，本次保留接口，没有选择新协议。
2. **比赛主状态**：网页继续作为权威来源时，指认结束推进阶段、断线、重连、超时和结算由网页处理；菜单只是操作入口。需确认最终方向。
3. **没有己方或敌方可选对象**：沿用网页现状会无法交齐两票，需要确认跳过、弃权或其他规则。
4. **全部玩家离线**：网页式 `All` 判断在在线名单为空时为真；独立模型保持现有语义，但没有接到自动推进。正式接入前需要确认。
5. **进度墙与结果页**：指认页是否显示全员提交进度，结束后是否继续展示原网页记分板；目前没有搬迁计分板。

## 六、其他遗漏/风险，按优先级

### 优先处理

- **Core 现有权限差异**：聊天 `/reset_plu` 检查 root，但当前 `css_reset_plu` 控制台入口缺同等检查。本次帮助已提示，未越过范围修改 Core。建议单独修复并测非管理员入口。
- **全组件音量**：需要草人杯组件共同遵守的个人音量协议。当前仅菜单插件消费设置；不能靠修改玩家全局 CS2 `volume` 来冒充完成，否则会影响正常游戏声音。
- **自动资源分发**：现在只是本机与服务器匹配的手动 VPK 测试版本。正式运营前仍需要选定分发方式、版本更新和下载失败处理。

### 可后补

- Snake 本地缺对应源码，不能确认所有参数意义，本次未凭名称猜测帮助。
- 普通玩家的部分命令要求对应模式启用；帮助文字会说明条件，但没有根据每项实时模式状态隐藏条目。
- 原生 CSS 按钮音由客户端处理，本次没有验证可单独调音量；“菜单提示音量”不是原生按钮音量。
- 真正背景模糊尚未证明可由此 HUD 层实现。没有用模糊文字/按钮或假背景图代替游戏画面模糊。
- GUI 捕获、悬浮层、分辨率适配、多人角色变化和声音需要人工进服验收。

关于 VAC/其他反作弊：本次没有注入进程、修改客户端 DLL 或启动游戏，界面沿用自定义 HUD 资源方案。**不能保证每种反作弊或每个服务器规则允许相同资源挂载。** 当前服务器本来就以 `-insecure` 启动，本次保留，因而本次加载检查不能证明 VAC 兼容性。
