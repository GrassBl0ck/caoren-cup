## 一、本次完成的改动

### 1. N 范围标注（取代"带N任务体系"红字）

- N 类任务格子标题旁自动显示取值范围，如 `【5N】 N={1,2,3}`，上限取自编辑面板"最大 N 值"（`cell.nMax`）：
  - 最大 N 值 ≤ 6：完整列举（`N={1,2,3}`）
  - > 6：缩写为 `N={1,2,3,...,10}`
  - 非 N 任务或旧模板缺 `nMax` 时不显示，不编造上限
- 实现于 `lobby-app.js` 的 `formatNRangeLabel()`，同时应用于**编辑器预览九宫格**和**玩家任务卡片**（`renderTaskCell`）两处渲染。
- 删除了编辑器预览底部红色 `[带N任务体系]` 标注（全库无残留）。
- 此后配置任务**不再需要**在描述里手写"N=1/2/3"；旧模板里已手写的文字不会自动清除，需要逐步人工清理。

### 2. 提示蓝框语义反转

原语义：查看提示**后**加蓝色包边；左上角还有"有提示/提示已查看"胶囊徽章（与 N 范围标注重叠）。

新语义：

- 格子配置了提示且**尚未查看** → 格子蓝色包边（提示可用）
- 查看提示后 → 蓝框消失，提示正文照旧显示在格子里
- 替换任务换来的新格子如带提示，蓝框自动出现
- "有提示/提示已查看"徽章已删除（重叠问题随之解决）

实现要点：

- 前端蓝框不再读 `borderHistory` 的 `blue`，改为按 `hint && !isHintUsed` 推导（`renderTaskCell`）
- 服务端 `REQUEST_HINT` 不再写入 `blue`，并顺手清理旧数据遗留标记（`socket-handlers.ts:1012`）
- 卧底规则弹窗"蓝色包边"文案已更新为新含义
- 编辑器预览：配了提示的格子直接显示蓝框

### 3. 右上角操作记录（◷ 图标 + 悬停弹窗）

- ◷ 图标从"有记录才显示"改为**常驻显示**；无记录时悬停显示"暂无操作记录"
- 弹窗放大：宽度 300→430px（小屏 88vw 兜底）、最大高 460px 可滚动、字号加大
- 条目文案改为"**第 X 回合，做出了「XX」操作**"，下方保留变更摘要（如"进行中 → 未完成；N 0 -> 1"）与操作时刻
- 显示条数 6 → 10

### 4. 左上角当前状态（ⓘ 图标 + 悬停弹窗）

经历两版迭代：第一版是彩色胶囊文字角标（含"已被替换+已完成"等组合文案），按用户要求改为与右上角一致的**图标 + 悬停**形式：

- ⓘ 圆形图标（与 ◷ 同规格 26px），颜色随主状态：绿=已完成、黄=已部分完成、红=未完成、灰=已放弃（含暗色主题）
- 悬停弹窗"格子 X 当前状态"逐条列出：主状态+说明（如"已部分完成（N=1/3）—— 当前 N = 1，最大 3"）、"已被替换"、"已获取提示"（各自带一句说明）；完成回合也在其中
- 弹窗从左边缘展开，样式与操作记录弹窗同源

### 5. 角标遮挡修复

根因：`.task-cell` 本身是滚动容器（`overflow-y: auto`），内容长时绝对定位的角标被滚动内容裁剪/遮挡。

修复：格子改为 `overflow: visible` 不再整体滚动，仅任务描述区（`.task-desc`）内部滚动（加 `min-height: 0`）。两个角标从此固定可见。

### 6. 开发玩家登录旁路（本地测试专用）

背景：本地无 CS2 服务器时，任务操作（标记/提示/替换/N±）只能由玩家本人的连接触发，管理员不能代打；而正式玩家账号必须经 Steam 登录创建，本地走不通。

改动：

- `game-constants.ts` 新增 `DEV_PLAYER_LOGIN_ENABLED`（仅当环境变量 `CAOREN_DEV_PLAYER_LOGIN=1` 时为真）
- 开关开启时，LOGIN 事件支持 `P:` 前缀登录名 + 管理员密码 → 以普通 **Player** 身份进入房间（仍需管理员密码，不是开放入口）
- **生产环境不设置该变量即为死代码，不受影响**
- 用法：`CAOREN_DEV_PLAYER_LOGIN=1 npm run dev` 启动后，无痕窗口用登录名 `P:测试玩家` + 管理员密码登录

## 四、本地测试方法（无 CS2 服务器）

1. 启动：`cd web-command-center && CAOREN_DEV_PLAYER_LOGIN=1 npm run dev`（默认 http://localhost:3000，管理员密码取 `ADMIN_PASSWORD` 环境变量，缺省 `CHANGE_ME_ADMIN_PASSWORD`）
2. 播种测试会话：使用仓库外临时脚本 `D:\OpenSourcework\tmp-dev-driver\`（`seed-all.js` 一键完成：加网页测试 BOT → 推进到赛前准备 → 注入演示模板 → 每队 1 名卧底发放身份 → 以测试玩家身份做两个示例操作）。注意：
   - `SET_ROLES_COUNT` 只在大厅阶段可用；卧底数量是**每队**数量（`roleCountMismatch` 按队校验）
   - Roll 阶段推进后服务端有 3 秒定时器才切阶段，脚本需等待
   - 会话快照持久化在 `runtime/live-session-snapshot.json`，重置状态 = 停服后删除该文件
3. 测试玩家：无痕窗口登录名 `P:测试玩家` + 管理员密码
4. 系统自带"网页测试 BOT"（`ADD_TEST_BOTS`，仅网页流程不进服务器），界面按钮在单挑模式控制面板里，但服务端任何模式都可调

## 五、本轮确认的设计决策

- **不做"剩余 X:XX"时间**：网页无法得知回合开始时刻与回合时长（round_start 不带时间、比赛选项无回合时长），用户决定操作记录只用回合数
- **无刀局**：开赛流程无 knife round，`/start` 后第一个回合即手枪局，现有"首个收到回合=第 1 回合"的偏移机制（`normalizePluginRound` 的 `roundBaseOffset`）+ 比分兜底对正式环境是准确的；本地测试显示"第 0 回合"属正常（无插件连接）
- 任务共 8 种操作：标记完成、撤销状态、放弃任务（每人 1 次）、查看提示（每格 1 次）、替换任务（每人 1 次）、N+1、N-1、设置 N 值
- "已被替换/已获取提示"与主状态可任意组合，状态弹窗天然覆盖（含"替换后再放弃"）
