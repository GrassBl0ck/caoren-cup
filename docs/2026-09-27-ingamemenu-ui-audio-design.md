## 2. 菜单导航和返回

### 2.1 管理员菜单

入口：

```text
/crcmenu_admin
```

权限：

```text
@css/root
```

固定顶栏：

```text
快捷指令　　指令帮助　　个人设置
```

要求：

- 三个栏目都可以直接点击切换。
- 栏目名称固定，不随当前页面变成其他文字。
- 当前栏目通过选中样式标识。
- 个人设置从首页移到顶栏。
- 首页中重复的“查看指令”“打开设置”入口移除。

### 2.2 玩家菜单

入口：

```text
/crcmenu
```

固定顶栏：

```text
玩家指令　　投票　　个人设置　　打开指引
```

要求：

- 不另设入口首页。
- 打开后默认进入玩家指令列表。
- 管理员也可以打开玩家菜单。
- 玩家菜单只提供普通玩家可操作的内容。

### 2.3 返回规则

两个菜单右下角都只保留一个：

```text
返回
```

返回路径：

| 当前页面 | 点击返回 |
| --- | --- |
| 管理员指令详情 | 管理员指令列表 |
| 管理员指令列表、个人设置等一级栏目 | 快捷指令首页 |
| 管理员快捷指令首页 | 游戏 |
| 玩家指令详情 | 玩家指令列表 |
| 玩家投票、个人设置、打开指引 | 玩家指令列表 |
| 玩家指令列表 | 游戏 |

现有投票管理中的确认页、预览页继续按层级返回。

直接通过 `/crcvote` 打开的独立投票页，沿用直接返回游戏的行为；从玩家菜单进入的投票页，返回玩家指令列表。

### 2.4 退出命令

删除界面上的直接退出按钮，保留：

```text
css_crcmenu_back
css_crcmenu_exit
```

- `back`：按上述层级返回。
- `exit`：直接关闭自己的菜单，释放输入捕获。
- 不自动修改玩家键位。
- 更新打开指引，避免继续说明已删除的退出按钮。

### 2.5 栏目切换状态

从指令详情切到其他栏目，再回指令帮助：

- 返回指令列表。
- 保留原列表页码。
- 不自动恢复详情页。

页码记忆至少覆盖本次菜单会话内的栏目切换，不新增长期保存导航位置的需求。

## 3. 悬浮提示

### 3.1 布局规则

悬浮说明必须独立于按钮正常布局：

- 显示提示时，按钮位置和尺寸不变。
- 按钮背景不会因提示内容撑大。
- 相邻控件不会移动。
- 提示层不拦截鼠标点击。
- 鼠标离开后收起提示。

文字和图片提示使用同一套通用组件。

提示位置根据按钮所在区域安排，保证屏幕边缘附近的提示能够完整阅读，避免遮住触发按钮。

### 3.2 展示范围

- 正式设置页移除“悬浮查看背景示例”演示入口。
- 保留通用组件和开发验收用例。
- 正式业务按钮的提示内容、图片清单以后再决定。
- 不因实现组件而给所有按钮添加提示。

### 3.3 验收

分别测试：

- 短文字。
- 多行文字。
- 图片。
- 文字与图片组合。
- 屏幕边缘位置。
- 鼠标反复移入、移出。

对比悬浮前后的按钮边界，必须一致。

## 4. 数值调节控件

替换当前透明度、音量滑轨：

```text
[−5] [−1]  50%  [+1] [+5]
```

符号、边框、选中与悬停表现由开发者按 CS2 风格处理。

### 4.1 操作规则

- 四个按钮分别调整 −5、−1、+1、+5。
- 中间数字只显示当前值。
- 首版不增加数字输入框和按住连续调整。
- 点击后即时生效，并更新显示。
- 支持真正的 1% 精度。

### 4.2 范围和保存

| 设置 | 范围 | 默认值 |
| --- | --- | --- |
| 背景透明度 | 0～100% | 10% |
| 草人杯总音量 | 0～100% | 100% |

- 到达边界后禁止继续向外调整。
- 不循环跳转。
- 保存、重开、重连后不得取整回 5 的倍数。
- 透明度只影响背景，文字和按钮不随之变透明。
- 个人设置只影响操作者。

当前不可用的背景模糊行从设置页移除。

## 5. 指令帮助

### 5.1 列表

保持现有列表形式：

- 按命令名称排序。
- 命令名称与摘要分列。
- 保留分页。
- 管理员和玩家帮助分别描述各自可使用的操作。

同名命令存在不同权限参数时，例如 `/eco`、`/sp`，分别介绍管理操作和普通玩家操作。

### 5.2 详情结构

```text
命令名称
简短说明
模块与权限

用法
参数意义
示例及具体效果
补充说明
```

“用法”“参数意义”“示例”等小标题加粗，段落间距略增。保留当前整体字号和页面风格，实机检查后再微调。

分页应避免标题独自落在页尾、正文全部进入下一页。

### 5.3 参数颜色

按参数顺序固定颜色：

- 同一命令中，不同参数使用不同颜色。
- 同一参数在用法、参数解释、示例和效果解释中保持同色。
- 命令名称及普通连接文字使用基础文字色。
- 颜色不是唯一识别方式，仍保留参数名称和文字说明。
- 调色板覆盖实际最大参数数量，不能简单循环复用颜色。

### 5.4 示例要求

每个示例都包含：

1. 可以执行的完整命令。
2. 这组具体参数产生的效果。
3. 参数值与效果说明之间的颜色对应。

例如：

```text
/dj t 2 300 true
```

解释应表达：

> 对 T 方启用共 2 段跳（最多 1 次额外空中跳跃），上推速度为 300，并允许在上升阶段再次跳跃。

`t` 与“T 方”同色，`2` 与“共 2 段跳（最多 1 次额外空中跳跃）”同色，其余参数同理。

示例必须依据真实代码核对，尤其是：

- 百分比与倍率。
- 时间单位。
- 开关值。
- 省略参数行为。
- `-` 是否表示保持当前值。
- 负数是否具有特殊意义。

### 5.5 数据结构

将现有整段文本拆成结构化内容，包括参数、示例参数值和解释片段。渲染时采用可控制颜色的文本片段。

查看帮助始终为只读，不执行示例命令。

## 8. 统一个人协议与音频系统

### 8.1 插件分工

| 组件 | 职责 |
| --- | --- |
| `CaorenCupCore` | 保存和提供个人偏好 |
| `CaorenCupContracts` | 定义个人偏好与音频服务协议 |
| 现有 `CaorenCupQOL_PlaySound.dll` | 扩充为统一音频服务，保留 `/ps` |
| `CaorenCupInGameMenu.dll` | 提供个人设置界面 |

沿用现有插件和目录，不新增音频 DLL。

### 8.2 个人偏好

首版统一保存：

- 菜单背景透明度。
- 草人杯总音量。
- 鼠标效果设置：仅在验证通过后启用。

协议预留音频分类，首版界面只提供总音量。

原菜单偏好数据需要保留并迁移：

- 迁移前备份。
- 不删除旧文件。
- 已有不同值发生冲突时，报告并停止覆盖。
- 不把迁移失败处理成清空全部偏好。
- 偏好读写失败不能导致整个菜单无法加载。

### 8.3 音量控制范围

控制草人杯主动增加的声音，包括：

- 投票提示。
- 网页桥接提醒。
- `/ps` 音频广播。
- 插件追加的痛叫和伤害声。
- 草人杯菜单交互声音的统一控制目标。

不改变 CS2 正常枪声、脚步等原生游戏声音。

总音量为 0 时，上述草人杯声音全部静音，包括通知，不设置强制绕过个人音量的声音。

个人静音不会暂停全服音乐，也不会影响其他玩家。

### 8.4 播放入口盘点

当前已找到：

| 入口 | 当前用途 |
| --- | --- |
| InGameMenu | 投票开始提示 |
| PlaySound | 全服音频广播 |
| 网页桥接 | 通知铃声 |
| Bleed、Smoke | 痛叫 |
| BladeAura、Magic | 追加伤害声音 |
| 菜单原生样式 | 悬停及点击声音 |

实施前继续核查当前源码中的直接和间接播放入口，并形成接入清单。

原生样式自动播放的声音不能直接认定已经接入个人音量。若无法控制，需要明确报告该项未完成。

### 8.5 代码调用方式

玩法组件通过稳定的“音频事件 ID”请求播放，例如：

```text
vote.started
bridge.notice
gameplay.bleed.pain
broadcast.example
music.example
```

调用方不自行拼素材路径，不各自维护个人音量。

音频服务负责：

- 查找事件和素材。
- 接收对象。
- 个人音量。
- 播放状态。
- 通道替换。
- 暂停、恢复、停止及循环。
- 资源缺失和服务不可用的错误反馈。

保留原玩法声音的位置、方向和接收范围；空间声音不能为了统一音量全部变成无方向的界面声音。

## 9. 长音频控制

### 9.1 通道

分为：

| 通道 | 行为 |
| --- | --- |
| 短音效、提示 | 可以与长音频同时播放 |
| 音乐 | 新音乐替换旧音乐 |
| 广播 | 新广播替换旧广播 |

音乐和广播可以同时播放。

首版不加入自动降低背景音乐音量的效果。

### 9.2 管理权限

首版由管理员控制音乐与广播：

- 播放。
- 暂停。
- 恢复。
- 停止。
- 循环开关。

普通玩家只调整自己的音量，不增加个人暂停按钮。

管理操作检查 root，并说明操作影响范围。保留 `/ps` 已有使用方式，新控制命令需避免与现有别名冲突，并补充到管理员指令帮助。

### 9.3 状态语义

- 暂停：冻结当前播放进度。
- 恢复：从暂停位置继续。
- 停止：结束该音频，之后重新播放从头开始。
- 循环：首版支持整段循环。
- 2026-09-28 补充确认：关闭循环后完成当前一轮再停止；暂停期间不消耗剩余播放时间。
- 替换：停止同通道旧音频，启动新音频。

不能把停止后从头重播当作暂停。

### 9.4 后加入和重连

尽可能从当前进度加入：

- 正在播放的音乐。
- 循环音频。
- 尚未结束的长广播。

不补播已经结束的音频和短提示。

2026-09-28 补充确认：正式音乐／广播不绑定启动管理员的在线状态。管理员离线后继续播放，直到自然结束或由其他管理员停止。地图结束和插件卸载的资源清理仍按宿主生命周期处理。

个人音量从 0 调高后，也应尽可能接入当前播放位置，而不是从头重复播放。

### 9.5 技术验证关卡

在开发完整控制界面前验证：

1. 指定声音停止。
2. 暂停与原进度恢复。
3. 循环及停止循环。
4. 同通道替换。
5. 按玩家音量播放。
6. 后加入玩家的当前进度接入。
7. 音乐、广播和提示同时播放。

当前 `EmitSound` 接口本身不能证明上述控制已经可用。[CounterStrikeSharp API](https://docs.cssharp.dev/api/CounterStrikeSharp.API.Core.CBaseEntity.html)

验证失败的能力列为未完成，不伪装成成功；其他不依赖该能力的工作可以继续。

停止操作必须针对草人杯管理的声音，不能停止全部游戏声音。

## 10. OGG 素材管理与构建

### 10.1 导入格式

用户统一放入 OGG 文件。

构建工具允许在内部自动转换、编译为 CS2 所需资源；用户无需手动转码，最终游戏资源不要求仍为 OGG。

验证实际音频内容和解码能力，不能只检查扩展名。

### 10.2 管理方式

建立约定的源素材目录和登记清单。

登记信息至少包括：

- 稳定事件 ID。
- 显示名称。
- 源文件。
- 分类及通道。
- 默认音量。
- 是否循环。
- 原生声音事件或自定义素材来源。

工具扫描 OGG 后生成登记草稿，保留用户已经编辑的配置，不自动覆盖。

### 10.3 更新流程

```text
用户放入 OGG
→ 扫描与校验
→ 自动转换及编译
→ 合并菜单、音频资源
→ 生成一个资源包和检查报告
→ 用户确认并手动更新工坊
→ 服务器应用对应版本
→ 客户端下载、挂载及播放验证
```

换素材不需要修改每个玩法的代码。

构建失败时保留上一份可用产物，报告失败文件和原因。

## 12. 实施顺序与验收

### 12.1 建议顺序

1. 检查现状、备份，单独完成 Core 权限修复。
2. 完成导航、返回、悬浮提示、数值控件和帮助样式。
3. 验证鼠标跟随及长音频控制能力。
4. 实现个人协议和音频服务，接入已有播放入口。
5. 完成 OGG 构建和统一资源包。
6. 指导用户发布工坊物品。
7. 验证 MultiAddonManager 分发及多人行为。

### 12.2 验收清单

**菜单**

- 顶栏固定且可直接切换。
- 返回路径符合本设计。
- 直接退出命令有效。
- 切换栏目保留列表页码。
- 悬浮提示不改变按钮边界。
- 数值可调整至 51%、52% 等值，并正确保存。
- 参数、示例和解释颜色对应。
- 标题加粗、段落间距合理。
- 不出现不可用模糊占位和正式页面演示入口。

**权限与音频**

- 普通玩家无法重置功能。
- root 和服务器控制台可重置。
- 两名玩家不同音量分别生效。
- 0% 不播放草人杯提示。
- 暂停恢复保持进度。
- 新音乐、广播只替换各自通道。
- 普通玩家不能管理全服长音频。
- 停止草人杯音频不影响正常游戏声音。
- 重连和后来加入的玩家符合接入规则。

**构建与分发**

- 用户可以只提供 OGG 完成构建流程。
- 换素材无需修改玩法代码。
- 一个资源包包含菜单和音频。
- 工坊发布、更新指引可按实际步骤执行。
- 未手动安装资源的客户端通过分发验证。

交付报告必须分别列出：已实现、已验证、未验证、技术阻塞。资源编译和单元测试不能代替游戏内界面、声音及多人验收。
