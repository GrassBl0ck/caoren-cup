# 单挑模式测试流程

这份流程用于单挑模式上线前验证，目标是把风险分成三层处理：

1. 本地编译检查：确认代码和插件能构建。
2. 网页大厅流程：确认临时管理员、投票、审批、旁观者规则正常。
3. 真实 CS2 实战：确认服务器命令、锁边、枪械和结算正常。

涉及服务器覆盖、重启、打开浏览器或客户端实测前，需要先征得确认。

## 0. 本地必测

推荐直接运行：

```powershell
cd D:\OpenSourcework\caoren-cup-open-source
.\scripts\test-duel-mode-local.ps1
```

如果本次也改了 `game-plugin/`，运行：

```powershell
.\scripts\test-duel-mode-local.ps1 -IncludeGamePlugin
```

脚本会执行：

```powershell
cd web-command-center
npm run typecheck
npm run test:duel-runtime
node --check public\js\lobby-app.js

cd CaorenCupPlugin.Tests
dotnet test

cd CaorenCupPlugin
dotnet build -c Release
```

如果包含娱乐插件本体，还会执行：

```powershell
cd D:\OpenSourcework\caoren-cup-open-source\game-plugin
dotnet build
```

通过后再打测试包，不使用旧的 `release-output` 包。

## 1. 有其他人一起测试

建议至少准备 4 个网页身份：

- 管理员
- 玩家 A
- 玩家 B
- 玩家 C

### 1.1 网页大厅流程

逐项确认：

- [ ] 管理员不在大厅时，玩家 A 发起临时管理员投票，玩家 B 同意，全票通过后玩家 A 成为临时管理员。
- [ ] 投票期间玩家 C 加入，投票立刻终止。
- [ ] 投票 30 秒无人全票通过，投票失败。
- [ ] 管理员在大厅时，玩家 A 只能提交申请，管理员同意后玩家 A 成为临时管理员。
- [ ] 管理员在大厅且已有临时管理员时，管理员不能直接操作单挑设置，只能收回临时管理员。
- [ ] 管理员收回临时管理员后，玩家 A 权限消失，管理员重新承担职责。
- [ ] 有临时管理员后，新加入玩家只能是旁观者，本局不能参赛。
- [ ] 临时管理员可以设置地图、A/B 队、回合分配。
- [ ] 回合总数小于 30 时，被拒绝或回退到合法值。
- [ ] 默认回合显示为手枪 8、步枪 16、狙击 12。

### 1.2 真实 CS2 实战

至少 2 名真实玩家进服，最好 3 名：A、B、旁观者。

逐项确认：

- [ ] 开局后服务器执行单挑配置：地图正确，`mp_maxrounds` 等于 X+Y+Z+1（额外 1 回合用于插件主动清理），不开启半场换边。
- [ ] 网页分到 A/B 的玩家，在游戏内确实进入相对两边，不出现网页不同边但游戏同队。
- [ ] 第 1 回合默认：USP-S，无主武器。
- [ ] 手枪阶段 `/guns` 显示手枪列表，输入 `/deagle` 后下回合生效。
- [ ] 步枪阶段默认：AK47 + USP-S。
- [ ] 步枪阶段输入 `/awp` 后，对方所有参赛玩家必须 `/agree_awp`，同意后下回合才给 AWP。
- [ ] 狙击阶段默认：AWP，无副武器。
- [ ] 狙击阶段 `/guns` 只显示 `/ssg | /awp`。
- [ ] 分数未到总回合时不能提前结算。
- [ ] 打满 X+Y+Z 回合后结束。
- [ ] 同分显示平局。
- [ ] 游戏结束但网页未结束时，临时管理员点结束游戏，能进入赛后页并开下一局。
- [ ] 中途强制终止时，临时管理员输入 `TERMINATE`。
- [ ] 如果管理员在线，强制终止需要管理员同意。
- [ ] 强制终止通过后不进赛后页，效果等同强制清局。

#### 武器与结束流程回归

- [ ] 地图放置枪械不能进入参赛者库存。
- [ ] 主武器或副武器按 `drop` 不会落地；投掷物仍可正常使用和切换。
- [ ] 参赛者死亡后没有枪械掉落供对方拾取。
- [ ] 手枪阶段连续 5 回合默认拿出手枪，不偶发持刀。
- [ ] 步枪阶段连续 5 回合默认拿出主武器，不偶发持刀。
- [ ] 狙击阶段连续 5 回合默认拿出狙击枪，不偶发持刀。
- [ ] 网页单挑最终回合保留比分和赛后统计，且不出现 CS2 官方地图投票。
- [ ] 游戏内独立单挑最终回合不出现在网页，且不出现 CS2 官方地图投票。
- [ ] 结束后用服务器控制台确认 `mp_maxrounds`、`mp_weapons_allow_map_placed`、`mp_death_drop_gun` 已恢复。

### 1.3 开玩前最终确认

- [ ] `git status --short --ignored` 中没有准备提交的备份、`bin/`、`obj/`、zip、日志。
- [ ] 测试包内容不包含 `node_modules/`、备份、日志、`.env`、`caoren_config.json`。
- [ ] 服务器部署后网页能打开。
- [ ] 桥接插件已加载。
- [ ] CS2 服务器能收到网页命令。

## 2. 只有一个人测试

### 2.1 能完整测的部分

用多个浏览器身份模拟多人网页：

- 普通窗口登录管理员。
- 无痕窗口登录玩家 A。
- Edge、Chrome 或手机浏览器登录玩家 B。
- 再开一个窗口登录玩家 C。

可以完整确认：

- [ ] 临时管理员投票、申请、审批、收回。
- [ ] 投票 30 秒超时。
- [ ] 新玩家加入取消投票。
- [ ] 有临时管理员后新玩家变旁观者。
- [ ] 地图、回合分配、总回合 >= 30 校验。
- [ ] 管理员和临时管理员权限互斥。
- [ ] 终止游戏的网页审批流程。

### 2.2 只能做烟雾测试的部分

一个 Steam 账号不能真实模拟两个对手，所以游戏内只能确认：

- [ ] 插件能加载。
- [ ] 单挑模式配置命令能下发。
- [ ] 地图能切换。
- [ ] `/guns` 能显示。
- [ ] 当前阶段默认武器大体正确。
- [ ] `/usp`、`/ak`、`/ssg`、`/awp` 等命令不会报错。
- [ ] 结束或 `TERMINATE` 不会卡死网页流程。

不能完全确认：

- 对方所有玩家 `/agree_awp` 的多人同意逻辑。
- 两边真实玩家锁边是否 100% 正确。
- 多人加入后全程旁观是否在真实 CS2 内完全一致。

这三项必须等至少另一个人上线做一次短测。

### 2.3 单人快速安全测试顺序

1. 运行 `.\scripts\test-duel-mode-local.ps1`。
2. 网页开 3-4 个身份，跑完临时管理员流程。
3. 部署到测试服或低峰期正式服。
4. 自己进 CS2，确认插件、地图、枪械命令、结束流程。
5. 记录需要多人复测的点：AWP 同意、真实两边锁边、多人加入旁观。
6. 找到第二个人后，只补测这些点和一次打满回合测试。

## 3. 最小通过标准

正式开玩前必须满足：

- [ ] 本地编译检查全过。
- [ ] 网页端临时管理员流程全过。
- [ ] 真实服务器能切地图、锁总回合、发默认枪。
- [ ] 新加入玩家不会误进参赛队。
- [ ] 强制终止不会卡住下一局。
- [ ] 至少一次双人实测通过：两边锁边正确，AWP 需要对方同意。

如果只有一个人测，最多只能算“可部署候选”，不要直接当成“多人实战已验证”。

## 4. 游戏内独立单挑真人验收（GameManaged）

本节只适用于游戏内使用 `/duel` 发起的独立单挑。它由游戏插件接管，**不应在网页大厅、网页对局列表或网页赛后页显示为一场网页比赛**；网页心跳仍可正常工作。

至少准备两名真人玩家（A、B）和一名观察者（C）。所有“通过”项都应记录测试时间、地图、参与者和异常现象。以下项目必须在真实 CS2 服务器中完成，不能用本地编译或网页多身份模拟代替。

### 4.1 指令、配置和开局

- [ ] 输入 `/duel help`，确认明确给出推荐顺序：先切换地图，等待玩家重连并选择 T/CT，再配置回合数、时间和道具，最后 `/duel start`；同时列出 `status`、`rounds`、`time`、`utility`、`reset`、`start`、`start confirm`、`pause`、`resume`、`stop`、`stop confirm`、`maps`、`map` 的用途，并说明 `/duel start confirm` 仅用于有意替换现有网页管理状态。
- [ ] 分别在闲置、进行中、暂停和网页管理状态输入 `/duel status`；确认状态、已完成回合、T/CT 比分、完整配置和（暂停时）暂停原因都与实际一致；游戏内管理状态还必须显示 T/CT 参赛人数与姓名、当前阶段和剩余回合数。
- [ ] 闲置时输入 `/duel rounds 0 18 12`（合法，总和 30），确认手枪阶段 0 回合被保存并在开局后跳过；再分别输入 `/duel rounds -1 19 12`、`/duel rounds 100 0 0`、`/duel rounds 8 x 22`、`/duel rounds 8 16`、`/duel rounds 8 16 5`，确认负数、超过 99、非数字、缺少参数和总和小于 30 都被拒绝，原配置不变。
- [ ] 闲置时输入 `/duel time 1.25`（合法）后确认配置更新；再输入 `/duel time 0.2`、`/duel time 6`、`/duel time abc` 和 `/duel time`，确认范围外、非数字和缺少参数被拒绝，原配置不变。
- [ ] 闲置时输入 `/duel utility random2`（合法）后确认配置更新；再输入 `/duel utility banana` 和 `/duel utility`，确认未知值和缺少参数被拒绝，原配置不变。
- [ ] 在游戏内单挑已经开始（GameManaged）或网页管理状态（WebManaged）时，重复输入 `/duel rounds 8 16 12`、`/duel time 1`、`/duel utility none` 或 `/duel reset`；确认都被拒绝，既有状态和配置不改变。
- [ ] 闲置时输入 `/duel reset`，确认恢复为手枪 8、步枪 16、狙击 12、每回合 1 分钟、道具 `none`；不要把 reset 预期写成“清理网页大厅”。
- [ ] 闲置且当前 T、CT 都至少有一名真人时输入 `/duel start`，确认按当前 T/CT 真人开赛；已经有 GameManaged 单挑时再次输入 `/duel start`，确认被拒绝。
- [ ] 网页存在未清理的旧对局状态时，先输入 `/duel start`，确认只提示使用 `/duel start confirm` 接管；再输入 `/duel start confirm`，确认独立单挑可接管，且没有向网页创建、更新或结束比赛。
- [ ] 进行中的 GameManaged 单挑输入 `/duel pause`，确认比赛暂停；输入 `/duel resume`，确认在所有参赛者已就绪时恢复。闲置或已暂停时重复输入不适用的 pause/resume，确认被拒绝且状态不变。
- [ ] 进行中的 GameManaged 单挑输入 `/duel stop`，确认只提示使用 `/duel stop confirm`，不会终止；输入 `/duel stop confirm` 后确认强制终止且本次不计算胜负。闲置时输入两者均应拒绝。
- [ ] 输入 `/duel maps`，确认仅列出可用创意工坊地图及切图用法，不改变比赛状态；兼容指令 `/duel_maps` 应得到同样的地图列表。
- [ ] 闲置时输入 `/duel map 1`（合法）或 `/duel map aim_redline`，确认开始切换对应地图；输入 `/duel map 999`（列表外）时确认不切图并显示地图帮助；输入 `/duel map`（缺少参数）时确认不切图并提示参数格式错误。兼容指令 `/duel_map 1` 应与 `/duel map 1` 行为一致。
- [ ] GameManaged 单挑进行中或暂停时输入 `/duel map 1` 或 `/duel_map 1`，确认拒绝切图且比赛状态不变。
- [ ] 确认默认配置为手枪 8、步枪 16、狙击 12；在默认 8/16/12 和合法的单阶段 0 回合配置各完成一次开局，确认总回合、阶段切换和最终结算均符合配置。

### 4.2 名单、队伍和观察者隔离

- [ ] 开局前确认当前 T、CT 真人名单与 `/duel` 配置一致；观察者不在任一参赛名单内。
- [ ] 开局后由新玩家加入服务器，确认其保持观察者身份，不能自动进入 T 或 CT 参赛队。
- [ ] 检查同一 SteamID 的参赛玩家断线后重连：确认其回到断线前的原队，观察者不会被误分配为参赛者。
- [ ] 参赛玩家断线时确认比赛自动暂停；管理员执行恢复后确认只在条件满足时继续，暂停状态正确解除。

### 4.3 结束、结算和幂等清理

- [ ] 执行 `/duel stop confirm`，确认需要明确确认才会终止，并且终止后不能继续推进回合。
- [ ] 分别完成“打满总回合后 T 胜”“打满总回合后 CT 胜”和“打满总回合同分平局”三种结算，确认胜方/平局显示正确。
- [ ] 对正常打满结算、`/duel stop confirm` 强制终止和异常结束（例如换图、插件卸载）分别检查：cvar 已恢复、队伍锁定已清除、阶段武器已清理、暂停状态已解除；重复触发清理也不报错或残留状态。

### 4.4 网页隔离回归

- [ ] 独立单挑开始、进行、暂停、恢复和结束期间，网页不展示该单挑为比赛、快照或赛后记录。
- [ ] 同时检查普通网页比赛的心跳和状态同步仍正常，确认独立单挑的遥测隔离没有影响网页管理的比赛。

完成本节不代表已经获得部署授权。服务器上传、覆盖和重启必须在获得明确授权后，按既定部署流程单独执行。
