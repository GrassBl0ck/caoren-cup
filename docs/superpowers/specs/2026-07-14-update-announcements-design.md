# 版本更新公告设计

## 目标

在草人杯指挥台新增独立的“更新公告”功能，让玩家在登录前和进入大厅后都能按版本查看与自己有关的历史变化。玩家即使连续跳过多个版本，也能从同一入口补看期间的全部更新。

更新公告由管理员在现有网页后台中新增和编辑，不从 GitHub Release 自动同步。网站内容只面向玩家，继续与面向开发者和部署者的 GitHub Release notes 分开维护。

本功能不替代现有“大厅公告”。大厅公告继续用于临时通知和当场提醒，更新公告用于长期版本历史。

## 范围边界

本次修改仅涉及 `web-command-center` 的服务器、公开页面、管理员页面、样式和测试。

以下内容不变：

- 固定成员、邀请码、管理员和游戏码登录流程；
- Identity、LobbyMembership 和比赛 Session 数据；
- 现有大厅公告的数据、接口和 Socket 事件；
- 比赛流程、娱乐插件和网页端服务器桥接插件；
- 桌面客户端壳。

更新公告使用自己的存储 schema，不升级身份库 schemaVersion。

## 模块边界

### 更新公告存储

新增独立存储模块，负责：

- 初始化公告库和历史种子；
- 校验 schema；
- 读取主文件和 previous 副本；
- 原子保存；
- 保证版本号唯一；
- 拒绝未知版本或损坏数据被静默覆盖。

默认主文件为 `runtime/update-announcements.json`，previous 文件为 `runtime/update-announcements.previous.json`。测试可通过专用环境变量指定隔离路径。

### 更新公告服务

新增独立服务模块，负责：

- 新建和编辑公告；
- 草稿、发布和隐藏状态转换；
- 首次发布时间与提醒修订号；
- 公开列表和管理员列表的投影；
- 排序与 HTML 清洗。

路由不直接操作 JSON 文件，前端也不负责业务校验。

### HTTP 与 Socket

新增独立路由和 Socket 事件。公开接口只返回已发布数据；管理员接口复用现有管理员密码。Socket 只广播公开投影，不广播草稿、隐藏内容或管理员密码。

### 玩家界面

登录前和登录后共用同一个更新公告入口、右侧抽屉、折叠列表和本地已读逻辑。玩家界面不依赖当前身份，因此未登录访问与登录后访问行为一致。

### 管理员界面

现有七个管理员导航模块保持不变。“公告”模块内部拆分为“大厅公告”和“更新公告管理”两个区域。

## 数据结构

公告库 schemaVersion 固定为 `1`：

```ts
type UpdateAnnouncementStatus = 'draft' | 'published' | 'hidden';

type UpdateAnnouncement = {
  id: string;
  version: string;
  title: string;
  sections: {
    webHtml: string;
    gamePluginHtml: string;
    bridgePluginHtml: string;
  };
  status: UpdateAnnouncementStatus;
  reminderRevision: number;
  createdAt: number;
  updatedAt: number;
  publishedAt: number | null;
};

type UpdateAnnouncementStoreData = {
  schemaVersion: 1;
  announcements: Record<string, UpdateAnnouncement>;
};
```

约束如下：

- `id` 使用 UUID，并在公告生命周期内保持不变；
- `version` 必须匹配 `^v\d+\.\d+\.\d+$`，并在草稿、已发布和隐藏公告中全局唯一；
- `title` 必填，最多 40 个 Unicode 字符；
- 每个 HTML 区域设置独立长度上限，并使用服务器端白名单清洗；
- 草稿可完全空白；发布时至少一个区域必须含有实际内容；
- 空白区域在公开投影中显示“本版本无玩家可见更新”，存储中仍保持空字符串；
- 新草稿的 `reminderRevision` 为 `0`；第一次发布时变为 `1`；
- `publishedAt` 只在第一次发布时设置，之后编辑、隐藏和重新发布均不改变；
- `updatedAt` 在每次成功修改时更新。

所有时间保存为 Unix 毫秒时间戳。玩家页面按 `Asia/Shanghai` 时区显示到秒，例如 `2026-07-14 16:25:08`。

## 状态转换

允许的主要转换为：

- 新建 -> 草稿；
- 草稿 -> 已发布；
- 已发布 -> 隐藏；
- 隐藏 -> 已发布。

管理员可编辑任意状态的标题和正文。编辑已发布公告时默认不增加提醒修订号；勾选“重新提醒玩家”后，`reminderRevision` 增加一。

公告第一次发布后仍允许修正版本号，但必须满足以下条件：

- 管理员完成二次确认；
- 新版本号格式正确且未被占用；
- `reminderRevision` 自动增加一，使所有浏览器重新收到提醒。

对曾发布后隐藏的公告修正版本号时执行相同规则。该公告再次发布后，玩家会看到新的提醒修订号。

隐藏后重新发布默认不增加提醒修订号，但管理员可以主动选择“重新提醒玩家”。不提供永久删除操作。

## 初始历史公告

仅当主文件和 previous 文件都不存在时创建新库，并预置玩家版历史公告：

- `v1.8.2`：新增成员账号登录与大厅界面优化；首次发布时间 `2026-07-12T19:25:21Z`，中国时区显示为 `2026-07-13 03:25:21`；
- `v1.8.3`：新增开赛前快速指引；首次发布时间 `2026-07-13T18:24:55Z`，中国时区显示为 `2026-07-14 02:24:55`；
- `v1.8.4`：登录入口说明更加清楚；首次发布时间 `2026-07-13T20:10:18Z`，中国时区显示为 `2026-07-14 04:10:18`。

这些时间取自对应的公开 GitHub Release `publishedAt`。种子正文采用玩家视角，并固定包含：

1. 网页端；
2. 游戏插件；
3. 桥接插件。

没有玩家可见变化的部分写“本版本无玩家可见更新”。种子不得包含私人服务器路径、部署方式、配置或管理员专用细节。

三条种子的玩家版要点固定为：

- `v1.8.2`
  - 网页端：新增“成员账号登录”，持有管理员预设密码的玩家无需邀请码和昵称即可进入大厅；保留邀请码加入方式；更新大厅布局和深浅色适配；
  - 游戏插件：本版本无玩家可见更新；
  - 桥接插件：游戏 SteamID 与成员账号一致时自动完成本场确认；未先进入网页大厅的真实玩家会收到提示；
- `v1.8.3`
  - 网页端：新增登录前和登录后都能查看的开赛前快速指引，并提供完整规则 PDF 下载；
  - 游戏插件：本版本无玩家可见更新；
  - 桥接插件：本版本无玩家可见更新；
- `v1.8.4`
  - 网页端：将玩家入口改为按“收到成员密码”或“收到本场邀请码”选择，并补充一直显示的登录方式说明；
  - 游戏插件：本版本无玩家可见更新；
  - 桥接插件：本版本无玩家可见更新。

若任一数据文件已经存在，则绝不执行种子合并或覆盖，避免部署后重复插入历史版本。

三个种子均以 `published` 状态写入，`reminderRevision` 为 `1`，`createdAt`、`updatedAt` 和 `publishedAt` 统一使用各自的公开 Release 发布时间。

## 持久化与恢复

保存顺序为：

1. 在同一目录写入 UTF-8 临时文件；
2. 若主文件存在且有效，将其复制为 previous；
3. 将临时文件原子替换为主文件；
4. 发生失败时清理临时文件，并保留内存中的上一个有效状态。

启动读取顺序为：

1. 优先读取主文件；
2. 主文件因截断、非法 JSON 或 schema 内数据校验失败而损坏时，尝试读取 previous；
3. previous 有效时恢复其数据，并在不复制损坏主文件的前提下安全重建主文件；
4. 主副本均损坏时，更新公告模块进入不可写错误状态；
5. 任一待读取文件声明未知 schemaVersion 时，视为可能由更高版本程序生成，立即进入不可写错误状态并保留原文件，不回退、降级或覆盖。

不可写错误状态不会阻止整个大厅启动，但公开接口返回明确的暂时不可用响应，管理员界面显示错误并禁用保存。系统不得用空库覆盖损坏文件，错误信息不得向浏览器泄露本地文件路径。

## 接口设计

新增以下接口：

- `GET /api/update-announcements`：公开读取全部已发布公告，按 `publishedAt` 从新到旧排序；
- `POST /api/admin/update-announcements/list`：验证管理员密码后读取全部状态；
- `POST /api/admin/update-announcements/save`：新建草稿或编辑公告内容；
- `POST /api/admin/update-announcements/status`：发布、隐藏或重新发布公告。

管理员密码只放在 POST JSON 请求体中，不放入 URL、查询参数、公开状态或 Socket 广播。

管理员保存接口根据操作校验：

- 版本号格式和唯一性；
- 标题长度；
- HTML 长度和清洗结果；
- 发布时至少一个区域非空；
- 发布后版本号变化的二次确认；
- “重新提醒玩家”只在有意义的状态下生效。

新增公开 Socket 事件 `UPDATE_ANNOUNCEMENTS`。公告发布、编辑已发布内容、隐藏、重新发布或增加提醒修订号后，服务器广播最新公开投影。管理员列表在管理操作成功后通过管理员接口重新读取，不通过 Socket 暴露非公开状态。

Socket 断开不会导致数据丢失。页面首次加载、重新连接和打开抽屉时均可通过公开接口校准最新列表。

## 玩家交互

### 入口和抽屉

- 页面公共顶部区域增加“更新公告”按钮，登录前和登录后始终存在；
- 存在未读修订号时显示红点；
- 桌面端从右侧打开抽屉；
- 手机端抽屉占满屏幕；
- 最新版本默认展开；
- 旧版本只显示版本号、标题和精确到秒的发布时间，点击后展开或收起正文；
- 每条正文始终显示“网页端 / 游戏插件 / 桥接插件”三段。

打开抽屉时先生成当前未读公告快照，并在当前页面立即清除顶部红点。该次抽屉会继续对快照中的条目显示“新”标记；关闭抽屉时才把快照中的公告修订号写入本地已读记录。抽屉打开以后才收到的新公告或新修订号不属于该快照，仍保持未读并重新显示红点。

抽屉支持关闭按钮、遮罩点击和 `Escape`。打开时焦点进入抽屉，关闭后焦点回到触发按钮；背景内容在抽屉打开时不可被键盘误操作。

### 本地已读

使用带版本后缀的 `localStorage` 键保存：

```ts
Record<announcementId, highestReadReminderRevision>
```

本地记录不包含 SteamID、昵称、密码、身份 ID 或其他玩家信息。清理浏览器数据或更换设备后，所有已发布公告重新显示为未读，属于预期行为。

如果 localStorage 不可用，页面退化为当前标签页内存记录；不得影响公告阅读或大厅登录。

## 管理员交互

“公告”模块包含两个分区：

1. 大厅公告：保留现有编辑器和行为；
2. 更新公告管理：新增版本列表和编辑表单。

版本列表显示版本号、标题、状态、首次发布时间和最后编辑时间，支持按草稿、已发布、隐藏筛选。可执行编辑、发布、隐藏和重新发布，不显示永久删除。

新建公告默认保存为草稿。表单包含：

- 版本号；
- 标题；
- 网页端富文本编辑区；
- 游戏插件富文本编辑区；
- 桥接插件富文本编辑区；
- 编辑已发布公告时的“重新提醒玩家”复选框。

三个编辑区共用简洁工具栏，支持粗体、编号、项目符号和安全链接。三段标题由界面固定提供，不依赖管理员手工输入。空段在预览和玩家端自动使用默认文案。

发布后修改版本号时显示二次确认对话框，并说明会重新提醒所有玩家。

## 视觉、主题和响应式

更新公告使用现有页面、表面、边框、正文、弱化文字、主色和状态色变量，不引入只适用于浅色的内联颜色。

- 红点只表达“存在未读更新”，不用于普通装饰；
- 草稿、已发布和隐藏使用主题兼容的状态标签；
- 桌面抽屉宽度适合阅读长内容，不覆盖整个页面；
- 360px 和 768px 下使用全屏抽屉，按钮和关闭控件保持至少 44px 可操作尺寸；
- 长版本号、标题和链接必须正确换行；
- 管理员列表在窄屏转为分组卡片或明确横向滚动，不产生正文级横向溢出。

## 错误处理

- 公开读取失败时，入口仍可操作，抽屉显示“更新公告暂时无法读取”；
- 读取失败时不凭空生成红点，也不把本地有效已读记录清空；
- 管理员密码错误、版本冲突、格式错误、空公告发布和存储不可写分别显示明确错误；
- 前端错误不得包含本地路径、堆栈或未经清洗的 HTML；
- 管理员操作失败后保留当前编辑内容，避免重新填写；
- Socket 同步失败时依靠公开接口重新校准。

## 测试与验收

新增服务器端测试覆盖：

- 首次初始化正确预置 v1.8.2、v1.8.3、v1.8.4 及精确发布时间；
- 重启后公告和时间保持，不重复预置；
- 版本格式与全状态唯一性；
- 草稿可空白、全空公告不能发布；
- 草稿、已发布和隐藏的公开可见性；
- 第一次发布设置 `publishedAt` 和提醒修订号；
- 编辑不自动提醒，主动重新提醒时修订号增加；
- 发布后修改版本号要求二次确认、强制重新提醒且保持唯一；
- 隐藏和重新发布保持首次发布时间；
- 三段 HTML 清洗和空段默认文案；
- 管理员接口鉴权，公开接口不泄露非公开公告；
- 主文件损坏时 previous 恢复；
- 主副本都损坏或 schema 未知时拒绝覆盖；
- 写入失败时保留上一份内存状态并可在后续写入恢复。

新增前端合约和纯逻辑测试覆盖：

- 登录前和登录后都存在公告入口；
- 抽屉、遮罩、折叠项、三段标题和管理员表单的关键 DOM 合约；

浏览器验收覆盖：
