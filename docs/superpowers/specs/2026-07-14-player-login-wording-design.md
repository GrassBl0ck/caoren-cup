# 玩家登录入口用语优化设计

## 目标

玩家不需要先理解“固定成员”和“临时参赛者”的身份含义，只需根据自己收到的是登录密码还是本场邀请码，直接选择正确入口。

本次只修改玩家可见的名称、说明和按钮文案，不修改登录请求、DOM ID、Socket 事件、身份数据结构或管理员账户管理逻辑。

## 登录页

登录方式切换区上方始终显示紧凑提示条：

- 管理员给了你草人杯成员密码：选择“成员账号登录”。
- 管理员给了你本场邀请码：选择“使用邀请码加入”。

切换按钮改为：

- `成员账号登录`
- `使用邀请码加入`

成员账号面板说明：

- 使用管理员登记的 SteamID64 和草人杯独立密码。
- 不需要邀请码，也不需要填写昵称；大厅昵称由管理员预设。
- 连接 CS2 后，游戏 SteamID 一致时会自动完成本场确认。
- 主按钮为“登录并进入大厅”。

邀请码面板说明：

- 使用管理员发放的本场邀请码，并填写本场昵称和 SteamID64。
- 连接 CS2 后，按网页提示完成本场确认。
- 主按钮为“使用邀请码进入大厅”。

原有输入框、错误区和辅助登录入口保持不变。

## 其他玩家页面

- 赛前指引使用“成员账号登录”和“使用邀请码加入”，并继续以“收到密码 / 收到邀请码”解释选择方式。
- 完整规则 Markdown 使用“成员账号”和“邀请码加入”描述两条流程，并重新生成 PDF。
- 当前网站 v1.8.3 玩家公告同步采用新用语。
- CS2 未进入网页大厅的提示已经使用“SteamID64 + 密码或邀请码”，无需修改插件。

## 管理员与内部兼容

- 管理员后台继续显示“固定成员账户”，因为它准确描述长期身份账户。
- `fixed`、`temporary` 等内部视图值和全部 DOM ID 保持不变。
- HTTP、Socket、身份库、桌面客户端和 CS2 插件均不修改。

## 视觉与响应式

选择提示条放在登录方式切换按钮上方并始终可见，使用现有中性色提示样式，不增加大卡片层级。

- 桌面端两条提示可并排或自然排列。
- 手机端改为纵向两行。
- 深色和浅色均使用现有设计变量。
- 提示条不挤压输入框，不产生正文横向滚动。

## 测试与验收

- 扩展固定成员 UI 合约测试，验证新标签、常驻选择提示和两个明确按钮。
- 扩展规则页面与规则内容测试，验证新用语并防止玩家页面恢复旧分类名称。
- 重新生成并检查完整规则 PDF。
- 运行 `npm run typecheck`、身份测试及相关 UI/规则测试。
- 在 360px 和桌面宽度检查深浅色登录页。

## 发布范围

修改完成并确认后只需部署网页端。GitHub 通过新的补丁版本发布；游戏插件、桥接插件和桌面客户端不需要更新。
