# 游戏内独立单挑流程设计

日期：2026-07-25

## 1. 背景与目标

当前单挑流程由网页端保存配置、分配队伍、推进阶段并向 CS2 桥接插件下发命令。虽然实际的回合阶段、武器发放、队伍锁定和事件采集已经位于 `CaorenCupPlugin`，但管理员仍需要依赖网页完成开赛和结束操作。

本次设计增加一套由游戏内管理员直接控制的独立单挑流程。它应满足：

- 管理员不打开网页也能配置、开始、暂停、恢复、查询和终止单挑。
- 独立单挑不读取、不更新、也不在网页展示比赛状态、比分或结果。
- 现有网页单挑继续保留，二者不会同时控制服务器。
- 复用现有单挑阶段、武器、出生保护和 AWP 同意规则，不重写第二套玩法逻辑。
- 仅修改和部署 `web-command-center/CaorenCupPlugin/`，不修改网页端、娱乐插件本体或桌面客户端。

## 2. 已确认的比赛规则

### 2.1 参赛者与分队

- 管理员先让玩家在游戏内自行进入 T 或 CT。
- 执行 `/duel start` 时，以当时 T/CT 中的全部真人玩家为参赛者。
- T 和 CT 必须各有至少一名在线真人玩家，否则拒绝开赛。
- 开赛时记录每名参赛者的 SteamID 和所属队伍，并立即锁定队伍。
- 开赛时处于观察者席的玩家不参赛。
- 开赛后加入的玩家，以及不在参赛名单内的玩家，只能留在观察者席。

### 2.2 地图

- `/duel start` 只在当前地图开赛，不自动切图。
- 管理员需要先切换地图，等待玩家重新连接并选好 T/CT，再开始比赛。
- 比赛进行中禁止通过单挑管理指令切图。
- 正常结束或强制终止后停留在当前地图，不自动切回其他地图。

### 2.3 阶段与结算

- 默认阶段回合数为：手枪 8、步枪 16、狙击枪 12。
- 每个阶段允许设为 0 回合，但总回合数必须至少为 30。
- 插件根据已经完成的正式回合数自动推进阶段，不要求管理员手动推进。
- 比赛必须打满配置的总回合数，不提前结束。
- 打满后按最终比分宣布 T 胜、CT 胜或平局。
- 正常结算后自动解除队伍锁定并清理本局状态。
- 管理员强制终止时不计算胜负。

### 2.4 掉线与暂停

- 参赛玩家掉线后保留参赛资格和原队伍。
- 同一 Steam 账号重连后自动恢复到原队伍。
- 参赛玩家掉线时自动暂停比赛，避免无人一方连续丢分。
- 玩家重连后不自动恢复比赛。
- 只有 T/CT 双方都至少有一名在线参赛者时，管理员才能恢复比赛。
- 管理员可以主动暂停和恢复比赛。

## 3. 架构设计

### 3.1 实现位置

功能在现有 `CaorenCupPlugin` 中实现。原因是当前单挑的以下能力已经存在于该插件：

- 回合计数与手枪、步枪、狙击枪阶段计算；
- `/guns`、枪械切换和 `/agree_awp`；
- 单挑武器发放与出生保护；
- SteamID 队伍分配与持续锁队；
- CS2 事件监听和服务器命令执行。

不把逻辑迁移到娱乐插件，也不新增第二个单挑插件，以免重复监听事件或同时修改玩家和服务器状态。

### 3.2 控制模式

插件增加明确的控制模式：

- `None`：没有单挑运行。
- `WebManaged`：由现有网页流程配置的单挑。
- `GameManaged`：由游戏内管理员指令配置的独立单挑。

互斥规则：

- `GameManaged` 运行时，拒绝网页下发新的单挑配置，日志记录拒绝原因。
- 检测到 `WebManaged` 状态时，普通 `/duel start` 不直接启动，而是提示管理员使用 `/duel start confirm`。
- `/duel start confirm` 明确清理原有网页单挑状态，并由游戏内流程接管服务器。
- 这一确认机制同时处理“网页单挑确实仍在运行”和“网页结束通知缺失导致旧状态残留”两种情况。
- `GameManaged` 的事件、比分、参赛名单和结果不进入网页事件队列；插件普通心跳和其他桥接功能继续运行。

### 3.3 组件边界

为避免继续扩大现有主类，新增职责清晰的内部组件：

- `DuelGameSession`：保存控制模式、配置、参赛名单、队伍、比分、阶段、暂停状态、暂停原因和需恢复的服务器参数。
- `DuelCommandHandler`：解析 `/duel` 子命令、验证 `@css/root` 权限、校验参数并调用会话操作。
- `CaorenCupPlugin`：继续接收 CS2 玩家、地图和回合事件，把与独立单挑相关的事件转交给会话处理，并复用现有武器与锁队实现。

纯状态判断应尽量放入可单元测试的类型中；CounterStrikeSharp API 调用仍由插件主类或窄接口封装完成。

## 4. 管理员指令

所有管理指令仅允许具有 `@css/root` 权限的管理员使用。普通玩家使用时得到中文拒绝提示。

### 4.1 主指令

```text
/duel help
```

显示简短帮助和推荐操作顺序。

```text
/duel status
```

显示控制模式、运行状态、参赛人数、T/CT 名单、比分、当前阶段、剩余回合、暂停状态和暂停原因。

```text
/duel rounds <手枪> <步枪> <狙击>
```

设置各阶段回合数。每项范围为 0～99，总和必须至少为 30；仅允许在开赛前修改。

```text
/duel time <分钟>
```

设置单回合时间，范围为 0.25～5 分钟，默认 1 分钟；仅允许在开赛前修改。

```text
/duel utility <none|random1|random2|random3|full>
```

设置道具模式；帮助文字同时提供中文含义。仅允许在开赛前修改。

```text
/duel reset
```

把待开赛配置恢复为手枪 8、步枪 16、狙击枪 12、回合时间 1 分钟、无道具。

```text
/duel start
/duel start confirm
```

第一条执行正常开赛检查；检测到网页单挑状态时要求使用第二条明确接管。

```text
/duel pause
/duel resume
```

管理员主动暂停或恢复。恢复前必须满足双方都有在线参赛者。

```text
/duel stop
/duel stop confirm
```

第一条只提示确认，第二条强制终止并清理状态，不计算胜负。

### 4.2 地图指令

```text
/duel maps
/duel map <序号|地图名|创意工坊ID>
```

- 地图指令直接切换服务器地图，不写入网页状态。
- 比赛进行中拒绝切图。
- 保留 `/duel_maps` 和 `/duel_map` 作为兼容别名，行为与新指令一致。

### 4.3 玩家指令

以下现有指令和行为保持不变：

- `/guns`；
- 各枪械切换指令；
- `/agree_awp`；
- 步枪阶段使用 AWP 仍需对方全部在线参赛者同意。

## 5. 生命周期与数据流

### 5.1 开赛

1. 验证管理员权限和控制模式。
2. 读取当前 T/CT 真人玩家；双方无人或任一方无人时拒绝。
3. 建立不可变的本局参赛名单和 SteamID 到队伍的映射。
4. 清空旧比分、阶段、武器选择、AWP 申请和出生保护状态。
5. 保存本次会修改的服务器参数。
6. 启用队伍锁定，并把非参赛者限制在观察者席。
7. 应用总回合、回合时间、无半场、无提前结束等单挑参数。
8. 设置 `GameManaged`，重启比赛并从手枪阶段第 1 回合开始计数。

只有全部前置校验成功后才修改服务器状态，避免启动一半留下残余配置。

### 5.2 回合推进

1. 正式回合结束后更新本地 T/CT 比分和已完成回合数。
2. 若已完成回合数小于总回合数，计算下一回合阶段并继续现有武器发放逻辑。
3. 若达到总回合数，进入正常结算。
4. `GameManaged` 下不向网页发送本局的比赛事件或快照数据。

### 5.3 正常结束

1. 根据最终比分生成中文结果提示。
2. 广播 T 胜、CT 胜或平局以及最终比分。
3. 解除队伍锁定和观察者限制。
4. 恢复开赛前保存的服务器参数。
5. 清理会话、武器、AWP 申请、保护和暂停状态，控制模式回到 `None`。

### 5.4 强制或异常终止

以下情况不计算胜负：

- 管理员执行 `/duel stop confirm`；
- 插件卸载或重载；
- 独立单挑进行中发生意外换图；
- 无法继续维护有效的比赛状态。

终止时尽最大可能恢复服务器参数、解除队伍锁定并清理本局内存状态。插件卸载阶段不得启动新的异步工作。

## 6. 安全与错误处理

- 比赛进行中拒绝修改地图、回合数、回合时间和道具模式。
- 重复 `/duel start` 不重启或覆盖当前独立单挑。
- `/duel stop` 必须二次确认。
- 检测到网页单挑状态时必须显式 `/duel start confirm` 才能接管。
- 指令参数错误、权限不足、双方人数不足、无法恢复比赛等情况均返回具体中文原因。
- 所有控制模式切换、接管、开始、暂停、恢复、结束和异常清理写入插件日志。
- 队伍和参赛身份以 SteamID 为准，不以玩家名称或临时槽位为准。
- 配置和字符串按 UTF-8 处理。

## 7. 测试与验收

### 7.1 自动化与本地验证

- `DuelGameSession` 单元测试：
  - T/CT 任一方无人时拒绝开始；
  - 当前 T/CT 真人被正确登记，观察者被排除；
  - 手枪、步枪、狙击枪阶段边界正确，包括某阶段为 0；
  - 总回合打满后正确判定 T 胜、CT 胜和平局；
  - 掉线触发暂停，重连恢复原队伍但不自动恢复比赛；
  - 双方在线条件不满足时拒绝恢复；
  - 强制终止和异常终止清空状态；
  - `WebManaged` 与 `GameManaged` 互斥，确认接管可清理旧状态。
- 指令测试：权限、缺失参数、非法数字、非法道具模式和二次确认。
- 在 `web-command-center/CaorenCupPlugin/` 执行 `dotnet build`。
- 运行已有桥接插件测试，确认现有网页单挑配置仍能进入 `WebManaged`。

### 7.2 真实服务器验收

至少使用两名真人玩家分别进入 T 和 CT，验证：

1. 管理员能在当前地图直接开赛，观察者不被加入。
2. 参赛者无法换到对方队伍，后来加入者只能观察。
3. 默认和自定义回合配置都能正确自动推进阶段。
4. `/guns`、换枪和 AWP 同意规则正常。
5. 参赛者掉线会暂停；重连恢复原队；管理员可恢复。
6. 打满总回合后自动宣布比分和结果并解除锁队。
7. `/duel stop confirm` 能安全终止且不产生结果。
8. 旧网页状态存在时，普通开始被拦截，确认接管有效。
9. 独立单挑不会出现在网页比赛状态、比分或结果中。

## 8. 部署边界

本功能只改动桥接插件，因此部署时只覆盖 `CaorenCupPlugin`，并仅重启 CS2 插件所在服务或按现有插件更新流程重新加载。不要覆盖或重启：

- 网页端；
- `CaorenCup` 娱乐插件本体；
- 桌面客户端。

部署前仍需本地构建、检查包内容、备份服务器目标目录，并按项目既定的本地打包上传流程操作；不使用服务器端 `git pull`。
