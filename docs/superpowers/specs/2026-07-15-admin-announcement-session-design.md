# 管理员更新公告会话授权设计

## 目标

管理员已经通过现有大厅登录流程进入管理员页面后，管理更新公告不再额外弹出管理员密码输入框。管理员密码、旧登录方式和现有 HTTP 管理接口继续保留。

## 边界与安全模型

- 网页端的更新公告管理列表、保存、发布、隐藏操作改走现有 Socket.IO 连接。
- 服务器只接受已经绑定到当前大厅 `Admin` 玩家身份的 Socket 请求；未登录、普通玩家、断开后重连但尚未恢复管理员身份的连接一律拒绝。
- 不缓存管理员密码，不写入 `localStorage`、`sessionStorage`、日志、Socket 广播或错误信息。
- 不新增长期令牌、设备令牌或自动登录能力；当前 HTTP 环境的 HTTPS 限制不变。
- 现有 `/api/admin/update-announcements/*` HTTP 接口继续要求管理员密码，供兼容、测试及非网页调用使用；网页管理面板不再调用它们。
- 管理员 Socket 断开或身份失效时，页面显示明确提示，要求按已有流程重新进入管理员会话，而不是再次弹出密码框。

## 接口变化

新增仅面向当前 Socket 的更新公告管理事件：

- `UPDATE_ANNOUNCEMENT_ADMIN_LIST`
- `UPDATE_ANNOUNCEMENT_ADMIN_SAVE`
- `UPDATE_ANNOUNCEMENT_ADMIN_SET_STATUS`

每个事件使用 Socket.IO acknowledgement 返回 `{ success, announcements }` 或 `{ success: false, error }`，不向其他玩家广播管理员专用数据。公告发布成功后，继续沿用现有公开公告广播机制通知玩家端。

## 前端行为

- `update-announcement-admin.js` 使用大厅已连接的 Socket 调用上述事件。
- 删除更新公告管理请求中的 `prompt('请输入管理员密码')` 与密码字段拼接。
- 管理员会话可用时，刷新、保存、发布、隐藏均不再要求额外输入。
- 管理员会话不可用时，状态栏显示“管理员会话已失效，请重新登录”，并保持编辑内容不被清空。
- 版本号、标题、内容、发布状态和重复提醒的现有校验与确认弹窗保持不变。

## 验证

- Socket 管理员可以读取、保存和变更更新公告状态，且不需要管理员密码。
- 普通玩家、未登录 Socket、伪造的请求参数不能操作或读取管理员公告列表。
- HTTP 更新公告接口仍拒绝缺少或错误的管理员密码。
- 前端合约测试确认更新公告管理代码不再调用 `prompt` 或向请求体写入管理员密码。
- 回归更新公告、身份登录与网页 UI 测试。

## 非目标

- 不改固定成员密码、邀请码、设备令牌、管理员登录和其他管理模块的鉴权方式。
- 不修改身份库、公开公告数据结构、CS2 插件或桌面客户端。
