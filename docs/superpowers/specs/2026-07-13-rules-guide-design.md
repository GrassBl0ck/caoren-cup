# 草人杯赛前指引与完整规则 PDF 设计

## 目标

在不改变登录、比赛、CS2 插件和桌面客户端逻辑的前提下，增加一个登录前后均可访问的公开赛前指引页面。它帮助新玩家在开赛前理解如何进入大厅、如何连接 CS2、不平衡竞技和卧底模式的基本玩法。完整规则继续以可下载 PDF 提供。

## 已确认的产品决定

- 采用独立公开规则页，而不是把规则嵌入大厅或弹窗。
- 规则页在登录前和登录后都可以访问。
- 快速指引只写玩家需要知道的内容，不展示管理员页面、身份库迁移、后台操作或部署说明。
- 完整规则提供 PDF 下载，继续公开服务器 IP 和 QQ 联系方式。
- 现有 Word 文档作为历史来源保留；以后以 UTF-8 Markdown 规则源文件维护内容，再生成公开 PDF。
- 固定成员和临时参赛者两条登录流程必须按 v1.8.2 现状描述；`!cclogin`、`!cccode`、`!ccbind` 仅说明为特殊情况恢复入口。

## 信息架构

### 公开赛前指引页

页面地址为 `/rules.html`，无需登录或 Socket 连接。现有 `index.html` 的品牌头部位于登录区和大厅区之外，会在登录前后持续显示；该持久头部提供“赛前指引”链接，无需按登录状态重复创建或切换链接。

桌面端采用页面顶部品牌导航、左侧页内目录、右侧阅读内容的布局；手机端将页内目录改为横向滚动导航。页面首屏包含“开赛前 3 分钟”的说明和完整规则 PDF 下载按钮，页面底部重复下载按钮。

快速指引固定为以下五个章节：

1. **进入大厅**：固定成员输入 SteamID64 和密码后进入大厅；临时参赛者输入邀请码、昵称和 SteamID64 后进入大厅。固定成员游戏 SteamID 一致时自动确认；临时参赛者按网页提示完成确认码流程。
2. **对局模式**：以玩家可理解的语言解释不平衡竞技的少人方补偿、技能点和 `.sp 1/3/5/r`；解释卧底模式的士兵、卧底、侦探、九宫格任务、中场问答和终局指认。共同的队长、Roll 点、蛇形选人、地图 BP 和选边流程以简短步骤呈现。
3. **进入 CS2**：给出服务器连接方式、`snd_toolvolume 0.3-0.5` 建议，以及“已进 CS2 但未进网页大厅”提醒的含义。说明固定成员无需手动确认码，临时玩家仍需完成确认。
4. **通用规则**：禁止作弊、必要沟通、避免噪音干扰、紧急暂停和插件效果可能在下一回合生效。
5. **常用指令与帮助**：`.r`、`.tac`、`.tech`、`.sp`、`!ws`；`!cclogin`、`!cccode`、`!ccbind` 放在“特殊情况恢复”说明中。

快速指引不包含积分明细、娱乐修改完整列表、管理员权限、数据导入、部署说明或身份库 schema 内容；这些内容仅保留在完整 PDF。

### 完整规则 PDF

完整规则源文件采用 Markdown，覆盖现有 Word 文档的所有实质性内容：草人杯简介、赛前准备、玩法分类、完整网页流程、通用行为规则、插件与指令、各玩法规则、卧底详细规则和计分、Demo、娱乐玩法汇总、FAQ、最终解释和联系信息。

以下旧表述必须重写：

- “输入昵称加入房间”和“网页显示绑定码后使用 `!ccbind` 完成绑定”改为固定成员/临时参赛者两条入场路径。
- “完成绑定”在正常流程中改为“完成本场确认”；固定成员由可信 SteamID 自动确认，临时参赛者使用现有确认码流程。
- `!ccbind`、`!cclogin`、`!cccode` 标注为故障恢复或特殊情况入口，不能再写成普通玩家的默认前置步骤。
- 平衡竞技和卧底模式流程中的“完成玩家绑定”改为“进入网页大厅并完成本场确认”。
- PDF 保留 `connect 119.45.166.182:27015` 与 QQ `3465434029`，并在登录说明旁提醒固定成员使用独立密码：当前 HTTP 环境下密码传输不具备 HTTPS 加密保护。

PDF 顶部标注“草人杯完整规则”和生成日期；内容使用真实标题层级、目录和表格，便于长文阅读和打印。

## 文件边界

| 路径 | 职责 |
| --- | --- |
| `web-command-center/public/rules.html` | 无登录要求的赛前指引页面语义结构与静态文案。 |
| `web-command-center/public/css/app.css` | 规则页的浅/深色变量适配、目录、卡片、步骤与移动端样式；复用既有主题变量。 |
| `web-command-center/public/index.html` | 在登录前后共用的持久品牌头部增加“赛前指引”入口，不改变现有表单 ID、登录请求或大厅状态。 |
| `docs/rules/caoren-cup-full-rules.md` | UTF-8 的完整规则唯一维护源。 |
| `scripts/build-rules-pdf.*` | 从 Markdown 构建公开 PDF 的可重复脚本；不得把临时目录、私有配置或系统路径写入 PDF。 |
| `web-command-center/public/downloads/caoren-cup-full-rules.pdf` | 规则页提供的公开下载资产。 |
| `web-command-center/scripts/check-rules-guide.cjs` | 静态 UI/内容契约检查。 |

Markdown 是完整规则的唯一内容来源；快速指引页面不从 PDF 解析，而是保留一份刻意简化的静态文案。两者均由同一变更提交更新，避免运营时出现旧登录说明。

## 视觉与可访问性

- 规则页沿用当前指挥台的浅色/深色 CSS 变量、8px 以下圆角、蓝色主操作和中性阅读表面。
- 不使用营销式大幅英雄图或嵌套卡片；步骤、模式对比和提示块只在有扫描价值时使用边框分组。
- 标题遵循 `h1`、`h2`、`h3` 层级，页内目录使用真实锚点；下载链接有明确可访问名称。
- 键盘焦点、深浅色对比度和 360px、768px、1440px、宽屏的文本换行必须可用；窄屏不得出现正文级横向溢出。

## 不在范围内

- 不修改固定成员密码、邀请码、设备令牌、确认码、管理员鉴权或 Session 行为。
- 不修改 CS2 比赛规则、游戏插件本体、桥接插件、服务器配置或桌面客户端壳。
- 不把完整规则的所有细节、积分表或娱乐玩法列表复制到大厅首页。
- 不删除现有 Word 原件。

## 验收标准

1. 未登录访问 `/rules.html` 能阅读完整快速指引并下载 PDF。
2. 登录页与大厅页都存在指向 `/rules.html` 的可访问链接；原有登录 ID 和请求行为不变。
3. 快速指引准确描述固定成员自动确认、临时邀请码确认和旧命令恢复角色。
4. 完整 PDF 不再把 `!ccbind` 或绑定码作为普通入场默认流程；保留公开的服务器 IP 与 QQ 信息。
5. PDF 和快速指引都包含 HTTP 独立密码提醒，且不包含管理员密码、哈希、令牌、生产配置或服务器文件路径。
6. 浅色和深色页面在 360px、768px、1440px 和宽屏下无正文横向溢出、遮挡或按钮文字截断。
7. 契约测试验证规则入口、关键固定/临时玩家文案、下载链接以及旧默认绑定表述不再出现。
8. PDF 生成后必须渲染为页面图片进行逐页视觉检查，确认中文、目录、表格和分页没有截断或重叠。
