# 卧底任务多预设设计

## 摘要

为卧底任务模板增加服务端共享的多预设管理能力。管理员可以新建、应用、重命名和删除任务预设；系统自动提供不可删除的“系统默认”预设。当前对局仍使用自己的 `taskTemplate`，应用预设时沿用现有的权限、时间限制和任务状态重置逻辑。

## 数据与服务端行为

- 新增独立的服务端 JSON 预设存储文件，保存 `id`、`name`、`taskTemplate`、`createdAt`、`updatedAt`、`system` 字段。
- 服务启动时读取预设文件；文件不存在或结构损坏时，自动生成/恢复“系统默认”预设，不阻塞大厅启动。
- “系统默认”使用现有 `getDefaultTaskTemplate()` 生成，固定 ID，不能重命名或删除。
- 当前对局继续把模板保存在 `session.taskTemplate`；应用预设时复制模板到当前对局。
- 应用预设后重置所有卧底的任务进度、操作记录、替换/提示计数和任务确认状态，沿用现有模板应用逻辑。
- 预设管理和应用仅允许管理员在大厅或身份发放前执行；比赛进行中拒绝操作。
- 预设文件使用临时文件写入后替换，降低写入中断导致损坏的风险。

## 接口与页面交互

新增管理员操作：

- `LIST_TASK_PRESETS`：获取预设列表。
- `CREATE_TASK_PRESET`：以当前编辑器模板或当前对局模板新建预设。
- `RENAME_TASK_PRESET`：修改普通预设名称。
- `DELETE_TASK_PRESET`：删除普通预设。
- `APPLY_TASK_PRESET`：将指定预设应用到当前对局。

服务端负责生成预设 ID，并校验名称：去除首尾空格、不能为空、限制长度、禁止重复名称。客户端不能覆盖预设 ID 或系统预设标记。

任务模板编辑器增加预设区域：

- 显示现有预设列表，并提供应用按钮。
- 提供“另存为预设”按钮，默认保存当前编辑器内容，不要求先应用到本局。
- 普通预设提供重命名和删除；“系统默认”只提供应用。
- 应用前复用现有危险确认提示，明确说明会清空卧底任务进度、操作记录和确认状态。
- 保存成功后刷新列表；应用成功后沿用现有状态广播。
- 保留 JSON 导入/导出、浏览器本地备份、撤销/重做功能。

## 异常、兼容与验收

- 预设文件不存在时自动初始化“系统默认”。
- 预设文件 JSON 损坏或结构不合法时记录警告、保留损坏文件副本，并重建可用的系统默认预设。
- 应用不存在的预设、删除系统默认、重复名称、空名称、比赛中操作均由服务端拒绝并返回明确提示。
- 删除当前正在使用的普通预设只删除预设记录，不改变当前对局已经使用的模板。
- 旧版本无预设文件时无需迁移，首次启动自动初始化。

测试覆盖：

- 预设存储的初始化、读写和损坏恢复。
- 新建、重命名、删除、应用及管理员权限。
- 系统默认不可删除。
- 应用后任务状态正确重置。
- 服务重启后预设仍可读取。
- 前端列表、按钮和不可用状态。
- 网页端类型检查、卧底相关现有测试及新增预设专项测试。

验收标准：管理员可以创建至少两个命名预设并在大厅中切换；普通玩家不能管理；比赛开始后不能切换；服务重启后预设不丢失；原有 JSON 和浏览器本地备份功能不受影响。

## 明确假设

- 预设共享范围为当前网页端服务实例，不引入数据库。
- 预设管理只面向管理员，不增加普通玩家可见的预设编辑能力。
- 本次不增加预设版本历史、多人并发编辑冲突解决或自动云端同步。
