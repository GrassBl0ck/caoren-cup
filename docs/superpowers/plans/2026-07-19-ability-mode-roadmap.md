# 草人杯异能模式实施路线图

> **执行要求：** 每个阶段必须使用 `subagent-driven-development`（推荐）或 `executing-plans` 技能执行；开始下一阶段前，先完成当前阶段的测试和人工验收。

**目标：** 在不推翻现有草人杯大厅、MatchZy 比赛流程和卧底模式的前提下，分阶段交付网页 BP、可靠同步、插件运行时、13 个职业与伊斯塔露回溯。

**依据规格：** `docs/superpowers/specs/2026-07-17-ability-mode-design.md`

**拆分原则：** 异能模式跨越网页、桥接插件、娱乐插件和 CS2 引擎高风险能力，不适合用一份超大计划一次实施。每个阶段都必须有独立输出、独立测试和明确的停止点。

---

## 阶段依赖

```text
阶段 1：网页角色 Ban / 选角
    ↓
阶段 2：网页 → 桥接 → 娱乐插件可靠同步
    ↓
阶段 3：娱乐插件通用运行时
    ↓
阶段 4A：基础职业
    ↓
阶段 4B：高交互职业与引擎原型
    ↓
阶段 5：伊斯塔露 15 秒回溯
    ↓
阶段 6：全链路联调、恢复测试与发布准备
```

## 阶段 1：网页角色 Ban / 选角

**独立输出：** 网页流程变为“选边 → 角色暗 Ban → 蛇形选角 → 赛前准备”；支持人数自适应批次、保密视图、超时、断电恢复和管理员配置。此阶段只形成最终职业配置，不向插件发送。

**已确认默认值：** 新建普通比赛大厅默认关闭异能模式，由管理员手动开启；单挑模式固定跳过异能 BP。

**详细计划：** `docs/superpowers/plans/2026-07-19-ability-mode-phase1-web-bp.md`

**验收门槛：** TypeScript 类型检查通过；BP 单元测试通过；A/B 两队视图不泄露对方未公开选择；服务重启后能恢复 BP；异能模式关闭时原流程不变。

## 阶段 2：可靠同步与开赛门禁

**涉及组件：**

- `web-command-center/src/plugin-command-queue.ts`
- `web-command-center/src/plugin-api.ts`
- `web-command-center/CaorenCupPlugin/CaorenCupPlugin.cs`
- `game-plugin/CaorenCupPlugin.cs`
- 新增结构化同步协议、摘要算法、事务暂存和最终 ACK 测试

**独立输出：** 网页能以同步 ID、比赛 ID、修订号和目录版本发送完整配置；娱乐插件原子校验并回报最终结果；赛前页显示同步状态；失败时只能重试或明确关闭本局异能模式。

**关键停止点：** 先用本地自动化测试证明重复同步幂等、错误配置整份拒绝、桥接 ACK 不会被误认为娱乐插件 ACK，再接入真实 CS2 服务器。

## 阶段 3：娱乐插件通用运行时

**建议新增目录：** `game-plugin/AbilityMode/`

**独立输出：** 完成席位状态、充能、`.charge buy`、`.ult`、每回合一次、HUD、统一伤害管线、移动倍率合成、持久化和正式替补继承；先用“测试职业”验证公共机制，不启用正式职业效果。

**测试基础设施：** 新建 `game-plugin.Tests/`，把纯规则与 CounterStrikeSharp API 适配层分开；纯规则必须可在无 CS2 服务器时运行 `dotnet test`。

**关键停止点：** 热重载恢复、回合胜负充能、死亡/复活重复计数、购买退款边界和伤害来源防递归全部通过后，才进入职业开发。

## 阶段 4A：基础职业

**范围：** 医师、狂战士、坦克、资本家、天平、指挥官。

**独立输出：** 优先交付主要依赖公共运行时、引擎不确定性较低的职业；每个职业单独开关，逐个完成纯规则测试和服务器人工验证。

**关键停止点：** 经济修改必须验证购买、回合奖励、最大金钱和换边；免伤必须验证与护甲、真实伤害、正面判定和加和上限的关系。

## 阶段 4B：高交互职业与引擎原型

**范围：** 刺客、玻璃大炮、道具手、超级飞侠、雪傀儡、女巫。

**独立输出：** 完成隐身、方向伤害、闪光期间弹道偏移、诱饵传送、空中免伤、击飞、中毒和真实伤害。

**原型门禁：** 下列能力先做最小服务器原型，确认 CS2/CounterStrikeSharp 当前版本可稳定控制后再接职业状态：玩家级道具购买上限、玩家级弹道偏移、完全隐身、诱饵落点事件、安全传送、枪械伤害归零但保留原始击飞量。

## 阶段 5：伊斯塔露回溯

**独立输出：** 完成每 0.25 秒快照环、15 秒死亡/复活/装备/弹药/金钱/C4 携带状态回溯、安全落点和 0.75 秒全员无敌；明确排除已安装 C4、飞行投掷物和地图机关。

**原型顺序：** 玩家安全传送 → 死亡与复活 → 武器实体所有权重建 → C4 携带状态 → 当前回合计时恢复 → 原子回溯与失败回滚。

**关键停止点：** 任一核心原型无法稳定实现时，停止该阶段并向用户说明具体限制，不用近似行为替换已确认规则。

## 阶段 6：联调与发布准备

**独立输出：** 完整比赛演练、断线重连、正式替补、网页重启、桥接重载、娱乐插件热重载、同步重试、半场换边、加时、各职业组合和故障降级测试。

**最终验证：**

cd D:\OpenSourcework\caoren-cup-open-source\game-plugin
