## 4. 本轮游戏内测试：按顺序进行

普通构建不注册探针；仅临时验证构建启用。root 启动和控制，只发送给启动者自己，不能替换另一位管理员的探针。服务器控制台只能 inspect/status。

个人设置先调到 100%。每组结束输入 `/caudio_probe stop`，不要多组交叉测试。

### A. 整段循环与停止

1. `/caudio_probe start loop12`。
2. 持续听约 65 秒：每 6 秒音高提高；30 秒后应回到第一段，60 秒再次回到第一段。
3. `/caudio_probe pause`，等几秒，再 `/caudio_probe resume`，应接续暂停位置。
4. `/caudio_probe stop`。继续等超过 30 秒，不能再次响起；枪声、脚步正常。

这验证“循环播放和停止该循环音”。运行中“关闭循环后在当前一轮结束时停止”尚未实现，不能用 stop 冒充 LoopOff。

### B. 单探针替换机制

1. `/caudio_probe start 12`，听到第二或第三段。
2. `/caudio_probe replace 16`。
3. 原声音应立即停止，只留下从第一段开始的新声音；不能两个音高同时响。
4. `/caudio_probe stop`。

此项只验证实体替换机制。Music 和 Broadcast 分开管理、同时存在的正式通道实现仍需后续验证，不凭单探针结果宣布通道系统完成。

### C. 动态音量参数实验

1. `/caudio_probe start loop12`。
2. 依次 `/caudio_probe gain 100`、`gain 50`、`gain 25`、`gain 1`、`gain 0`，每步留 2～3 秒比较。
3. `gain 100` 应恢复当前进度的声音，不能从头开始。
4. `/caudio_probe stop`。

gain 只实验当前探针的公开 volume 参数，不保存个人偏好，不修改全局游戏音量。它不是已接入的菜单音量控件。记录“逐级变小／只有 0 静音其余一致／完全无效／恢复从头”等真实结果。

### D. 进度接入的前置实验

1. `/caudio_probe start 12`，等约 13 秒，处于第三段。
2. `/caudio_probe resync`。
3. 记录：仍是第三段、从第一段开始、跳到别段、无声或报错。
4. `/caudio_probe stop`。

resync 只对自己的接收端发送定向停止，再重建声音事件并携带服务器推算的进度。start_time 的语义尚待验证，所以这是独立 seek 实验，绝不是暂停／恢复的实现。它不测试真人新连接，也不代表后来加入已通过。

若失败，保留失败记录，正式服务继续拒绝未验证的同步能力。若通过，再实施两名玩家的迟入／重连测试和接入流程。

### 返回反馈

按 A/B/C/D 四项回复即可：循环是否重复、替换有无叠音、100/50/25/1/0 的变化、resync 接在哪段。开发者同时核对 sound.start/stop/params/gain/resync 日志。

## 6. OGG 素材导入

1. 保留原 OGG，放进素材目录；不要用改扩展名的方法假装转换。
2. 用 scan-caoren-audio.py 扫描：检查容器、单音轨、有效时长、全文件解码，生成新草稿。
3. 确认显示名、稳定事件 ID、分类／通道、默认音量、是否整段循环。新草稿不会自动覆盖正式登记。
4. 需要统一响度时用 normalize-caoren-audio.py 生成新副本。当前 -12 LUFS 只对本次探针得到“刚好”的反馈；其他人声／音乐仍要测量和试听。峰值上限继续 -1.5 dBTP。
5. 单独构建。Loop=true 自动将 OGG 解码为内部 WAV 并加首尾 cue，再编译为声音资源；源 OGG 不写入游戏 VPK。
6. 长音频需要匹配的声音事件 bank。本轮 bank 已提供示例；当前构建脚本的 AdditionalSoundEvents 不会自动为任意新素材生成全部受控事件。
7. 以同一 VPK 更新两端，并完成真人试听后再发布。

登记通道或 Loop=true 不代表正式服务能播放它；当前服务明确拒绝未验证的受控长音频。
