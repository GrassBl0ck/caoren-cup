## 1. 目标与非目标

**目标**:把网页桥接插件(`web-command-center/CaorenCupPlugin/`,部署名 `plugins/CaorenCupPlugin/`)中的单挑逻辑拆出为独立插件 **CaorenDuel**(部署 `plugins/CaorenDuel/`),与娱乐插件(CaorenCup)、桥接插件平级。

**非目标**:不改变单挑玩法行为;不实现游戏内菜单;不改网页端;不处理 Git 提交/部署(另行确认)。

## 2. 已确认决策(2026-09-22 用户拍板,不再重新讨论)

1. 单挑拆分为独立插件。
2. **遥测/心跳隔离协议保留**:其必要性已查清(见第 4 节),拆分后通过跨插件通知维持等价行为。
3. **单挑期间遥测停发**:这已经是现状(`ShouldPublishMatchTelemetry()` 在 GameManaged 单挑和隔离激活期间返回 false),拆分后单挑插件不实现遥测即保持该决策。

### 3.2 隔离协议现状(必要性已查清)

网页指挥台心跳是**命令下发 + 状态纠正通道**:`PluginHeartbeatResponse` 携带 `matchId/phase/commands/scoreCT/scoreT/currentRound`,应用时会切换比赛 ID、清空统计、直接覆盖插件侧比分回合(`CaorenCupPlugin.cs:1732-1746`)。隔离防三类真实故障:

1. **防旧比赛命令打断单挑**:单挑开始时把当前比赛 ID 记入 stale 集合;旧比赛心跳携带的未执行命令(换图/重启/锁队/阶段跳转)会被判 `Stale` 丢弃。
2. **防旧比赛状态回灌**:stale 集合永久累积,单挑结束后旧比赛 ID 的心跳也永远丢弃,直到网页出现新比赛(非 stale 心跳)。
3. **防清理窗口期被新命令搅局**:单挑结束走引擎重启 + CVar 恢复重试,释放需三条件同时满足(清理重启后首回合开始 + 观察到安全心跳 + CVar 恢复就绪),见 `DuelTelemetryIsolationState.ReleaseIfSafe()`。

释放后由 `CommitReleasedDuelHeartbeatStateOnGameThread()` 提交挂起的心跳状态(应用新比赛 ID 并清空统计)。

## 4. 隔离协议跨插件化设计(核心)

**原则**:`DuelTelemetryIsolationState` 状态机**留在桥接插件**——它管理的是"心跳何时应用",是桥接自身职责。单挑插件通过服务器命令通知状态变化,CSSHarp 跨插件通信用 `Server.ExecuteCommand` + `AddCommandListener` 是常规做法(无进程内插件 API)。

### 4.1 通知命令(桥接侧新增监听,仅服务器/控制台可执行)

| 命令 | 触发时机(单挑插件内) | 对应现状调用 |
|---|---|---|
| `css_duelbridge_begin <matchId\|none>` | 单挑开始 | `_duelTelemetryIsolation.Begin(staleMatchId)` |
| `css_duelbridge_cleanup_restart` | 决定清理重启时 | `BeginCleanupRestart()` |
| `css_duelbridge_round_start` | 收到 RoundStart 事件 | `CompleteCleanupRoundStart()`(内部自带"仅清理重启后首个回合生效"守卫,单挑插件每个 RoundStart 都通知即可) |
| `css_duelbridge_cvar_ready <0\|1>` | CVar 恢复状态变化 | `UpdateCvarRestoreReady(bool)` |

桥接收到通知后走现有 `DuelTelemetryIsolationState` 方法,行为与现状等价。监听命令建议加权限前缀校验(仅服务器执行来源),避免玩家聊天伪造。

### 4.2 当前比赛 ID 的获取(单挑开始时需要 stale matchId)

桥接在 `_currentMatchId` 变化处同步维护一个 ConVar `caoren_bridge_matchid`(空表示无比赛)。单挑插件 `StartGameManagedDuel` 时直接读该 ConVar 作为 `staleMatchId` 传入 `begin` 通知。选 ConVar 而非反向命令:实现简单、无时序竞争。

### 4.3 时序(与现状逐条对齐)

```
单挑开始:  css_duelbridge_begin <旧matchId>   → 桥接挂起/丢弃心跳(旧ID判Stale)
单挑运行:  (无交互;单挑插件不发遥测)
单挑结束:  css_duelbridge_cleanup_restart    → 桥进入清理重启等待
重启后首回合: css_duelbridge_round_start      → 条件①满足
CVar恢复:  css_duelbridge_cvar_ready 1       → 条件③满足
网页新比赛心跳到达(桥接自行观察)             → 条件②满足 → 释放 → 提交挂起状态
```

## 5. 共享事件处理器的职责剥离

遥测停发(决策 3)大幅简化剥离:单挑插件的事件处理器**只保留单挑推进逻辑**,不实现 `QueueEvent`;桥接侧把 `round = _duelModeEnabled ? Math.Max(1, _duelFormalRound) : _currentRound` 一律简化为 `_currentRound`(单挑模式不再发遥测,无需正式回合号)。逐个方法:

| 方法 | 单挑插件获得 | 桥接保留 |
|---|---|---|
| `OnRoundStart` | 清理重启回合消费(`TryConsumeRestartRound`→`CompleteDuelCleanupAfterRestart`)、单挑回合标记、回合保护启动、装备下发、回合公告、`CvarRestore` 重试安全点、`css_duelbridge_round_start` 通知 | 回合计数、遥测事件、`CommitReleasedDuelHeartbeatStateOnGameThread`、`DrainDeferredHeartbeatCommandsAsync` |
| `OnRoundEnd` | GameManaged 计分(`RecordRoundEnd`)、`FinishGameManagedDuel`;移除 WebManaged 分支 | 普通比分累计、`round_end` 遥测、快照 |
| `OnPlayerDeath` | —(单挑无需死亡遥测;胜负由回合结算判定) | 全部保留(round 字段简化) |
| `OnPlayerHurt / OnPlayerBlind / OnWeaponFire` | — | 全部保留(round 字段简化) |
| `OnTick / QueueCrouchSamples` | — | 全部保留(round 字段简化);单挑插件不注册 OnTick |
| `OnPlayerTakeDamagePre` | 回合保护(先判单挑激活) | 不保留 |
| `OnJoinTeamCommand` | GameManaged 锁队分支 | 网页分队锁定分支 |
| `OnDuelDropCommand` | 全部 | 删除 |

单挑侧比分:`_scoreT/_scoreCt/_duelFormalRound` 的单挑语义字段随迁(建议收进 `DuelGameSession` 已有 `ScoreT/ScoreCt/CompletedRounds`,避免再散落);桥接保留自己的比赛比分字段。

## 9. 验证方案

**自动化**:随迁的 4+1 个测试文件全部通过;桥接剩余测试全部通过;两端 `dotnet build` 零警告新增。

**本地/测试服手动清单**(核心是隔离时序,不能省):

1. 无单挑时:网页指挥台心跳、快照、命令下发行为与拆分前一致(对照拆分前录一段)。
2. 单挑完整流程:`/duel_map` 换图 → `/duel rounds/time/nades` 配置 → `/duel start` → 打完 → 自动清理重启 → CVar 恢复。
3. **隔离时序**:单挑开始前让网页挂一场旧比赛 → 开单挑 → 确认单挑期间网页命令不执行、比分不被覆盖 → 单挑结束后旧比赛心跳仍被丢弃 → 网页开新比赛后桥接恢复正常(可观察 `caoren_bridge_matchid` ConVar 与桥接日志)。
4. `/duel pause/resume/stop/reset/status` 与掉线暂停(30 秒重连)行为不变。
5. 两插件同装,服务器无加载错误;`css_gaben` 式的既有其他插件不受影响。

## 10. 风险与注意

- **两个插件都不要重复注册同名命令**:桥接删干净 `duel/guns/dp/dr` 系列后再部署新插件,同包同批覆盖,避免新旧并存期命令冲突。
- `css_duelbridge_*` 通知命令必须校验执行来源(仅服务器),防止玩家伪造。
- `CompleteCleanupRoundStart` 的"仅首个回合生效"守卫在状态机内部,单挑插件每个 RoundStart 无脑通知即可,不要在插件侧重复实现守卫。
- 摘出 2646 行后的零散引用时,以"读取单挑状态字段"为迁移判据;不确定归属的先列出再判断,禁止凭猜测删桥接代码。
- 修改现有文件前按 `agent-rules/file-safety.md` 备份;本次不执行提交/推送/部署。
