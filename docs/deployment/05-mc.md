# MC 开服

[返回目录](README.md) · [上一章](04-cs.md) · [下一章](06-integration.md)

Windows 服务端路线未验证。A 的历史记录曾出现 Windows JDK 25 loopback 启动阻塞，遇到相同错误时保留完整日志并核对 JDK 构建与主机网络环境。先使用专门的测试世界，本章建图操作会改变棋盘范围内的方块。[A 平台验证记录](../../mc/cushion-wars/cushion-wars-a/docs/13-试玩修复与本地验收.md)

## 1. 选择玩法和服务端

| 内容 | 初次安装选择 | 状态 |
|---|---|---|
| 坐垫战争 A | 独立 Paper 实例、对应 Java 25/Paper 26.3、插件和两个地图数据包 | 有历史原型运行记录，当前修复版与真人试玩按各自记录核验 |
| 坐垫战争即时制 B | 独立 Paper 实例、Java 25、对应 Paper 26.3 | 本地自动验证，真实服务端及真人待验收 |
| 跨时代实验 | 隔离实验环境，明确允许世界 | 默认关闭，旧版战斗还原待验收 |

草人杯外层同一时间只启用一套玩法或地图。初次体验每次只安装所选内容，A 与 B 分别测试。第三方游玩地图仅在本地自行准备，不随仓库或发行包分发。[MC 发行包说明](../../mc/INSTALL.md)

从 Paper 官网选择与插件声明相符的服务端，记录游戏版本和 build，下载 JAR 后放入新的 MC 目录并命名为 `paper.jar`。若目标版本不可获取，应停在此步骤并向维护者确认兼容版本。[Paper 官方入门](https://docs.papermc.io/paper/getting-started/)

## 2. 启动空服务端

Ubuntu SSH 终端执行。

```bash
cd "$HOME/caoren/mc"
java -version
java -Xms2G -Xmx2G -jar paper.jar --nogui
```

Windows 服务端 PowerShell 执行。

```powershell
Set-Location 'C:\Caoren\mc'
java -version
java -Xms2G -Xmx2G -jar paper.jar --nogui
```

第一次通常生成 `eula.txt` 后退出。阅读文件中指向的 Minecraft EULA，只有同意后才编辑为 `eula=true`，然后再次执行启动命令。出现 `Done` 后，在服务端控制台输入 `stop` 并等进程退出。这里的命令保持前台，关闭窗口会影响开服。

## 3. 配置世界与正版验证

停服后用文本编辑器打开实例根目录的 `server.properties`，核对以下键。示例的 20 人上限可按所需人数和机器能力调整。

```properties
online-mode=true
enforce-secure-profile=true
server-ip=
server-port=25565
level-name=cushion-wars-a
max-players=20
```

`server-ip` 留空时使用默认监听。修改 `level-name` 会选择或生成另一个世界，已有世界和玩家数据先备份。A 与 B 使用不同独立世界，B 的 `level-name` 改为 `cushion-wars-b`。`enable-rcon` 保持关闭，地图管理参考脚本按单独高级场景配置。[Paper 服务端配置](https://docs.papermc.io/paper/reference/server-properties/)

重新启动一次，让目标世界生成，然后 `stop`。正版 Java 客户端版本匹配时，同机先连接 `localhost:25565`。可在服务端控制台执行 `op REPLACE_PLAYER_NAME` 给自己的测试账号管理权限，随后在游戏中验证命令。

## 4. 安装坐垫战争 A

把 MC 发行包解压到单独暂存目录。停服后按以下映射复制，`<实例>` 对应 Ubuntu 的 `~/caoren/mc` 或 Windows 的 `C:\Caoren\mc`。

| 包内内容 | 目标 |
|---|---|
| `cushion-wars/cushion-wars-a/plugins/CushionWarsProbe-0.1.0.jar` | `<实例>/plugins/` |
| `cushion-wars/cushion-wars-a/datapacks/` 中 cw-entry.zip、cw-maps-menu.zip | `<实例>/cushion-wars-a/datapacks/` |

棋盘生成、恢复、缩圈和校验由插件负责；旧 cushionwars-a 地图数据包已归档，不要随新实例安装。旧实例升级前备份世界和模板，再于停服期间移出旧数据包；不要删除世界存档。

首次启动生成插件配置后停服，编辑 `plugins/CushionWarsProbe/config.yml`，将 `board.world` 从默认 `world` 改为本章创建的 `cushion-wars-a`，核对中心坐标和地面高度。A 的地图标识为 `cushion-wars`，独立实例可保持默认，显式设置时使用 `-Dcw.map=cushion-wars`。

重启后在游戏内执行 `/datapack list enabled`、`/cw help`、`/cw status`。两个数据包应启用，`cw` 应显示帮助和状态。只有 `/cwprobe` 而无 `/cw` 时检查是否拿到旧探针产物。

首次建图先确认世界专用且已备份。管理员执行 `/cw size 1`、`/cw build 1`，两名测试玩家分别 `/cw join red`、`/cw join blue`，管理员执行 `/cw start`。检查地图、准备、行动、结算与结束。中止执行 `/cw stop`。1v1 跑通后再调整人数，8v8 至少需要 16 个玩家位置。

不同修复版的规则与未验收项查看对应版本源码记录，首次真人测试逐项记录实际表现。[A 修复与本地验收](../../mc/cushion-wars/cushion-wars-a/docs/13-试玩修复与本地验收.md)

## 5. 安装坐垫战争 B

B 使用新的实例或独立世界，先按第 3 节生成 `cushion-wars-b`。停服后将包内 `cushion-wars/cushion-wars-b/plugins/CushionWarsRealtime-0.1.0.jar` 放入实例 `plugins/`。首次启动生成配置后停服，编辑 `plugins/CushionWarsRealtime/config.yml`，显式设置 `board.world`、`center-x`、`center-z` 和 `ground-y`，世界名应与已加载世界一致。

以后启动时在 `-jar` 前加入 JVM 参数，Ubuntu 在实例目录执行。

```bash
java -Dcw.map=cushion-wars-b -Xms2G -Xmx2G -jar paper.jar --nogui
```

Windows 在实例目录执行同一条 `java` 命令。预期 `/cwb status` 能返回状态。“当前地图未启用”表示启动参数未匹配。查看 `/cwb help`，核对管理员建图、人数与入队步骤，建图前检查对应世界和坐标。其真实 Paper 交互、多人连续对局和恢复过程仍待验收。[B 配置、命令与限制](../../mc/cushion-wars/cushion-wars-b/README.md)

最小 1v1 测试先由管理员执行 `/cwb size 1`，玩家分别 `/cwb join red`、`/cwb join blue`，按提示选择 `/cwb spawn 1`，再由管理员 `/cwb start`。检查准备、同步行动、结算和恢复，中止使用 `/cwb stop`。

## 6. 自行准备游玩地图

第三方游玩地图、数据包源码与专用下载工具不随本包分发。管理员按地图作者说明自行取得地图，核对服务端、客户端版本及资源包要求，再安装到独立世界。已有玩家存档须先备份，不能直接覆盖。

地图切换工具保持通用，地图 ID、标题和菜单入口按实际安装的地图配置。[MC 安装范围](../../mc/INSTALL.md)

## 7. 实验内容与地图管理

跨时代观察探针、CrossEraCombat 和 OCM 参考源码分清用途。需要实验时按其说明明确配置允许世界和 `experimental-enabled`，OCM 当前按独立依赖获取，发行包提供参考源码。普通开服路线保留这些组件的默认关闭状态。[跨时代说明](../../mc/cross-era-pvp/combat/README.md)

包内 `shared/tools/` 是原 Linux 多世界部署的参考工具，涉及 systemd、RCON 和特定目录。Windows 与普通单世界开服先使用本章的前台启动和 `stop`，以后需要切图管理时再逐项适配服务、目录、权限及恢复行为。
