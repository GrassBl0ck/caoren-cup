## 1. 安装 CS2 本体

从 Valve 下载 SteamCMD，对应 Linux 或 Windows。此处使用 Steam app 730，安装根目录为 `caoren/cs2`，该目录下应生成 `game/`。`force_install_dir` 指向安装根，核对后再运行。Valve Wiki 在本次在线核对中返回 403，本节命令依据仓库既有流程整理，首次部署需实测。[SteamCMD 官方 Wiki](https://developer.valvesoftware.com/wiki/SteamCMD) · [CS2 服务端 Wiki](https://developer.valvesoftware.com/wiki/Counter-Strike_2/Dedicated_Servers)

Ubuntu SSH 终端，下载并解压 SteamCMD 到自己的专用目录。

```bash
cd "$HOME/caoren/steamcmd"
curl -fL https://steamcdn-a.akamaihd.net/client/installer/steamcmd_linux.tar.gz -o steamcmd_linux.tar.gz
tar -xzf steamcmd_linux.tar.gz
./steamcmd.sh +force_install_dir "$HOME/caoren/cs2" +login anonymous +app_update 730 validate +quit
test -f "$HOME/caoren/cs2/game/bin/linuxsteamrt64/cs2" && echo 'CS2 executable found'
```

预期 SteamCMD 报 app 730 安装成功，并找到可执行文件。只有退出进程或目录存在还不足以证明下载完整。缺少 32 位库时回到环境准备，下载失败时检查磁盘、DNS 和 Steam 出站访问。

Windows 服务端 PowerShell，下载 Valve 提供的 `steamcmd.zip` 到 `C:\Caoren\downloads` 后执行。[Valve Windows SteamCMD 下载](https://steamcdn-a.akamaihd.net/client/installer/steamcmd.zip)

```powershell
Expand-Archive -LiteralPath 'C:\Caoren\downloads\steamcmd.zip' -DestinationPath 'C:\Caoren\steamcmd'
Set-Location 'C:\Caoren\steamcmd'
.\steamcmd.exe +force_install_dir C:\Caoren\cs2 +login anonymous +app_update 730 validate +quit
Get-Item 'C:\Caoren\cs2\game\bin\win64\cs2.exe'
```

## 2. 原版启动和停止

Ubuntu SSH 终端执行，暂时保持前台以便查看日志。

```bash
cd "$HOME/caoren/cs2/game"
./bin/linuxsteamrt64/cs2 -dedicated -console -usercon -port 27015 +game_type 0 +game_mode 1 +map de_dust2 +sv_lan 1
```

Windows 服务端 PowerShell 执行。

```powershell
Set-Location 'C:\Caoren\cs2\game'
.\bin\win64\cs2.exe -dedicated -console -usercon -port 27015 +game_type 0 +game_mode 1 +map de_dust2 +sv_lan 1
```

预期地图加载、没有持续启动错误。同机 CS2 玩家开启开发者控制台，执行 `connect 127.0.0.1:27015`。远程机器先检查进程和日志，客户端连接在联网章节测试。游戏控制台输入 `quit` 停服后，再安装框架。Linux 若日志提示缺少 `~/.steam/sdk64/steamclient.so`，先查找 SteamCMD 实际下载的 `linux64/steamclient.so`，在确认目标存在且原链接未占用后按 Valve 指引建立链接。

公网运行需要把启动命令中的 `+sv_lan 1` 改为 `+sv_lan 0`，按 Valve 账户页面创建服务端登录 Token，并在私有启动配置中添加 `+sv_setsteamaccount REPLACE_GSLT`。该 Token 与网站桥接 Token 分别保存。[Steam 服务端账户管理](https://steamcommunity.com/dev/managegameservers)

## 3. 安装 MetaMod 和 CounterStrikeSharp

1. 在各自官方发布页面选当前 CS2、操作系统和架构适用的版本，记录具体版本。首次安装 CounterStrikeSharp 选择 **with-runtime** 产物。
2. 停服后分别解压到暂存目录，把各包内的 `addons/` 内容合并到 `cs2/game/csgo/addons/`。
3. 先备份 `cs2/game/csgo/gameinfo.gi`，在其 `SearchPaths` 中的 `Game_LowViolence csgo_lv` 下添加一行 `Game csgo/addons/metamod`，已有该行时核对位置。
4. Windows 按官方要求安装 VC++ x64 Redistributable。Linux 的运行库根据启动日志补齐。
5. 重启后在服务端控制台执行 `meta list`、`css_plugins list`。前者应识别 CounterStrikeSharp，后者应能列出 CSS 插件。

核对日期 2026-11-09，当前 CSS 入门文档要求支持 KHook 的 MetaMod build 1467 或更新版本。仓库历史记录中的 build 1410、CSS 1.0.374 是旧环境证据，新装应同时核对当前框架要求与草人杯兼容性。[CSS 官方入门](https://docs.cssharp.dev/docs/guides/getting-started.html) · [MetaMod 下载](https://www.metamodsource.net/downloads.php?branch=dev)

## 4. 安装草人杯合集

把服务器发行包解压到 `downloads/server-stage` 这样的新暂存目录，查看 `package-manifest.json`。确认文件摘要及版本后，将包内 `addons/counterstrikesharp/` 合并到游戏对应位置。新安装的结构应如下。

```text
cs2/game/csgo/addons/counterstrikesharp/
├─ plugins/CaorenCup/
│  ├─ CaorenCupCore/CaorenCupCore.dll
│  ├─ CaorenCupFunCommands/CaorenCupFunCommands.dll
│  ├─ CaorenCupInGameMenu/
│  ├─ CaorenCupGamemodes/
│  ├─ CaorenCupMiniGames/
│  ├─ CaorenCupQOLs/
│  └─ CaorenCupWebBridge/CaorenCupPlugin/CaorenCupPlugin.dll
├─ shared/CaorenCupContracts/CaorenCupContracts.dll
└─ gamedata/
```

复制时保留包内子目录。共享契约只放在 `shared/` 指定位置。旧版迁移时若分类根目录还残留旧主 DLL，先按[维护章节](08-maintenance.md)核对迁移范围，该文件会影响分类下插件发现。

重启后执行 `css_plugins list`，逐个核对清单中的主插件及错误日志。确认 Core 加载后查看分类根的 `module-configs/`，优先修改这里的分模块配置，示例预设按需使用。具体项目与 DLL 对照以[服务器清单](../../scripts/server-package-manifest.json)为准。

## 5. 管理权限和桥接配置

游戏内管理权限在 `addons/counterstrikesharp/configs/admins.json`。使用管理员自己的 SteamID64，新增项前保留原有内容。单人测试可按下面结构配置，替换示例身份。

```json
{
  "server-owner": {
    "identity": "REPLACE_STEAMID64",
    "flags": ["@css/root"]
  }
}
```

保存有效 JSON 后重启并用自己的身份核验权限。网站管理员密码和 CSS 管理权限各自配置。[CSS 管理员配置](https://docs.cssharp.dev/docs/admin-framework/defining-admins.html)

桥接目录中复制 `caoren_config.example.json` 为 `caoren_config.json`，配置方法见[联通章节](06-integration.md)。真实配置随升级保留。

## 6. 资源与可选依赖

| 需要的功能 | 安装与验证 |
|---|---|
| 菜单、音频资源分发 | 按 MAM 官方说明安装匹配系统的产物，配置草人杯工坊 ID `3810054981`，检查服务器下载与新玩家自动下载 |
| MatchZy 相关练习或功能 | 单独安装匹配版本并核对其配置，草人杯 Core 会抑制 MatchZy 自动进入比赛，避免两个控制器争用 |
| 换肤 | 配置专用数据库、对应 gamedata 和数据文件，执行组件健康检查 |
| RUSH 决胜局补丁 | 按配方提取合法原版脚本、校验 SHA 后生成 VPK，单独验证挂载和决胜局 |

MAM 与 MatchZy 的参数以相应版本上游文档为准，框架安装后先做最小功能验证再启用资源。工坊资源下载依赖服务器能访问 Steam，日志应显示下载完成。新加入的客户端要验证实际菜单与声音。[MAM 上游](https://github.com/Source2ZE/MultiAddonManager) · [RUSH 资源工具](../../cs/game-plugin/PluginSplit/CaorenCupGamemode_RUSH/AssetTools/README.md) · [换肤说明](../../cs/game-plugin/PluginSplit/CaorenCupQOLs/CaorenWeaponPaints/README.md)

MAM 发行包解压到 `game/csgo/`，重启后用 `meta list` 确认加载。在 `game/csgo/cfg/multiaddonmanager/multiaddonmanager.cfg` 设置草人杯资源，已有其他工坊 ID 时保留并用逗号追加。新安装只使用草人杯资源时可填以下一行。

```text
mm_extra_addons "3810054981"
```

MAM 下载与挂载可能触发地图重载，先在测试场次观察完成日志。PlaySound 的 `audio-events.json` 和 `audio-assets.json` 需要来自同一份匹配资源构建，核对包内完整清单和工坊版本后再试听。[MAM 配置与下载行为](https://github.com/Source2ZE/MultiAddonManager#convars)

## 7. 平台限制和完成标准

头部缩放原生适配当前只支持代码中已核对的 Linux 服务端二进制，游戏更新造成哈希变化时也会拒绝启用。Windows 保持该功能关闭，其他功能分别实测。Linux 专用 `.so` 与 Windows `.dll` 依赖按平台选用。[头部缩放实现](../../cs/game-plugin/Features/HeadSizeFeature.cs)

完成标准为原版能连接、框架识别、所选插件正常加载、管理命令有效、资源可达。网站功能还要通过桥接与完整比赛流程验证。
