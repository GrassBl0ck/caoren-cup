# InGameMenu 悬浮反馈修正

## 已确认的选择

返回使用“‹ 返回”，浅色按钮底，固定在左上；无上级仍隐藏。X 固定右上退出。研究参考：[GOV.UK Back link](https://design-system.service.gov.uk/components/back-link/) 使用图形加文字；[Apple UINavigationController](https://developer.apple.com/documentation/uikit/uinavigationcontroller) 在顶部导航提供返回控件。具体视觉选择由用户确认。

用户实测：0% 已完全遮住地图，只有 1% 不符合预期。这限制了排查范围，但尚未证明小数 RGBA 是根因。

## 本轮实际修改

- 提示从 Button 内移到固定尺寸的兄弟 Panel 中，隔离原生 `.PopupButton Label` 的字体、边距和布局规则；原按钮文字在悬停时保留。
- 数值控件 56×48、导航 120×64、指令行 54 高、投票行 80 高、操作按钮 200×56、分页 120×48、返回 120×56、X 64×56。尺寸单位为 Panorama 逻辑像素。悬停只改变底色，不改变尺寸。
- 固定占位容器与业务按钮同步隐藏，避免空行/无效翻页占位。
- 主体与导航作为根容器的独立层，导航明确从 (0,0) 开始；不再依靠 ignore-parent-flow 把底部子项移动到顶部。
- 提示使用固定黑框，通常位于按钮上方；顶部控件的提示位于下方。取消相关祖先的裁剪，仍需实机确认不同分辨率下不会遮挡。
- 透明度背景改用等价的八位颜色值：0% `#141414ff`、1% `#141414fc`、100% `#14141400`。设置仍逐 1% 保存。此为隔离小数 RGBA 路径的对照修正，效果待验收，不能声称根因已解决。
- 点击音效注册为 PlaySound 现有服务中的 `menu.click`，使用游戏原生 `UIPanorama.submenu_select`；点击本人的活动菜单才请求播放，个人音量 0% 不发送。取消菜单 CSS 的自动声音，避免绕过个人音量。没有修改游戏全局音量，0% 的实际静音与是否重复播放仍待实测。
- 保留全部已有响度试听版本，未改正式默认响度；暂停组件未处理。

## 部署后的复测

1. 完全退出 CS2，更新匹配的服务器插件与两端 VPK 后重开。用户本机测试由用户执行。
2. `/ca` 或 `/cm`：确认左上“‹ 返回”、右上 X，品牌仍在左下；根页面没有返回，其他页返回层级不变。
3. 将鼠标移到 −5、−1、+1、+5，原文字不能变动；按钮不可变宽/变高，黑框文字单行完整、位置在外侧。检查指令行、广播、分页和投票同样如此。
4. 比较 0%、1%、2%、10%、50%、100% 背景，尤其记录 0→1 是否突然变亮。1% 应与 0% 接近，而不是大幅露出地图；重开菜单设置保存。
5. 个人音量 100% 点击按钮，应听到一次原生轻提示；50% 应降低，0% 应完全静音。恢复 100% 并复测，游戏武器等声音保持原样。
6. 普通玩家投票资格、已投票只读、左侧完整选项与最终结果保持原行为。

若八位色值下 0→1 仍突然变亮，则本次透明度对照验证失败；继续检查引擎半透明背景的合成路径，不能通过更改设置标签或伪造数值掩盖问题。
