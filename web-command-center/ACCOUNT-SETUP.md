# 草人杯统一账户与 CS / MC 入口

入口 `/`：邮箱验证码注册、自设账号密码登录、邮箱找回密码、板块选择和账号补绑邮箱。`/cs` 保留 CS 大厅，`/mc` 提供玩法与入服指引。两个板块复用现有 HttpOnly 账户会话，切换页面不自动加入或退出比赛。

## 邮件配置

使用专用网易邮箱，按网易邮箱设置开启 SMTP 并生成客户端授权码。服务端通过环境变量读取 `.env.example` 中的 `SMTP_*` 配置，不会自动加载 `.env` 文件。

- 163 示例：`smtp.163.com`、465、TLS；126 按实际邮箱使用 `smtp.126.com`。
- `SMTP_USER` 为完整邮箱地址，`SMTP_PASSWORD` 为客户端授权码；`SMTP_FROM` 留空时使用发信邮箱。
- 465 使用 `SMTP_SECURE=true`。使用其他服务的 STARTTLS 端口时设为 `false`，程序仍强制 TLS 升级，不能降级为明文认证。
- 缺少发信配置时，网页明确显示服务尚未启用，新注册不可用；已有账号仍可登录。不会把模拟发送当作真实发信成功。
- 授权码只在受控配置中填写，不进入 Git、任务、日志或聊天。SMTP 传输使用 Nodemailer，禁用内容/协议日志和外部附件读取。

验证码有效期 10 分钟，60 秒后可重发，最多猜测 5 次；邮箱、IP、用途和绑定账号受到校验。当前单进程服务使用内存保存短时挑战，重启后未完成验证码失效；扩展多进程部署前需先设计共享挑战与限流存储，不能直接开多个实例。

## 老账号与 CS 身份

- 老账号及原有身份 ID 保留，密码仍按原规则区分大小写；登录后可补绑邮箱，不重新建号或自动合并战绩。
- 新账号无需进入游戏即可注册、登录及浏览两个板块。
- 参加 CS 比赛前，在 CS2 输入 `/cclogin`，登录网站后在“账户与游戏身份”中绑定一次性码。网页表单不能自行声明 SteamID。
- 已属于其他账号的 Steam 身份拒绝转移，提示登录原账号；不自动合并身份。
- 仅未绑邮箱的老账号保留游戏码恢复。新玩家不能通过恢复接口或 `/ccreg` 绕过邮箱注册。`/ccreg` 改为网页注册指引，不再收集游戏聊天密码。
- Steam 快捷登录没有接入服务入口；历史源码保留，不因本次整理而删除。

## 存储升级与回滚

账户存储由 schema 3 升为 4，增加可独立于 Steam 的已验证邮箱账户。加载旧版 1/2/3 时使用既有原子持久化机制保存，保留 `.previous` 快照，维持已存在账号、身份和关联记录；版本 1/2 沿用此前密码迁移策略。

上线前需额外备份完整身份、会话及比赛数据，不能只依赖会持续轮换的 `.previous` 文件。旧程序不识别 schema 4：回滚必须同时恢复对应的旧版数据快照，并保留升级后新增数据，不能直接用旧程序读取新数据。

邮箱重置密码会撤销相关网页会话和设备令牌；补绑邮箱保留当前会话，撤销其他网页会话。敏感变更不把邮箱验证当作自动合并两个账号的依据。

## 验证与上线边界

`npm run check` 包含邮箱注册/恢复与 CS 身份服务端测试。测试使用注入的假邮件传输，只验证程序行为；真实网易发信及收件箱投递仍待专用邮箱配置后核验。

2026-10-31 经用户授权，只读确认当前 MC 服务器的 `online-mode=true`、`enforce-secure-profile=true`；没有写入配置、重启或读取玩家数据。此核对不代表新网站已部署，上线时仍需复核实际环境。

本地修改不自动覆盖服务器、修改 DNS/邮箱设置、推送 GitHub 或发布版本。后端仍需通过现有反向代理提供 HTTPS。
