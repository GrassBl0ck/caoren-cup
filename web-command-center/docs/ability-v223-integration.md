# 异能 BP 与测试比赛运行时（v2.2.3）

旧异能分支的 BP、阵容锁定、配置确认、运行时管理与统计恢复已接入当前 CS 页面。网站入口仍在 `/cs`，根页面继续提供共用账户与 CS/MC 板块选择。

`matchController = caoren` 继续兼容现有 Core 模式生命周期，不代表启用桥接插件内的 MR12/MR3 比赛运行时。新增独立的 `matchRuntimeEnabled`，默认关闭；只有管理员在大厅显式启用，且模式为竞技或异能时，才允许发送测试运行时控制命令。Random、Duel、RUSH 等模式继续走原有 Core 路线。

桥接插件还必须在本地配置启用测试运行时，并检测与 Core、MatchZy 的控制权互斥。网站开关不是卸载、停用或改配 MatchZy 的授权。

网站只信任已通过心跳顺序校验的协议能力声明：`matchRuntimeProtocolVersion = 1`、`abilitySyncProtocolVersion = 1`。旧桥接缺少声明时，不发送对应的新命令；异能配置保持等待状态。网页重启后，持久化的能力声明不继续生效，须重新等待桥接声明。

BP 可以独立于测试比赛运行时使用。完整职业配置未收到当前比赛、版本与摘要匹配的最终确认时，不允许正式开赛。关闭异能后迟到的 ACK 不会重新启用它。

启用测试运行时后，网页不再将 Core 心跳或原始 round_start/round_end 事件解释为另一套正式比赛；比分与阶段来自带稳定比赛标识、运行时 epoch 和事件序号的桥接快照。旧 MatchZy 路径只在明确选择 MatchZy 时保留。

自动检查覆盖 TypeScript、原有网站回归、异能 BP/同步、MR12/MR3 状态投影、恢复与显式开关门禁。尚未执行此次整合后的真人完整比赛、浏览器操作与实际服务器接管验收；发布不等于部署，也不等于已完成卸载 MatchZy 的验证步骤。

权威回合统计使用事件自己的 `roundKey` 和 `roundNumber`，不使用该次心跳最新快照的回合号。开始/结束事件携带当时的玩家阵营、存活快照、Unix 毫秒时间，结束事件另带胜方引擎阵营。个人回合数、KAST、残局、多杀、生存时间和保枪统计与比分控制分开执行。

原始战斗遥测携带比赛、revision、epoch、回合键、发生时间、递增 `eventSequence` 及重试不变的 `eventId`。网页保留每轮统计日志；权威结束先于战斗请求到达时，按发生时间重算该轮及后续统计，并更新恢复检查点。同毫秒事件按生产端序号排序，重复 ID、旧 epoch、无正式回合键和实际结束后的战斗不累计。日志随网页会话持久化，恢复目标回合及之后的旧时间线会失效。

测试运行时的比赛是否结束完全取决于权威阶段；13:12 加时不会触发旧竞技 13 分结束逻辑。默认 Core 竞技和 Random 的既有胜负规则保持各自路径。
